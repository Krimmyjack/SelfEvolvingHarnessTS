## 2. 三项核心交付

### A. 原选择的影子审计：不重问模型

覆盖 DEV-SEQ-3 g2 已完成的两臂、u9/u10/u11、全部 120 条历史决策，不只挑 identity
被覆盖或后续受损的案例。逐条对照：

1. 当时 Fast 在当前 Support 之前真正选中的、可执行的程序；
2. 当时 Support 选策后实际交付的程序。

用完整 typed 参数、作用几何、编译/执行记录解析选择，不能只用 candidate 名字或算子
标签匹配。缺乏重建材料记 UNKNOWN，不重问 Fast 补一个“原选择”。确定性合法性失败
按既定且实际执行的 raw 回退记 0；模型/传输故障、未测损失不记 0。

两项动作分别取得 origin 和 origin+48 的配对读数；缓存精确复用，缺项可在预算内补评。
标明这是**固定实际历史的一次决策影子**：不让当前 Support 改写本次选择会怎样。
它不重建采用 Fast-only 后整段历史，不能叫端到端反事实课程，也不把事后评分写回任何
活动历史、Skill 或提示。0 新增 LLM 不等于 0 新增 fits。

必须同时报身份保持/覆盖/改选/合法性回退/未知的数量和各自效用贡献；不要把“选择与
交付一致率”称为 LLM 的因果贡献比例。

### B. 冻结 Fast-only：真实运行，不经在线选策兜底

- 固定使用 **DEV-SEQ-3 g2 A 在 u8 后、u9 前可用的父知识快照**，不带之后新增的 B 卡
  或 DEV-SEQ-4 修订；从既有 store 恢复，不重新形成知识。两次运行用完全相同的快照。
- 本段不注入原始 Episode bank，`experience_episodes=()`；只读冻结的合法 Skill、
  当前序列截至 origin 的 Context 与不读 Outcome 的工具。不得把影子读数、菜单 oracle
  或 u9 之后的历史摘要送入 Fast。自然到达下一 origin 的原始观测可以作为当前 Context，
  但不能附带上一单元的效果分数。
- 复用真实 `TTHAMethod.prepare`/Fast 执行路径，**承接返回的实际选择与执行结果**；
  不调用旧 `run_online_round` 再寻找 Support winner。保留确定性合法性检查，不把
  历史 Support 拒绝规则暗中放回本段。
- 选择 identity 就交付 identity。选中合法程序就按原管线交付该程序；非法程序按
  既定回退，无法确定执行的故障记 UNKNOWN。不能因外部事后分数不好再换程序。
- 每条决策新会话；同一组按 u9→u10→u11 推进，不写经验、不调用 Slow、不铸卡、不
  晋升/撤销。组间同 Request 语义与 Domain 绑定，不能仅为命名新臂让旧 Skill 失配。
- 固定两次运行 g1/g2；种子 2026090901 / 2026090902，组顺序 g1→g2。
  共 **2 × 3 × 20 = 120 次 Fast 决策**。种子实际控制的层级必须说明；未支持后端 seed
  时不能宣称 LLM 采样已固定。两组是同数据重复，不是跨域复现。
- 两组全部程序和输出先落盘冻结，再由不向 Agent 回传结果的 evaluator 评分。
  不因 g1 正/负决定是否跑 g2；若过程故障导致不完整，保留完成部分，不挑好组。

**计分时点，必须在发车前按本条命名：**

- 主读数是 `deployment_gain_at_origin`：Fast 在 origin 看 prefix、决定当前预测程序；
  外部 evaluator 比较该次预测与 raw 的损失。它数值上使用原 evaluator 的 origin 面，
  但本包不是给 Fast 的 Support——分数从未参与本次选择。这是在开发数据上模拟正式
  零反馈部署，不改损失定义，也不改写旧 SEQ 包以 delayed 为主终点的协议。
- `fixed_program_gain_at_plus48` 加报：保持 origin 时选定的 P，在 +48 的 Context 上
  按既有管线再评。这衡量程序持续性，**不是 Fast 在 +48 重新观察决策的结果**，也
  不是同一次 forecast 的另一个名称。不得挑两面中较好的一面作本包主结果。

### C. 真 0-LLM 基线：提前校准、冻结后同场计分

以下参照都与 B 使用同一完整人群、Consumer 和计分时点；确定性列不增加 LLM 臂：

- `Static/raw`：既定原始管线，无准备干预。
- `D-fixed` / `D-safe`：公共 DSL 菜单 + 确定性 held-in 校准 + 固定部署。菜单从当前冻结
  P1/HEC-1 的合法默认**单步**程序机械生成，另含 identity；不得从 LLM 历史候选库
  补出“人工固定菜单”。完整参数来自现有 schema 的默认/既定确定性解析，缺必要参数
  的条目明确记 unavailable，不根据测试结果补参或增算子。先按公开算子名固定排序。

校准只看 u7/u8：每个候选在两个单元完整 20 条上取得 origin 面读数，真实不可执行
者按既定回退，未测保留 UNKNOWN。`D-fixed` 在读数完整的候选（含 identity）中选
两单元等权全人群收益最大者，平局按菜单顺序；它是效用基线，不预先保证安全。
`D-safe` 另在两个校准单元分别通过**既有四线**的候选中按同样规则选；没有合格候选
就冻结 identity，明确记 NO_QUALIFIED_FIXED_PROGRAM。这是本包基线校准规则，不
修改生产接受策略或授予新 Skill 权限。两列均进入主表，不能只打败退化为 raw 的
D-safe，就宣称打败了强确定性基线；也不能忽略 D-fixed 的风险来宣称其全面更好。

u9/u10/u11 不再探测或择优；只允许不读 Outcome 的合法性回退。确定性策略相同条件
无需重复拟合来制造第二组样本，可在两组比较中复用同一份实际读数。

基线的源菜单、校准读数均不依赖 LLM，是 0-LLM 系统。复用 LLM 历史候选池后做
确定性选择的另一个结果只能叫“零新增 LLM 回放”。F 的 K0 历史形成成本单列；
第一包 F vs D 是部署能力定位，不冒充已经严格拆净全部历史预算的 LLM 增量消融。

## 3. 辅助诊断：同包完成，不再作为一串准入门

### 3.1 菜单内的事后改进空间

分别计算公共单步菜单与“公共菜单 + 历史已记录且可合法重建的 typed 程序”的结果。
后者只供 evaluator 诊断，不能进入 B/C 的输入。无当前结果驱动的新组合搜索。

在同一单元、同一服务人群、同一 origin 面上，报：

- 实际 F、冻结 D-fixed/D-safe、事后 best-fixed；各自来源分别标明。
- 菜单 oracle：每条序列可在合法菜单和 identity 中事后选最优，计算全人群效用。
- 对上述 oracle 的既有风险/覆盖四线读数；若它未过线，不把其效用叫可部署上限。
  若预算内能用已有工具计算受相同约束的 assignment 最优，单列；本包不要求建设新求解器。

新组合、主动观察或菜单外程序不在该上界内。未测候选不能当 raw，也不能悄悄删去
难测人群；不完整菜单只能给“已测集合最好值/未完成”，不能给完整菜单的上限判词。
诊断最多使用 500 个新增 fits，优先保留核心真实运行所需资源，不因求完整上界拖延收口。

### 3.2 可辨别尺度，而非伪精确功率

复用严格同提示/同知识的历史配对，连同本包两次重复，列出差异分布、尾部贡献、
UID/窗口/拟合共享关系。不把 6/51 超过 MATERIAL 叫假阳性率；不把两组当可靠方差。
提供暴露比例 p 下的稀释敏感性 `全人群增量 = p × 暴露子群增量`，写明无外溢等假设。
按 UID/窗口依赖作敏感性范围；独立簇不足则说明不能给可信样本数，不无限补样。
单特征识别失败只限制该规则，不作为禁止主动观察/组合推理实验的环境门。

## 4. 比较器、指标与未知项

唯一评分口径：同一计划 roster、同一单元集、同一面；先对单元的完整服务人群求均值，
再对 u9/u10/u11 三单元等权。分别报 g1、g2，不用合并正号代替一致性。

主表至少有：origin 全人群效用、相对 raw/D-fixed/D-safe 的差、处理数/覆盖、受损数/比例、
最坏单序列伤害、逐单元既有门通过、完整/未知决策数，以及 LLM/fits/墙钟。
所有风险分母仍用既有定义，既有 min_treated=5 不改；identity 是合法回退参照，不因此
冒充满足“有效处理覆盖”的方案。+48 同指标单列为辅助表。

UNKNOWN 不能被 `deployed or ()` 变成 identity；若计划人群中存在未知，受影响的完整
人口均值/比较标 UNKNOWN，同时列完整配对的诊断值与缺失位置，不改变主分母。
预测复用和重复引用不算新增独立样本，重复组也不重复计算数据人数。

保存实际行为链：呈现了什么、观察/工具、typed 候选、原选择、实际交付、合法性回退、
外部评分。字段复用既有字典，不新建 Episode/Skill schema 或日志平台。

## 5. 实现、运行与恢复

- 一个逻辑 Runner package，薄封装复用现有 Fast、编译器和 evaluator。建议入口
  `evaluation/main_protocol_p4/run_dev_deploy1.py`；必要辅助与烟测留同目录。
  默认不改核心文件；若必须改变核心合同、快照依赖或评分语义，暂停该变更说明理由。
- 模型固定 `gpt-5.6-sol`，使用环境里已授权端点；核验实际返回模型。不得回退 Flash，
  不并行开 Flash 探针，不临时换 Pro 后并表。密钥不写进任务书、工件或命令回显。
- 包级上限：**2000 次物理 LLM、2000 新增 fits、6 小时执行墙钟**，含预检、失败、
  重试；Slow=0。两次 F 各最多 900 次 LLM，余量供共同预检/必要烟测，不跨组调额度。
  已有 per-sequence 防死循环上限保留 24，不引回旧 5-call 帽。复用成本与历史形成成本
  分开列，无法精确归属的故障开销记未知，不冲销。
- 默认并发 2，单元串行、一单元一进程；Fable 在首个正式调用前可仅依据内存/端点
  健康选定 1/2/4 路并写入配置，不按效用调并发。每序列状态独立，拟合/共享缓存写入
  串行；按固定 roster 汇总。只验证确定性绑定/重放/计费等值，不要求 LLM 输出逐位相同。
- 每次付费动作后承接已有原子记账；每个决策完成即落盘。中断按 checkpoint 恢复，
  不删除完成的 checkpoint，不重问已成功返回的决定来换答案；在飞未知费用单列。
- 无反馈阶段只恢复冻结知识和已完成输出，不携带评价所得历史。旧 SEQ-4 的
  `--positions 13` 缺 u12 历史问题不能复制到有历史的辅助重放里；恢复需按时序重建。
- 暂态错误按现有有界重试；账户/权限错误停受影响线，不能记弃权。内存不足只停止
  自己的任务并保留进度，不杀用户浏览器/其他 Agent。只设一个轻量监视器。

最小烟测只检查改变的关键路径：逐 UID 绑定；identity 不被候选池改写且 Fast 阶段
Consumer feedback 调用为 0；冻结输出后才评分；未知不进零值/不缩人口；恢复不重问
已完成决定且不引入评分历史。复用已过的缓存/确定性并发检查，不再扩测试矩阵。
