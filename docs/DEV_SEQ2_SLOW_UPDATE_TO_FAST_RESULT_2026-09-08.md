## 方法与实现（本包相对 DEV-SEQ-1 的改动）

### 可编辑面：从一个扩到四类对象，仍只改软指导

每次仍只改一处，沿用既有编译器、分支与前置条件。本包在父快照上实例化出 **6 个可写面**：

| 对象 | 实例 | 机械推导的 cause |
| --- | --- | --- |
| 情境化指导（ADD） | `skill_library.entries/{skill_id}` | `SKILL_LIBRARY_GAP` |
| 观察/候选/选择 procedure 正文（PATCH） | `bootstrap_skills.entries/{inspect_and_localize, build_contrastive_candidates, select_or_identity_and_verify}.body` | `OBSERVATION_PROCEDURE_GAP` |
| 提议指导（PATCH） | `candidate_policy.proposal_guidance` | `PROPOSAL_CONTROL_GAP` |
| 选择指导（PATCH） | `candidate_policy.selection_guidance` | `SELECTION_MISS` |

K0 里唯一的 capability 卡是**冻结 Program 卡**，属执行体而非指导，故"已有指导条目的
`.body` / `.observable_applicability`"两面在 K0 **无实例、不供给**，原因写在工件里。
**confirmed_cause 由模型选中的面机械推导**，不预先裁定故障类。

仍然 fail-closed 拒绝：白名单外任何面、任何位置的 `Frozen program steps:`、
`supplies_candidates`、serving Scope、`instruction.core`、retrieval top_k、候选槽数、
risk_guards、verification。烟测里 8 个越权提案**全部被拒**。

**一个值得记录的观察**：六个面全部呈上后，两组 Slow **都选了 ADD 新指导卡**，没有去改
`proposal_guidance` / `selection_guidance` / bootstrap 正文——尽管 g2 那张卡的内容本质上是
一条**选择层**建议（"只有面向异常的候选时保留 identity"）。也就是说，它把一条选择指导写成了
一张带检索条件的情境卡，于是被条件挡住；如果同样内容写进 `candidate_policy.selection_guidance`，
就**没有检索条件、对每个决策都可见**。本包不追这条线，只如实记下。

### 采用判据：从谓词覆盖换成真实两臂

DEV-SEQ-1 的 L1/L2/L3 说的是关于**谓词**的陈述，不是关于**指导是否有用**的陈述。本包保留
它们作诊断（廉价、可算、**不设门**），把门换成：同一 withheld 单元、同一人群、同一预算跑
两臂真实 Fast，B 相对 A 的配对 delayed 增益达到既有 MATERIAL，且 B 通过既有权威门。
**不改常数、不改风险分母。** 本包两组都没走到这一步。

### 本包事后新增的开发级停止规则（必须留痕）

原任务书要求"只要有合法候选且仪器健康，都把两臂在 u10/u11 跑完"。这条**没有区分两种情况**：

- **Fast 读到了指导但效果不好** → 仍应按计划跑完，不能见负数就停；
- **所有剩余样本都读不到指导** → 继续只是在重复父知识下的运行，无法检验这条指导。

本包两组都属于第二种，因此新增停止规则并**明确标注为事后增加**：候选编译后先做零成本暴露
检查，命中为 0 则记 `CANDIDATE_COMPILED_BUT_NEVER_EXPOSED`、两臂不跑、`treatment` 记
`COMPILED_BUT_NEVER_EXPOSED__UTILITY_UNTESTED`。**它不是覆盖门**：不要求条件解释多数失败，
只问"要花钱测的东西有没有被呈现"。

**这两组因此不得作为完整两臂比较呈现；后续报告也不得只挑那些指导确实加载了的组来展示。**
两次这样的运行也**不足以**建立可靠的"噪声底"，本包不为此补跑。

### 特征语义说明（输入完善，本包已实现）

查清了每个可见特征的实际计算范围：**全部**在 `values[:origin]`——序列到决策原点为止的整段
历史，而这个窗口随课程单调变长。据此把 21 个特征按漂移性质分类写进给 Slow 的卡：

- **比率**（`missing_fraction`）→ 大致尺度无关，阈值能活过窗口增长；
- **长度 ÷ 窗口**（`longest_missing_run_fraction`、`level_region_fraction`）→ 随窗口**衰减**；
- **位置 ÷ 窗口**（`estimated_region_*_fraction`、`*_region_end_fraction`）→ 固定绝对位置**衰减趋零**；
- **窗口内最大值**（`local_robust_z_peak`）→ 随窗口**单调不减**，只会越来越容易满足；
- **未归一化幅度**（`estimated_level_offset`）→ 不随窗口漂移。

并明确写入一句：**这套词汇里没有任何一个特征测量的是"程序实际要修改的那个局部区域"**——
如果指的是那个，就写在正文里。这是对症的**输入**补全，**不是**对条件的软化。
