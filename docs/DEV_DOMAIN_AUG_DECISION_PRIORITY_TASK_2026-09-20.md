## 1. 目标与这次真正改变的内容

目标：让域 Skill 学会根据当前观察和已取得反馈，优先验证有价值的处理假说，减少“构造了却没有评价”的机会损失，并在新实体任务上改善交付。

本包复用上一包的真实经历，不重新生成 Source。方法改动集中在一个面：Slow 学习下一项观察/构造/评估的决策依据，而非照抄旧卡的配方偏好。共有的上下文去重、材料诊断语义澄清与并行修复由所有臂获得，不计为 Skill 独享贡献。

本包检验三个问题：
1. 新卡是否改变了值得实测的假说和评估顺序，而不只是少调用、重复默认？
2. 在相同共同契约下，新卡是否优于旧卡和无卡，并与随机/固定策略可比？
3. 收益来自较好的候选供给、较好的交付选择，还是仅成本节省？

不要求先显著胜 NoMix 才允许研究；NoMix 继续作为公共候选和强对照。保留完整构造，不改成仅关组件。不新增算子、Consumer 调参、训练采样权重、Router、TSFM 或外部方法复现。本轮也不同时重设计 C_A/B/E，以免把反馈仪器变化归于 Skill；候选优先级改善并不保证修好时间排序。

输入须包括两个方向：观察后优先评估确有收益的经历，以及相似研究/保守偏好导致更差交付的经历。由全量合法事实形成，不由执行者挑只支持预想路线的几个案例。

> 在有限的四次新方案评估内，学习哪些观察值得取得、哪些处理假说值得优先实测、什么反馈会改变下一项实验，以及何时继续或提交。优化实际下游交付；成本是附加维度，不能通过永远不实验冒充交付进步。请提出相对旧卡可检验的决策差异。不要因原语没被试过就禁止它，不从外观直接推断效用，不把旧卡正文当证据。允许完整组合和条件化；是否用它们由当前证据决定，不强制复杂。

每张提案同时给出：

禁止将实体号、S/V/Q 案例号、时间切点到程序的查表放入卡正文。证据 metadata 可以有引用。检查同时覆盖完整 D01_Q03 等和历史 S06/S08 这类缩写；不要只沿用旧 a85 检查。软优先级不改工具权限，不接受“未测试所以禁分组/禁三步”的全局权限禁令。

每提案最多一次契约纠正；不按后期成绩重采样。字节完全相同或明确 KEEP 的卡可别名复用，不为凑三张加调用。文本不同不能当行为不同，静态渲染也不能预测自然语言卡的真实决策；实际差异在 Select 观察。不设置额外的零成本“保证必触发”门。

## 7. 必须落实的并行执行

### 7.1 并发范围与资源

用户要求能并行的计算/API 就并行。一个主协调器负责整个包；不同案例并行、同案例各臂串行。推荐上限如下，写入配置：

| 工作 | 并发上限/要求 |
|---|---|
| 活跃案例 | 4；新 Select 四案一起推进，MetaTest 八案排队，空位立即补下一案 |
| 实际在途 LLM HTTP | 全包 4；Slow 六个独立提案也用这个池；Fast 等拟合时其他案例继续发请求 |
| 数值重任务 | 全包目标 3 个进程，每个训练固定 8 线程；材料构造、拟合、评分共用资源限流，不是每个案例各 3 个 |
| 单条 Fast 轨迹 | 请求→工具→反馈的依赖顺序保留，不并发互相依赖的 LLM 调用 |
| 同一案例材料注册/各臂 | 顺序推进，避免 TA 编号和注册表竞争；不同案例目录独立 |
| C_B、E 预测、E 评分 | 各阶段内部跨案例并行，三个阶段之间保持屏障 |
| 报告汇总 | 只读完成工件，按冻结 domain/case/arm/seed 顺序汇总，不按返回快慢排序 |

训练环境沿用父包实际环境。主机或 WSL 可用内存不等价，先确认数值子进程到底运行在哪侧。接线时若三并行超出实际内存余量，降为两并行并记录，不改训练线程、seed、batch 或科学预算；资源空闲时恢复已验证上限。不因临时资源拥塞杀其他人的任务。

不得把所有案例串行后只称“三 seed 并行”；也不得无节制启动 4×3 个训练 worker。无需新队列平台，一个工作池、现有薄 study 的线程安全改动与独立数值子进程即可。

### 7.2 并行前的最小必修

以下风险已由代码只读核对，不可直接把原串行 runner 套线程池：

1. 共享 Ledger、MeteredClient 的编号分配/HTTP 计数/在途额度预留/落盘必须在短临界区串行；HTTP 等待在锁外。记录未完成预留，结束时按该响应实际 usage 结算。每个请求明确 stage/case/arm/call/attempt，不使用全局计数差额给分支收费。
2. entity_split 的 FastClient 当前按全局 token 前后差记费用，evaluate/restore 也用全局 fit_attempts 差判断缓存；改成本次 request/fit receipt 的归属和 cache_hit/fit_started 字段。last_text 等响应状态不得在线程间共用。
3. 包目录在任何 Ledger 构造、stage/resume 前取得 OS 排它锁，持有到全部 worker 退出。第二个 driver/resume 立即拒绝；监视器只读。单纯 PID 文件或检查一个 started 标记不够。
4. 请求/响应编号由协调器唯一分配，工件拒绝覆盖。冻结内容、成功轨迹、未知在途请求不能因恢复自动重写。账本原子替换不等于多写者安全，所有共享写入仍须排它。
5. 同案例顺序运行，保留 ensure_material 的唯一注册者；单个物理 cell 只能有一个在途拟合。构造、训练和标签保持进程隔离，不能在线程里交换全局 numpy/torch RNG。

## 9. 读数与解释

主差定义 G_j(A over B)=100×[mean_seed E(B)−mean_seed E(A)]/mean_seed E(None)，正为 A 好；逐 seed 配对差也使用同一个该案例 None 均值分母。先域内四案例等权，再两域等权。单位 pp of None，不能写成相对旧卡或 NoMix 的百分比提升。

首页回答：
1. F_new−F_old、F_new−F0，逐域/逐案例/总体，连同 Random、Fixed_dev、NoMix 和 None。
2. H_deploy 实际选择及收益，是否仅来自采用固定程序；与学习臂结果分开。
3. 两域新卡全文/可读摘录、每条主要改动的来源，真实触发了哪些不同的观察、构造、评估、提交。
4. 研究优先级：构造/评估/未评估方案数量；材料检查次数；合法但未验证的候选是否被误写为已证有害；新卡是否只是更早停。
5. 本轮离线学习成本与部署成本；物理拟合、缓存命中、独立部署的公共+新增拟合工作量分别列，不能只用新增拟合的节省宣称整体训练成本减半。

每个已评估池保留逐 seed/origin 分数，统一 E 屏障后计算事后机会与选择损失。例如以 NoMix 为 r：
- available=100×[E(r)−min_{m∈自身已评估池}E(m)]/E(None)；
- selection_loss=100×[E(commit)−min E(m)]/E(None)；
- net=available−selection_loss。

这是已评估池上的描述性算术，随池大小和噪声变化，不证明可达到完美选择器；未拟合材料没有 E，不得补入 oracle。不合并不同臂私有池冒充某臂的可用池。

分开报告三种可能贡献：更好的候选进入评估；同候选被更好地交付；同交付而成本下降。commit 是否等于本臂 C_A argmin 如实统计。不能把共同请求去重的 token 减少归于新卡，也不能把一个零差称成统计等效。

保留配对 seed 差/SE、案例胜平负、两个切点的分层读数；seed 不冒充独立任务。同一时间的实体组仍可能相关，小样本不设显著性准入，也不以“不显著”宣布无任何空间。无需额外大统计平台。

本包完整跑完即可收口：结果好时提出下一项验证；混合时定位到具体决策；同交付时明确成本和未触发。三者都不自动追加提示词修订、诊断循环或新实验。
