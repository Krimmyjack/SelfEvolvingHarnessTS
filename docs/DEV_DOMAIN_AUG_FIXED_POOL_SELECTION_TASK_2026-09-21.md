## 1. 本包要交付什么

交付两域各一张由真实经历学习、经过开发选优的**提交决策 Skill**，以及同候选池下有卡、无卡、简单规则的实际交付比较。直接运行一个小型学习实验，不再单独派一包诊断，也不重跑整个构造/训练流水线。

主问题：

> 候选已经构造并评估后，Slow 能否从同域历史的 T、程序、C_A 与后期效果中学到判断方法，让提交 Agent 比无卡及 C_A argmin 更好地选择？

本包固定候选池，是为了隔离“候选供给”与“交付选择”。它是完整 Harness 的一个组件实验，**不永久收缩完整构造权限，不把项目改成固定菜单分类器**。组合、条件化、NoMix 及编辑材料都按原记录保留；本包不生成新材料。

辅助分析中需要保留的事实边界：

- 当前 C_A 已有两个起点 × 三个训练 seed 的评分，不是单窗标量。缓存还有实体维度；两个邻近起点仍不足以代表丰富的时间条件。本包只整理已有信息，不声称新增了时间覆盖。
- 相似卡片、旧实验的低相关性、一次特征筛选未显著，都不能证明当前学习对象不存在，也不能排除提示词、模型或输入组织的影响。跨模型旧结果不是本 setting 的受控模型消融。
- 事后最优用于度量候选机会，不是可部署上界的保证；有限样本 E 自身也有不确定性。
- 不把本包改为缺口修复、TSFM、Consumer 调参、画像路由或成本论文。成本照报，质量改进仍是主问题。

## 3. 同池与同信息：这一包的核心契约

### 3.1 候选池

每案 P_j = 四公共参照 + 该案原 F0 **实际成功评估过**的新增材料。四公共为 None、FixedMixup、P_AmpResample、P_NoMixRecipe。

- 不加入仅 build 未 evaluate 的方案，不并入其他臂的私有池；不按 C_B/E 好坏筛候选。
- 按既有 material_key、实际 assignment、profile 与 seed 去重。沿用语义身份，不生成 SHA。
- common 缓存仅用于补齐相同物理材料的已有程序/诊断，不扩候选资格。
- 不把 F0 原提交、构造先后、计划名里的判断词或事后赢家带入判断输入。保留程序真实含义，不保留“这个方案曾被选中”等提示。
- 每案以规范化程序语义的固定排序分配 C00…；FixedMixup 使用其已定义的特殊语义键。排序不依赖分数。所有臂接收完全相同的顺序；字节一致只比较共同任务部分，卡字段另外记录。
- 候选缺三 seed、绑定冲突或缓存缺失时，先定位工件；不能补训练、改用别臂替代、按已知 E 排除。无法修复则记技术未完成并暂停受影响案例，其他独立工作继续。

原始 id → 展示 id 的映射留在 evaluator 侧；每份交付记录能还原精确物理材料。

### 3.2 提交 Agent 的共同输入

从缓存**白名单提取**，禁止把含 scores.c_b 的整个 cell 或 e_scores 传进请求。每案提供：

1. 原 T-only overview 的字段定义、全体实体特征与批摘要；实体只保留案内索引。保留任务、Consumer、程序和评分语义。
2. 每份候选的完整处理程序、已解析的实体赋值、条件规则及已缓存材料诊断。材料诊断只证明改了什么，不能预判效用。None 的缺省诊断记“不适用”；缓存缺字段记 unavailable，不能现造数值。
3. C_A 的三 seed × 两起点实体宏平均矩阵、各 seed 总分、各起点均值；提供跨 seed/起点汇总后的逐实体分数，支持检查收益集中在哪些实体。
4. 对 None 与 P_NoMixRecipe 的配对差：三 seed 差值、均值、seed SE、两个起点的均值差与符号。原分数保留，Agent 可比较任意两候选。两起点分歧只作描述，不把六个单元当六个独立样本。
5. 固定任务说明：目标是随后 E 的预测效用，C_A 是支持证据；允许选任意池内候选；不强制 C_A argmin、3/3 门、NoMix 默认或偏离默认。

计算与最终计分使用缓存全精度；模型表格可统一显示 8 位有效数字，并保留全精度 clean_packet。两 LLM 臂使用同一显示版本，不因选卡状态改变精度。

去掉全局案例/实体编号、文件路径、原臂名、原 commit/rationale、旧卡和后期标签。domain 身份可以保留，按已知域注卡。既有工件中的缓存路径、事件备注也不能夹带结果。

这是**统一整理的合法反馈视图**；部分缓存细节此前未必出现在每条 Fast 请求里。不能把相对历史 Fast 的全部改变归于 Skill，主要归因只看本包共同视图下的有卡/无卡比较。

### 3.3 实际决策

本包调用的是 Fast 的提交决策子任务，正常每案/臂一次 LLM 请求；不是重演原 16 轮工具研究。保留现役客户端与 Skill 注入语义，不调用会初始化训练或原始数据的 CaseAdapter 构造器，不运行旧 stage worker。

共同系统提示要求：

> 阅读本案合法观察、候选程序、材料诊断和 C_A，提交一个已评估候选，以改善随后时间块的整批预测。C_A 与历史指导均可能出错；说明哪条当前证据使你采用或拒绝一个偏好。材料更平、更强或未在历史中尝试，本身不是有害证据。可以保持公共方案，也可以选择组合或条件方案，无需为了表现变化而偏离。你看不到本案 C_B/E。

结构化输出至少含：

```json
{
  "selected_candidate_id": "C03",
  "evidence_refs": ["candidates.C03.ca.by_seed_origin", "overview.summary.lag24_corr"],
  "reason": "仅引用实际输入的选择理由",
  "uncertainty": "仍无法区分的风险或比较"
}
```

schema 检查只确认合法 id、真实字段引用和可解析结构，不由执行者审核“是否选对”后要求改选。不把相同选择、保守选择或与 C_A 相同判为格式失败。

## 5. B 阶段：每域三个独立 Slow 提案

六次主要调用，每次一张 <=6000 字符的 Workflow/Principles 卡；同域三次使用同一份事实表，互不看到另两次输出，不继承旧卡。

Slow 的输入是 §4 全部同域 Learn 证据及新提交接口。重复定义只给一次，T 字段可用列式数组压缩；所有候选、实际结果、反例与不确定性保留，不只截取“成功案例”。目标控制在约 60K 输入 token/请求；先对真实序列化载荷做无调用容量/预留检查。若仍超长，以去重和列式表示解决，不丢反例，也不重复上传完整长轨迹。实际后端容量是硬约束。

学习目标明确写为：

> 从多个同域案例中提出可执行的比较与提交方法，使未见实体案例的后期表现改善。后期 C_B/E 是学习监督，不能当作可忽略旁注；当前 C_A 是部署可用证据，不保证等于最终目标。学习当前观察怎样改变候选比较、什么证据支持偏离某个偏好、何时保留不确定性。不得预设永远保留或永远拒绝 NoMix，也不得凭未尝试认定条件化/三步方案有害。

每条规则在独立 evidence 表标 support/counter/unresolved，**保留规则也须引用实际 Source 证据**。正文不能按 Source 编号、案例位置、物理实体 id 或评分结果查表。不准由执行者写入“某域应选某原语”的答案。

允许卡形成固定偏好，报告其性质，不强制生成不存在的条件分支；三卡若同文或同决策照实记录，不循环采样直到有差异。可明确输出 NO_SUPPORTED_RULE，此项在后续为无卡别名；技术超时/格式失败不能冒充此科学输出。

每次至多一次仅格式/契约纠正；纠正不看 Select/Replay 分数，不因规则看起来弱就要求第二稿。Workflow 与可选 Principles 一起生成，本包不追加迭代修订。

## 6. C 阶段：Select 实测、选卡与固定对照冻结

四个 Select 案，每案评估 S0（无卡）和三张同域卡，共最多 16 次主要调用。全部读取同案同池同输入；只有 experiment_guidance 不同。

待四案的所有决策落盘后，evaluator 从既有缓存读取 E 计分；C_B 可附列，不改变本包已定选卡目标。两个块的角色在起跑前确定，不择优换评分块。

每域按两案等权的

`J(selector) = mean_case[mean_seed E(selected) / mean_seed E(None)]`

选 W*。J 越小越好；差 <=1e-12 视为数值平局，然后按 Select 已记录 token 较少、候选编号较小破同。成本破同只表示更省调用，不称效用更优。

同时在**四公共参照**中按同一 J 选 Fixed_dev[d]，平局按 None、FixedMixup、P_AmpResample、P_NoMixRecipe 固定顺序。它是一个不依赖当前案 C_A 的域内固定对照，不声称覆盖所有可能固定程序。不能用 Replay 的 E 选默认。

W* 即便不胜 S0 或 Fixed_dev，仍进入 Replay，以免“未采用”掩盖组件测试。另冻结只作系统读数的 H_select：在 Fixed_dev、R_CA、S0、S_W* 中按 Select J 选一种；平局按上述顺序。Replay 引用对应臂的既有选择，无额外调用，不覆盖 S_W* 的主要比较。

冻结每域 W*、Fixed_dev、H_select、共同提示词/packet schema 后进入 Replay。Select 标签不交回 Slow，卡不再修改。

## 8. 并行、恢复与最小验收

用户要求能并行的独立 API 并行。复用 decision_priority 已有机制：

- 一个协调器取得包目录 OS 锁后启动；HTTP 全包最多 4 个在途。六个独立 Slow 提案排入同一池；Select、Replay 内各案/臂的独立请求可同时发出，空位及时补充。
- 每请求独立目录和 request/response receipt，共享账本短临界区写入；HTTP 等待不持锁。不可在线程里切换模块全局提示词、共享 last_text 或按全局 token 差给分支计费。
- 本包没有拟合池。缓存提取可 2–4 路只读；阶段 A→B→C→冻结→D 的依赖顺序保留。不要把同一案两臂并行误当作对一个材料注册表并发写入，本包不注册/修改材料。
- 响应写一次；恢复复用已有成功 receipt，不重发已完成逻辑请求。第二 driver/resume 拒绝，监视器只读，只保留一个。
- 超时/500 若是否计费不明：暂停新增付费派发，收齐在途响应，记录未知。沿用需用户接受未知费用后才能恢复的规则，**Opus、子 Agent 或自动循环不得自己扮演用户批准**。不因有重试额度而先重发再说明。
- 输入预留失败、网络失败、有效 NO_SUPPORTED_RULE、合法但保守的决定分别记账。普通不影响科学内容的修补在授权内连续完成；不要每改一行再次询问。
- 本包派工后连续执行到报告，正常阶段之间不等 Planner 再批准；新增数据/拟合、读错信息边界、模型身份变化等实质变更才需停受影响部分。

最小 smoke 只验证新增风险：池资格与去重；含 C_B/E 的原 cell 不被透传；S/Q 学习白名单；同输入/异卡；合法 id 与缓存计分；并行 receipt/重复启动/恢复；未完成决策不连结果。用 fake client，**不能调用旧生产 stage 或回落真实 client**。

接线用一个已有 Source 的缓存数字复算：R_CA 与原完整池 shadow argmin 相符、选定材料 E 与原缓存一致；0 拟合、0 Consumer 预测推理、0 实验 API。不为文档/易逆低影响改动加整套历史测试。

## 9. 固定规模、费用与实现边界

| 阶段 | 主要 LLM 请求 | 最多格式纠正 |
|---|---:|---:|
| A：整理/接线 | 0 | 0 |
| B：2 域 × 3 Slow | 6 | 6 |
| C：4 Select ×（S0 + 3 卡） | 16 | 16 |
| D：8 Replay ×（S0 + W*） | 16 | 16 |
| 合计 | **38** | **38** |

每逻辑调用最多一次格式纠正：逻辑请求至多 76。另留最多四次获准/确定未计费的传输重试，每逻辑请求最多一次，HTTP 至多 80；没有自动接受未知 usage 的授权。每请求输出上限 8K token。别名可减少实数，不把省下的调用用于追加卡或案例。

**新 Consumer 拟合 0；优化器更新 0；Consumer 预测推理 0；新标签 0；新增 SHA/Hash 0；git commit 0。** 不安装依赖、下载模型、读取原始 CSV/NPZ 或修改参考仓库。必要统计运算使用现有 Python 环境，不导入训练模型。
