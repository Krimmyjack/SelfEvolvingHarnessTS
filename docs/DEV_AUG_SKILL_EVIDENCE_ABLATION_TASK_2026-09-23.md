## 4. 两个新增卡家族与原有对照

所有家族均按已知域加载。不同家族的主要差异是 Slow 得到的 Source 证据。

| 家族 | Slow 可见信息 | 每域候选数 | 是否新运行 |
|---|---|---:|---|
| F_naive | 相同任务、Consumer、原语／预设语义、字段定义，以及本域 8 例的 T 观察摘要；没有试验记录或下游结果 | 2 | 是 |
| F_table | F_naive 的信息，加上本域所有已评估方案的定义、材料诊断、三 seed 效果、来源与最终提交标记；不提供研究行动序列和理由文本 | 2 | 是 |
| F_full | 父包完整 Source 普查：方案效果与真实无卡 Agent 轨迹 | 父包已有 2 | 复用父包已冻结域卡和结果 |
| F0 / F_shared | 父包无卡／共享卡 | 已冻结 | 复用 |
| None / NoMix / Fixed_source / Fixed_global_source | 父包冻结固定参照 | 已冻结 | 复用 |

F_naive 是“无试验经验形成、经过相同 Select 选优的指导卡”，不是完全没有验证信息的系统。它是本项目的 naive 对照，不冒称 Eval-Skill 原文基线的完全复现。

F_table 不得只放胜者或十二方案均值：
- 保留父包普查中的同一组已评估方案，包括无卡 Agent 实际提交且不在十二方案内的方案；
- 保留逐 seed 分数、NoAug 参照、负面与冲突案例；
- 保留已有、与方案绑定的数值材料诊断；缺失诊断写 unavailable，不补造；
- 保留 scripted / agent_submission 来源和 committed 标记，以便与 F_full 具有相同方案与结果覆盖；
- 去掉 action 时间顺序、Fast 观察／构造／拒绝／提交的理由文本及轨迹叙述。
因此 F_full 与 F_table 的差别是额外研究过程信息，不是是否看到了更多已评估方案。

F_naive 不得收到以下任何内容：方案效果、名次、赢家标签、成功／失败总结、提交与拒绝记录、旧卡规则、父包报告结论。它可以使用模型自己的通用知识，不能被故意写成弱对照。

## 5. 形成与选优公平性

两个新增家族各形成 3 域 × 2 张卡，共 12 次主要 Slow 生成。
- 复用父包生成契约、输出 schema、卡片权限、长度限制与通用说明；只改证据字段及说明。
- 每域的两个候选槽沿用父包对应的案例排列；从保存的请求读取，不根据已知赢家重新挑顺序。
- 不将 F_full 的卡正文作为模板给新家族；不手写“某域应选择某程序”。
- Naive 的规则可以标通用知识或待验证假说；不要求引用不存在的实验，也不让其伪造效果证据。Table 的证据引用仅指向获准的表记录。
- 统一保留父包已有的“材料改动不能直接证明效用”等通用契约；不得只给某臂新增提示。
- 每个候选最多一次格式／契约纠错；内容保守、重复或不够新颖不构成重抽理由。
- 相同候选可以登记为别名，不额外补抽；不能为了三域不同而强迫产生不同卡。
- 保存形成输入的字段清单、实际请求与候选原文；只需普通 JSON/文本，不新增哈希。

将两家族全部候选和形成协议冻结后，进入 Select：
- 每个 Select 案例运行本域 F_naive 两候选与 F_table 两候选，共 24 × 4 = 96 条 Fast 轨迹。
- 每阶段全部提交冻结后，外部 evaluator 才训练／打开新方案的 E；已有分数也不得通过缓存命中反馈给 Fast。
- 每个家族分别在每域选一卡：
  J_d(W) = mean_c[mean_seed E(c,W) / mean_seed E(c,None)]。
- 完全数值相同才按较少部署 token、固定候选顺序破同；区间跨零不作相同。
- Select 只选卡，不回流 Slow 修改。
- 沿用父包对合法 KEEP、无卡别名、INCOMPLETE 的处理；不得让 Runner 代交 NoMix。技术失败不伪装成有效 KEEP。
- 冻结 6 张部署卡后进入 Test。

“每域两个候选 + 同样的 Select 案例”是必要公平性，不能为了省事将新臂改成单次生成直接测试。旧完整臂不重新抽卡、不根据新臂表现重新选旧卡。

## 8. 主要读数与解释

主指标沿用：
G_c(A,B) = 100 × [mean_seed E(c,B) − mean_seed E(c,A)] / mean_seed E(c,None)。
先域内案例等权，再三域等权；这是 pp of None，不是相对 B 的百分比降幅。

主表列：
- F_full − F_naive（主要）；
- F_full − F_table（次要机制）；
- F_table − F_naive（辅助）；
- 新两臂对 F0、NoMix、Fixed_source；
- 旧 F_full − F0 仅作父包锚点，不重复称作本包新发现。

沿用父包按时期×实体组的配对聚类重采样（同一抽样索引用于所有臂，B=4000），报告 95% 区间、逐域/逐时期/逐案例、胜/同交付/负、最大伤害、留一时期及三个 seed 读数。不把三 seed 当作独立时间环境，不把区间跨零写成等效。

行为表至少包含：提交程序、实体赋值是否统一、构造和检查次数、强增强是否被检查后放弃、实际引用的规则、部署 token。至少给一个产生不同交付的案例；没有差异就明确写没有，不编造“规则触发导致收益”。

解释：
- Full 优于 Naive：支持完整经验流程相对通用指导的增量；单凭这一项不能把增量全归于轨迹。
- Table 优于 Naive、Full 与 Table 未分辨：支持方案—效果证据有价值；轨迹的额外价值仍不确定，可作为以后简化依据。
- Full 优于 Table：提供研究过程信息有额外价值的证据；结合实际交付解释，不能直接称独特算法已被证明。
- Naive 也达到类似表现：父包的“有卡改善交付”仍保留；历史经验形成的额外贡献需收窄。
- 固定参照同样有效：照报，不取消参照，也不要求为证明 Agent 必須提交新程序。
上述均为本次生成、选优与已曝光案例上的消融判断，不宣称普遍结论或模型能力上限。

## 9. 并行、资源与恢复

保持一个协调器、一个运行锁、一个预算账本。
- Slow 的独立候选可并行；Select/Test 跨案例与跨家族可并行，最多 4 个 API 请求同时在途。
- 材料构建与拟合共用数值池，默认 2 路；每次启动检查父包内存余量条件。内存紧张减少并发，不改变数值配置；不强开第三路。
- 同一轨迹中的观察→构造→检查→提交依赖顺序不变。
- 阶段依赖：全部候选冻结→Select 96 条交付冻结→评分选卡→六卡冻结→Test 80 条交付冻结→统一评分。
- 若在执行环境内委派研发子 Agent，限根 Agent 一层、具体边界、不同时写主入口或账本；实验 API 并行不等于无限制委派。

预算是硬边界，不要求花满：
| 资源 | 上限及推导 |
|---|---|
| Source 新轨迹 | 0 |
| Slow 主要生成 | 12；每次最多 1 次格式/契约纠错 |
| Fast 新轨迹 | 176 = 96 Select + 80 Test |
| 逻辑请求 | 1080 = 176×6 + 12×2 |
| 额外传输请求 | 16，独立计数；每个逻辑请求至多重发一次 |
| HTTP 总请求 | 1096 |
| 新物理拟合尝试 | 543 = 528 最坏情况下提交拟合 + 3 接线 + 12 技术重试 |
| 总 token | 40M，已知用量和未知用量保守预留均计入；30M 预警 |
| 墙钟 | 首次付费调用起 6 小时预警、8 小时停止新派发并收口 |
| SHA/Hash、git commit | 0 |

父包平均轨迹成本不同，新卡成本不能提前视为已知。前 8 条 Select 完成后自动更新总成本预测，仍在预算内就继续，不增加用户决策点。
预算耗尽则保存完整／未完成分支与配对覆盖，报告 PARTIAL，不删案凑 COMPLETE。预警不能自动修改协议或扩大上限。

恢复沿用已授权的 TRANSPORT_TRANSIENT_FAULT 一次重试与未知用量记录规则；其他未知用量类别不自动接受。
已返回且保存的有效响应不得再付费重取。协调器死亡后先确认旧进程全部退出再恢复；无法恢复的在途轨迹不自动整条重跑，记录情况后按既有授权处理。普通接线修复在不改变方法/权限/预算时自行完成，变更集中写入报告。
