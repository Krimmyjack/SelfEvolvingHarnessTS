- 域卡 vs 无卡：离线经验是否改善交付。

## 3. 零反馈路径（本包最重要的实现）

Source、Select、Test 的 Fast 使用同一零反馈协议。

**允许 Fast 读取和执行：**

- 本案例的公开任务信息、Consumer 说明、合法历史 T；
- 批级统计、按需获取的逐实体明细和历史片段；
- 原语与预设的定义；
- 构造材料、检查材料、提交合法方案。

**不得向 Fast 暴露：**

- 当前案例任何候选或公共参照的 C_A、C_B、E；
- 候选排名、历史筛选结论、缓存中的效果字段；
- “该域最优是什么”之类的人工答案；
- 其他案例的原始 Episode。

evaluate 以及返回下游分数的 compare 在此路径不可用。隐藏字段、错误消息、缓存状态和报告摘要也不得间接带出分数。

**提交机制：**

- 支持提交已构造、合法、尚未拟合的材料；提交冻结后，由外部 evaluator 训练和评分。
- 不得伪造“已评估”状态来通过旧 commit 校验。
- 旧的带反馈路径保持原行为，新路径显式启用。

**三臂一致性：**三个 Fast 臂获得相同的公开域身份、工具、观察字段和预算，差别只是加载的卡。共享卡可以根据合法信息执行条件分支。

## 5. 阶段 A：24 条 Source 无卡轨迹与成本实测

运行三域各 8 条无卡 Fast，均不看筛选分数。24 条提交全部冻结后，再由 evaluator：

1. 对最终提交做三 seed 拟合和 E 评分；
2. 同案例、同材料、同 Consumer 配置命中筛选缓存时复用；
3. 新构造的材料只训练最终提交的那一份；
4. 保留完整真实轨迹，与脚本筛选记录分开标注。

不得假设“大部分一定命中缓存”，命中率是实际读数。

**检查点报告（一页），内容包括：**

- token、调用数、材料构建时间的均值、中位数、P90、最大值；
- 无卡交付相对 None、NoMix、Source 固定方案的表现；
- 无卡选了什么、是否构造新方案、失败或未交付的数量；
- 与筛选菜单中更好方案的差距，注明是开发集上的事后比较；
- 剩余阶段的点估计、保守成本估计与拟定硬上限。

**A 段预算：**

- 24 条 Fast，最多 144 次逻辑请求；
- 最多 8 次额外传输尝试，独立计数；
- 总 token 上限 500 万，未知用量的保守预留计入；
- 新增拟合最多 82 次：最终提交最多 72、接线 6、技术重试预留 4。

A 完成后停止付费派发，不调用 Slow，不进入 Select/Test。这是一次预算与研究决策点，不设置“无卡必须差几 pp 才允许学习”之类的新门槛。若无卡已接近简单最优，如实呈现；是否继续由用户 / Planner 结合成本决定。

## 7. 阶段 C：零反馈选卡

每个 Select 案例运行本域两张候选域卡和两张共享卡，合计 24 × 4 = 96 条轨迹。本阶段不另跑无卡，避免非必要费用。

全部提交冻结后，外部训练和评分。选卡目标：

J_d(W) = mean_{c ∈ Select_d} Ē(c, W) / Ē(c, None)，越低越好；Ē 表示三 seed 平均。

**选卡规则：**

- 每域按本域 J 选一张域卡。
- 共享卡按三个域 J 的等权平均选一张。
- 只有数值完全相同的平局，才依次按较少部署 token、固定候选顺序破同；不把“不显著”自动当作平局。

本阶段只需额外建立 None 参照，不遍历十二个菜单。选定后冻结三张域卡和一张共享卡。Select 结果不回流 Slow 修卡；卡表现不好，也不能偷偷换成人工规则。

## 9. 读数、统计与费用

主差值沿用 G_c(A, B) = 100 × (Ē(c, B) − Ē(c, A)) / Ē(c, None)，正值表示 A 更好。先域内等权，再三域等权；不能让电力、交通因案例较多而压低太阳能的权重。

**必须报告：**

- F_domain − F0、F_shared − F0、F_domain − F_shared；
- 三臂相对各固定参照的差值；
- 每域、每时期及逐案例的结果，胜 / 同交付 / 负，以及最大伤害；
- 交付的程序、观察与构造行为、token 与拟合成本；
- 至少一个有益例子，以及一个有害或未改变交付的具体例子。

**统计处理：**

- 同一实体组和时期会重复出现，不能把 40 例当作 40 个独立样本直接计算标准误。
- 报告配对差，使用保留时期、实体组聚类结构的重采样区间，并补充留一时期敏感性分析；seed 波动另外报告。
- 固定方案差距、池内事后最优都是辅助读数，不能当作 Skill 的可实现上限。区间跨零不等于方法等效。

**成本分开记录：**前期筛选、本次离线学习、每案例部署。缓存减少了本次的物理费用，但不能把被复用的学习成本记为不存在。

## 11. 并行、恢复与交付

- **并行：**
  - 单协调器、单运行锁；最多四个在途 API 请求，跨案例独立运行。
  - 数值任务根据实测内存用 2–4 路；材料构建与拟合共同受资源池限制。内存不足时降低并发，不改变训练语义。
  - 同案例内按观察、构造、提交的依赖顺序执行。
  - 相同材料的训练由唯一任务负责，其他分支等待复用，避免重复拟合。
- **恢复：**保留已取得的有效响应；未知用量如实记录，按已有授权的恢复规则处理，不自行接受未获授权的费用风险。
- **禁止事项：**smoke 不得启动真实实验客户端；不新增哈希平台，不提交 git，不覆盖旧筛选产物。
- **交付：**一个入口和一套报告，包括 REPORT.md、METHOD.md、result.json、tables.md、冻结配置、预算记录和卡片。

## 12. 执行者接线说明（阶段 A，2026-09-23；不改变上文规格）

- **零反馈循环**：新模块 `methods/ttha/batch_zero_feedback.run_job_zf`，旧 `batch_research.run_job`（held_in / deploy）一字未改。
  - 工具只有 overview（逐实体表，按需）、inspect_data、build_material、inspect_material、commit。
  - 请求与每个工具输出都过“下游分数通道”检查（c_a / c_b / e / feedback / normalized_mse_macro 等键出现即中止）。
  - commit 冻结已构造、未拟合的方案或公共参照，写 `commit.json`，其中 `status = COMMITTED_UNFITTED`、`fitted = false`；不经过旧 commit 的已拟合校验。
  - 最后一次请求（按调用、工具或 token 闸）只开放 commit。
- **请求格式**：
  - 首个请求约 20 KB：案例卡、23 个字段的批级分位数、动作表和工具契约各出现一次。
  - 历史中每个 Fast 响应、每个工具结果只出现一次，不回显 overview、方案规格或指导正文。
  - 所有行动、拒绝、延迟和观察都保留在存档的 trace 中。
- **三个新字段**：用筛选包 `entity_features` 原函数，在各案例的 T 行上计算。谓词校验与编译使用扩展后的字段集，并真实参与赋值；smoke 已核对 `zero_fraction` 分位规则的逐实体赋值。
- **缓存**：`common/<case>/` 的注册表引用筛选材料，按赋值键匹配，文件留在筛选目录、只读，筛选目录不写入。
  - 提交的材料与筛选材料同键、同 Consumer 配置（2000 步、8 线程、同 roster / seed / profile）时，直接复用筛选的三 seed E。
  - 否则新拟合三 seed，再由本包的评分进程读 E 行。
  - 新材料构建与筛选一致，均用 torch 单线程。
- **传输与未知用量**：有界重试沿用上一包的做法（同一逻辑请求至多重试一次）。
  - 自动接受的失败类别限于 `TRANSPORT_TRANSIENT_FAULT`（attempt 0 或有界重试的 attempt 1），依据是用户在 TEMPORAL-COVERAGE 包作出的常设决定，每次写一份 incident 文件。
  - 其他类别一律停止派发、等人决定。
  - 从未得到应答的请求，在额外传输预算内原样续发一次。
- **纠错**：沿用上一包的每轨迹 2 次纠错；工具参数错误和响应格式错误共用这 2 次，且都计入 6 次请求。
- **smoke**：脚本客户端，20/20 通过；不创建真实 LLM 客户端，不拟合。
