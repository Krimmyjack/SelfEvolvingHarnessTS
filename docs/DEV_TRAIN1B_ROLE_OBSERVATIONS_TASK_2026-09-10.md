# DEV-TRAIN-1B：作用窗口观察与一次 Skill 修订

状态：用户在阶段总结后明确“继续推，看下效果”；本页是开跑前执行规格。
这是新的 development 配置，不覆盖 TRAIN-1，不与旧包直接相减归因。
用户随后要求缩小找问题阶段的数据量：首轮改为10 train/10 eval，固定取既有各角色
roster顺序的前10条，不按已知效果选样。只用于机制与明显方向，不能保证小效应功率。

## 唯一主问题

让 Fast 与 Slow 看到训练/预测各自实际作用窗口的事实，并明确部署能力边界后，
一次自主 Skill 修订能否改善后续真实交付，而非只学成全 identity？
不是测试“必须更多处理”；质量、伤害和固定基线均保留。

## 固定部分

- 复用 TRAIN-1 数值 evaluator 与 runner；10 train / 10 eval，来自含缺失 KDD development
  roster [40:80]各角色前10条；anchors312…852、192 X + 48 y、共享 Ridge 数值合同不变。
  训练人口缩小会改变模型，全部四臂与固定菜单在10/10重算，不直接使用旧20/20分数。
- 形成 u9/u10/u11；后续 u12/u13。全部已曝光，只作机制开发，不称 fresh/密封。
- 四臂 Static / 形成段校准固定单步 / 原 h0 Skill / 一次 Slow 修订的 Skill。
  共同从 h0 开始，不继承 TRAIN-1 未获采用的全identity卡，不人工填一个优胜 Skill。
- 形成与最终各训练轮内一条训练序列一份 W；每臂准备汇总后拟合一个共享模型。
  最终知识、W和模型冻结后逐条生成预测 V；无当前 Support 兜底，无 Fast Episode。
- 1–4步 DSL、风险线、候选槽、算子实现、修改比例和评价真值不变。
- 实验请求 cpa-grok-4.6 / http://127.0.0.1:8318/v1；返回须为既有 grok-4.6-build；
  不默换模型。Fast四路，Consumer拟合串行。

## 本包唯一共同接口调整

在现有 public_input 加只读 execution_observations：训练侧对当前序列的每个既有
240点执行窗，分别计算 whole/X/y 的一小组已有公开特征；预测侧只用当前192点。
保留原prefix特征，清楚标明范围，不能用window值冒充原全prefix特征。
不新增万能质量分数、未来效用、标签真伪判断或新的算子；不建立新Schema/哈希平台。
这些摘要在 inspect/propose/select 均可读，记录在该决定中，并进入Slow对应训练或
评价材料。不同执行窗的参数坐标仍按原DSL解释，不改变W的逐序列粒度。

公共能力说明明确：四种probe方向在无panel时不可取得，unknown不是效果为负；
本包没有当前Support与跨轨迹Episode，验证只指确定性合法性/试执行，不是下游得分。
不能把前缀位置直接搬到每个240点窗。说明不推荐算子/阈值，不强制提案或减少identity。
所有臂共用该说明。其相对旧包的效果不是本包可识别的学习增量。

## Slow与评价

保留原完整形成段X/y分解和逐条正负结果；按完整程序与响应方向整理小组，明确只是
事实分组而非共同原因证明。训练UID不按评价UID损失贴成败标签；共享模型信用仍未知。
Slow一次机会，一处已有文本surface，可PATCH/ADD/保持/弃权；仅既有schema/传输重试。
不向Slow送入u12/u13评分；不在看到后续结果后重写候选。

编译/暴露是过程检查，不因看起来保守或预期不涨分而拒绝合法暴露候选。
合法且有暴露则按完整人口跑完新旧两臂；未产出/不暴露则如实记无处理，不伪造比较。
最终所有决定与模型冻结后统一评分。主读数全10人群每窗口效用及两窗等权差，
同报每条收益、受损次数、最坏伤害、实际处理与调用成本。
故障保持UNKNOWN，不用可读子集替代人口；同UID/共享模型/相邻窗口不是独立样本。

## 资源与停止

单包沿用上限：2000次实验API尝试、500次fit、6小时活动运行；研发代理成本另列。
预计规模约100次Fast决定（形成10训练+30预测，旧/新最终各10训练+20预测）；
一次新的Slow机会，不连续抽到正号。出现值得追的信号后另做20/20确认，不把本轮当终验。
快照、形成材料和已完成决定复用当前包checkpoint；不修改旧包工件。
账户/身份错误停受影响线；有界暂态重试按实际计数，基础设施问题不算模型弃权。
只做新增的窗口绑定、并发隔离、信息墙、Slow字段送达定向检查，不重跑全仓测试。

## 判读与分工

- 新知识优于同接口旧知识且有实际收益/风险价值：局部学习线索，随后测重复性/迁移。
- 全identity或只保守退回Static：明确仍未学出准备收益，不追认成功。
- 有处理且更差：按角色和已有分解定位，禁止事后手选赢家。
- 无法完整计分：只报告可读部分，不以进程结束当方法完成。

Grok提供局部适配器实现；根Agent复核关键差集、接入已验收runner并执行结果审查。
单层委派；不改参考仓库、核心运行时、旧报告、DECISIONS/STATE，不自动commit。
一个主报告与独立run目录；9/15路线检查点不变。本包不自动授权更多同类轮次。
