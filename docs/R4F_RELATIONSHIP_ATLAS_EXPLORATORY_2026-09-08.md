## 1. 关系图谱：四个"因子"（按跨块稳定性排序）

全表 2×2×3×27 = 324 行在工件里；下面按因子归组，只列四块同号且四块 |Spearman| 中位 ≥ 0.13 的。

### 因子一：context 的"尖峰显著性" ↔ 清洗自身窗口的收益（最强、最稳）

pooled、**ctx 通道**（只在服务窗被程序修改的实例上算；ANCESTOR 335 行、W2 723 行）：

| 特征 | program | Spearman pooled | 四块 | 四块 \|ρ\| 中位 | 之前是否报过 |
| --- | --- | ---: | --- | ---: | --- |
| `local_robust_z_peak` | ANCESTOR / W2 | −0.412 / −0.347 | 全同号 | 0.460 / 0.386 | 是（R4E 0.83 的那条） |
| `outlier_region_end_fraction` | W2 / ANCESTOR | −0.289 / −0.232 | 全同号 | 0.338 / 0.248 | **新** |
| `spike_sign_balance` | W2 | −0.299 | 全同号 | 0.329 | **新**（正向尖峰越多，清洗越有益） |
| `spike_recurrence` / `spike_head_count` / `spike_tail_count` | W2 | −0.307 / −0.296 / −0.208 | 全同号 | 0.32 / 0.32 / 0.24 | **新**（R4A 里它们对 total 是弱的） |
| `spike_recency` | W2 | +0.292 | 全同号 | 0.315 | **新**（尖峰越久远/没有，越没收益） |
| `spike_peak_over_tail_sd` | W2 / ANCESTOR | −0.269 / −0.221 | 全同号 | 0.281 / 0.211 | 是 |

这八个量是同一个潜变量的不同侧面：**context 里有多少、多大、多近的尖峰**。它们与 ctx 通道的相关方向一致、四块全同号、
幅度 0.2–0.46——是本项目迄今最稳的序列级关系。R4E 只报了其中一条（z_peak 0.83 的 AUC），本包说明它不是孤例而是一族。
它在 R4A 里"看不见"，是因为 R4A 对 total 测，而 total 七八成是 route（R4D-A）。

开始与部署效用直接相关。方向都是"有东西可修 → 修了有益"。

### 因子三：极端尖峰是收益的主要来源（树探针根节点）

深度 ≤ 3 的回归树只作探针。pooled total 的根节点在 W2 上四折全是 `spike_peak_over_tail_sd`，ANCESTOR 三折：
阈值 ≈ 15，**55 个实例（6.5%）的均值 −0.68 到 −0.72，其余 785 个只有 −0.19 到 −0.20**。pooled ctx 的根节点四折全是
`local_robust_z_peak`（阈值 ≈ 10：48 个实例均值 −0.76，其余 −0.08）。per-channel W2 total 的根节点四折全是
`srv_tail48_period_filled ≥ 2.5`（291 个实例均值 −0.21，其余 −0.06）。

### 因子四：context 几乎全缺时，准备不再有益（树探针第二层）

pooled ANCESTOR total：`srv_gap_points ≥ 144.5`（context 192 步里 ≥ 75% 缺失）的 48 个实例均值 **+0.03**（无益/微害），
其余 737 个 −0.22。画廊里 pooled 最差的六个有两个（T119、T11 @3576）就是 87% 缺失、`z_peak` 因 MAD 退化到 10⁹–10¹⁰ 的实例
——这也暴露了 `local_robust_z_peak` 在极稀疏 context 上的**数值失效**（见 §5）。

## 2. 程序之间、Consumer 之间

- **同族程序的受益者高度重叠**：pooled 下 ANCESTOR 与 W2 的 total Spearman **0.554**（四块 0.43–0.63）；m_r0k 五程序矩阵里
  ANCESTOR–`outlier_iqr>winsorize` **0.717**、ANCESTOR–`outlier_iqr>hampel` 0.647、W1–`outlier_iqr>hampel` 0.673。
  受益重叠：840 实例中 439 两者都受益、162 都不受益、139 只 ANCESTOR、100 只 W2。**程序层的比较性知识（R2）有它的物理基础：
  裁剪族程序在同一批序列上起作用。**
- **route 与 ctx 两个通道互不相关**（Spearman −0.03 / −0.13 / −0.03 / −0.02）：训练侧作用与服务侧作用是两件独立的事。
- **pooled 与 per-channel 下"谁受益"几乎无关**：同一 (program, position, face, uid) 的 total 相关 **0.041（ANCESTOR）/ −0.023（W2）**，
  route 相关 0.003 / 0.006，ctx 相关 0.19 / 0.10；而两种 Consumer 的 Static 难度相关 0.477。**换一个 Consumer，同一条序列
  用同一个程序是否受益，重新洗牌。** 这是项目核心前提（质量随 Consumer 反号）在序列粒度上最直接的实测。

## 3. 看真实曲线：共同模式（人话，来自 12 张图）

1. **pooled 下最差的实例几乎全是 route 伤害、服务窗一个点没动**：要么是干净的强周期序列（T185@1464，z 1.2、缺失 5%，+2.02），
   要么是 context 87% 缺失只剩最后 40 步的序列（T119、T11 @3576，+1.18 / +1.06）。它们不是被"洗坏"的，是被换了一个更差的共享模型。
2. **pooled 下最好的实例是同一条序列 T23 在四个 origin 上**（−7.2 / −5.3 / −4.4 / −2.9）：context 里有 500 对 50 的孤立巨尖峰，
   裁掉就赢；尖峰留在 192 步窗内跨了四个 origin，所以这条序列的收益**持久**——序列身份在"有持久伪影"时是有信息的，R4A-b 的
   "身份 ≈ 噪声"是平均结论，不是每条序列都成立。
3. **W2 的 ctx 伤害有两种形状**：(a) 长缺口或尾部缺口被周期中位数填成锯齿（T2@1176、T155@1656：供体相位间差异大，填出来
   比线性插值更跳），(b) **MAD 全局裁剪把真实的上行水平抬升当成离群削平**（T152@2136：context 后段抬到 200、真值继续在
   150–200，裁剪封顶在 140）。`operators/s1_outlier.py` 文件头警告的正是 (b)。
4. **per-channel 下最差的实例也全是 route（ctx = 0），伤害缩到 +0.4–0.8，五分之六是 40–48% 缺失、前段大段空白、无尖峰的序列**：
   自己的训练窗里长缺口被线性填补再裁剪，教坏了自己的模型。
5. 最好的实例两种 Consumer 下都由"孤立巨尖峰被裁掉"主导；**没有一张"最好"图是靠填补缺口赢的**。

## 5. 这份结果不是什么，以及几个仪器问题

- **不是证据**。全部 development、行间重复观测、块只有 4 个；相关 0.2–0.46 在 335–840 行上不可能"显著"到能部署。
- **不是 Router 的输入**。因子一到四是给 Observation / Scope / 供给顺序设计用的假设，任何一条要进方法都得冻结后重测。
- **`local_robust_z_peak` 在极稀疏 context 上数值失效**（MAD → 0 ⇒ z 10⁹–10¹⁰）：它同时是本项目的 Scope 谓词特征（K0 卡 `z_peak >= 3`）。
  应加 floor 或按有效点数门控；这是一个具体的仪器缺陷，不改本包数字，呈执行线修。
- **`srv_donor_dispersion` 按点算掩盖了按缺口段的不一致**（画廊模式 3a 显示的是段级锯齿）；R4C 的该量应重定义后再测。
- **画廊只看了极端值**（每格 6 + 6 + 6），中间的大多数实例没有被看；模式描述可能只对尾部成立。
- 未涉及 W1 / W3 的三格（只有 m_r0k 的 g）；未改任何冻结协议、阈值、预算；未新增 SHA；未提交 git。
