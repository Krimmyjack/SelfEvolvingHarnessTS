## 先回答什么

第一阶段只问：在预训练预测模型的小预算适配中，原来冻结的增强材料能否改善下游？保持离线经验、交付方案、Source/Test 案例和指标，不重学卡。若以后需要证明模型条件化能力，必须另外让 Fast 读取 TSFM Consumer 描述、在 Source 上重新形成/选择卡；不能用冻结方案迁移冒充这一结果。

## 优先复用的模型与代码

Time-MoE-50M 公开权重（旧包总参数 113,352,192），现有 `_scratch/dev_data_readiness_ltsv_core_repair_signal/tsfm_env/` 下的 Windows venv、model、src 均存在。旧包记录的来源：模型 revision 446753ee、Time-MoE 源码 d3524fd；transformers 4.40.1。保留其版本，不升级现役环境。可复用 `ltsv_tsfm_helper.py` 的 KV-cache 可微 48 步展开；该实现旧包在真实输入上与官方 generate 逐位相同，接入新域后仍须在 Source 再验一次。

旧 LTSV 在 KDD/PRSA 上测的是逐块估值与修复，不是本轮增强。这里不做 LTSV 估值；零样本预测只能作锚点，因为没有训练就没有“训练数据增强”的作用通路。

## 建议的最小接入包（尚未授权执行）

1. 每域一个 Source 案例，依固定名单顺序取首例，不按新效果挑。检查 192→48 预测、有限梯度、父/子材料对齐、官方 generate 一致性。测实际峰值显存、每更新耗时及数据加载成本。
2. 三个 Source 案例的 None 微调：预注册 lr {1e-5, 3e-6}，每条 100 步，在 {25,50,100} 保存检查点，仅据 Source 验证误差冻结一套统一训练配置；未适配零样本结果单列。不开 Test 选设置。
3. 参数更新先沿用已跑通的全参数 fp32 微调，microbatch1、有效 batch4；parent/child 损失各半、相同父窗抽样流，通过累积梯度实现。不直接套 MLP 的 batch64/2000步，也不临时改成只训预测头。如果显存不足，保留失败记录后再定 LoRA 或 head-only 独立方案。
4. 确认训练：Source 上 None、NoMix、该 Source 原无卡轨迹已提交的程序，三 seed。域卡没有在 Source 上产生过交付，不人工替它补写答案。检查模型是否有可解释的损失变化及适配相对零样本的表现，给出成本，不把增强必须有正号作为实现验收条件。
5. 用户开放后，再跑与 PatchTST 相同的 40 Test / 六臂 / 三 seed，按相同物理材料去重。每条从同一预训练权重重置，禁止候选间串联继续训练。交付与配置统一冻结后打开 E。若时间紧先缩成三臂 None微调/F0/域卡，须在启动前定稿；不事后只保留有利臂。

训练目标优先复用已经验证的 48 步预测 MSE 和 KV-cache 展开，说明它与 Time-MoE 原生多头 Huber + router 辅助损失不同，是同任务下的受控适配。T scaler 沿用主包；先不增加逐窗标准化、截断负值或重采样等第二项变化。Source 测出实际性能后才能决定是否另开原生目标版本。

## 成本范围与约束

旧机器上的确认适配约 100 步/2 分钟、峰值显存约3.3GB，**仅作旧实验参考**。新增强训练含 parent+child 两次前向，耗时不能直接照搬。567 物理拟合在旧单次速度下已约19小时；考虑双视图，可能更长。所以 TSFM 全量不是今晚 PatchTST 的顺带任务。首包以 Source 实测给出完整/精简两档小时数，再由用户开放正式预算。

不下载另一套大权重、不启动云 GPU、不新增 API费用。Time-MoE 预训练语料与这些公开数据的重合状态待核实，不能宣称严格零样本未见数据。无论是否重合，冻结增强对同一预训练起点的配对适配比较仍需把此范围写明。

## 成本清单（2026-09-24 午补充；仍为准备状态，未运行）

依据：旧 LTSV 包在本机 RTX 4060 上实测 Time-MoE-50M 单视图 100 步适配 108–117 s、worker 冷启动 6.4–8.0 s、峰值显存 3.3 GB（`_scratch/dev_data_readiness_ltsv_core_repair_signal/REPORT.md`）。增强臂是 parent + child 两次前向，下表按单视图 115 s、双视图 230 s **估算**，不是实测；首包 Source 接线必须重测。

| 方案 | 物理拟合 | 其中双视图 | 单路 GPU 估计 |
|---|---:|---:|---:|
| 冻结迁移，全六臂（与 PatchTST 迁移同构） | 567 | 447 | ≈ 32 h |
| 冻结迁移，四臂（None / NoMix / 无卡 / 域卡） | 453 | 333 | ≈ 25 h |
| 冻结迁移，三臂（None / 无卡 / 域卡） | 357 | 237 | ≈ 19 h |
| TSFM 条件化重新学卡（与当前 PatchTST 包同构，约 1460 拟合） | ≈ 1460 | 多数 | ≈ 85 h，10/1 前不可行 |
| 一次性：Source 接线 + 三 Source 案例 None 校准（2 lr × 100 步） | ≈ 9 | 3 | ≈ 0.5 h |

- **资源约束**：显存两路（2 × 3.3 GB）在 8 GB 内可行；主机空闲内存目前 1.5–3.7 GB，TSFM worker 的主机内存峰值未测，默认单路。GPU 目前由 `DEV-AUG-PATCHTST-OFFLINE-SKILL` 占用（预计约 8–12 h），TSFM 接线须等它结束，不能与它并发。
- **开放前需用户决定**：跑哪一档（可先只做一次性接线与校准，按实测时间重估后再定档）；是否接受 Time-MoE 预训练语料与三数据集可能重合（只能写配对适配比较，不写零样本未见）；0 LLM、0 API 费用。
