# VLDB 方法定位与主实验安排（2026-09-23）

当前顺序：方法定调与主实验确定 → 两天内完成方法和摘要 → 补充机制、泛化与消融实验。本文是规划交接，不启动付费调用、训练或新的数据曝光。此前 DEV-AUG-SKILL-EVIDENCE-ABLATION 的整包执行后置。

## 1. 本轮论文的方法定位

研究问题：能否把历史任务中昂贵的下游训练反馈，转化为可复用的数据准备经验，使 Agent 在新案例上无需逐候选训练反馈，也能交付有效的时序增强方案？

本轮实证任务限定为预测训练数据增强。完整的数据就绪 Harness 仍保留原架构；本轮不将尚未验证的跨 Task、跨 Consumer 适应或自动画像路由写成已实现的论文贡献。

采用已经跑通的算法骨架：
1. 离线：在 Source 案例上运行数据观察、方案构造和材料检查，提交后用真实下游预测结果评价；记录可观察条件、可执行程序、效果与成本。
2. 学习：Slow 从这些证据形成 Workflow / Principles 候选，在独立 Select 案例上按实际交付效果选优，冻结共享卡或域卡。
3. 部署：Fast 读取新案例的训练历史、工具和冻结卡，构造并提交程序；部署决策不接收该案例的下游验证或测试得分。
4. 评价：提交冻结后，统一训练 Consumer 并评价未来预测效果及成本。

本轮按已知 domain 加载域卡；特征决定案例观察与处理，不将“自动找到正确域卡”写成现有能力。Comp、Edit、预设与条件化程序保留；NoMix 不是必须采用的起点。

主要主张是“离线经验提高零反馈交付的质量与效率”。域卡相对共享卡的额外价值作为待检验问题；不以必须超过 NoMix 作为唯一成功条件，但完整报告强固定程序对照。

## 2. Introduction 的逻辑与方法区别

- 数据准备的目标是改善下游预测；材料看起来更自然，未必带来更好的预测模型。
- 逐案例用训练反馈搜索处理方案成本高；完全依赖 Agent 的通用直觉，又会出现系统性处理偏差。
- 因此，将历史干预与真实效果组织成可执行、可复用的经验，在部署阶段减少昂贵的试错。
- 本文检验这种经验是否改善交付、节约多少成本、跨实体与时期能否复用，以及域级组织额外提供多少价值。

最相关工作围绕 Eval-Skill、DS-Agent、HAIPipe / CtxPipe 组织；增强方法比较优先考虑 AutoDA-Timeseries。不能把“离线学习”“每域一张卡”单独作为新颖性。区别须落到下游效用证据如何指导时序材料处理、可执行程序及整体质量—成本效果；这些区别是否足以支撑方法贡献，需要在方法稿中明确论证。

## 3. 主实验确定

数据和已有结果先固定：Electricity、Traffic、Solar；复用 OFFLINE-SKILL 的 Source / Select / Test 划分、40 个测试案例、3 个训练 seed、多时期与实体隔离。MLP 是已有主实验 Consumer。新增比较使用相同案例和计分，保留已曝光开发测试的身份，不包装为全新终验。

| 主表内容 | 用途 | 下一步 |
|---|---|---|
| None、NoMix、Source 选出的全局 / 域固定程序 | 判断增强收益与强简单方案的位置 | 复用已有缓存 |
| 无卡 Fast、共享卡 Fast、域卡 Fast | 论文核心端到端比较 | 复用已有完整结果 |
| 朴素指导卡：只给任务、工具和通用知识，不给历史效果 | 区分经验学习与普通提示指导 | 补一个简洁对照，不连带启动大消融 |
| AutoDA-Timeseries | 与已有自动增强方法比较 | 优先检查官方预测实现能否接入，按其机制适配 |
| 第二 Consumer：优先 PatchTST | 检查收益对 Consumer 的依赖 | 并行准备，随后补结果；先明确这是冻结方案迁移 |

AutoDA 接入若遇到实质兼容障碍，依据实现可行性改选 TSAA，并在读比较结果前记录原因。不能把随机菜单搜索命名为论文方法。外部方法所用训练、验证信息与计算成本分别记清；其常规训练不等同于给 Fast 开放测试反馈。

主指标：未来块预测损失、逐域结果、成对增益、学习与部署成本。沿用现有 normalized MSE 和 pp of None；可复用预测补充原尺度 MSE / MAE。成本同时列一次性学习和每案例部署，不只报 token 节约率。

中间过程优先用已有轨迹统计：交付了什么程序、材料改变幅度、构造与检查次数、失败/拒绝情况、卡片改变决策的实例。材料外观或改动幅度不是“数据质量提升”的独立证明，下游预测效用仍是主要依据。
