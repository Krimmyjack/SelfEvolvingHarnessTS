# DEV-SEQ-3：指导送达之后，后续 Fast 变了什么（开发级，2026-09-08）

**判词：`DELIVERED_AND_LOADED__AGENT_COMPLIED__SELECTION_LACKS_DELIVERY_AUTHORITY`**

> **2026-09-08 更正。** 本报告初版写的是
> `DELIVERED_AND_LOADED__DELIVERY_UNCHANGED__UTILITY_NOT_SEPARABLE`，并断言"Fast 读到了
> 没照做"。复核逐决策工件后，这个断言**是错的**：Fast 照做了——在卡片匹配的 3 条决策上，
> B 臂 select 阶段 **3/3 选择 identity**，而同臂在 57 条未匹配决策上的 identity 选择率是
> **8/57**，与 A 臂**同为 8/57**。交付之所以未变，是因为 **select 阶段对运行时供给的候选
> 没有否决权**。初版把架构上的否决权缺失，误读成了模型不服从。下面正文已按工件更正，
> 被更正的原文逐条列在第八节。

## 报告开头的四个回答

**指导有没有送到？** **送到了，三个包以来第一次。** g2 的 Slow 写出的指导卡
`missingness_deviation_identity_guard` 出现在 3 个目标决策的运行时 `retrieved_skill_ids`
里（A 臂 0 个，两臂分离干净）。g1 的卡仍然一个也没送到（0/60）。

**Fast 因此改变了什么？** **改变了选择，没有改变交付。** 在那 3 条被送达的决策上：

- **select 阶段的输出变了**：B 臂 **3/3 选 identity**，A 臂只有 1/3。这不是采样——同一
  次运行里，两臂在 57 条**未匹配**决策上的 identity 选择率**都是 8/57（14%）**，一个数
  不差。卡片自己写的 `predicted_agent_behavior_change` 前两项
  （`retrieve_skill:…`、`choose_candidate_kind:identity`）**都实现了**。
- **候选池与观察也变了**：暴露 3 条上 A 共提 5 个候选、B 共提 3 个；B 在 u9/T14 与
  u10/T146 各少提一个自主候选（`hampel_filter`、`impute_linear`），u10/T14 多做一次工具
  调用。
- **交付、Support、delayed 逐位相同**。原因不在模型：**运行时不接受 select 说的
  identity**。u10/T146 上 B 选了 identity，运行时照样探测池中那个由技能库供给的
  `cand_skill_…outlier_mad`，它 Support +0.0699 通过准入，于是被部署——delayed −0.0778。
  卡片第三项预测 `identity_retained` 就是在这里失败的，**失败在运行时，不在模型**。

**后续效果有没有改善？** **没有，主终点保持原定口径照报。** 主终点（u10/u11 全 20 条
人群配对 delayed，逐单元平均再等权平均）= **−0.004644**（u10 −0.020752，u11 +0.011465）。
u9 是**验证单元**，不进主终点（其差为 −0.014628）。

这个数字的**算术**贡献里，3 条暴露决策确实为 0——但**不能**因此说"全部是纯采样"，也
**不能**事后把主终点降级成无关描述。两点理由：(1) 两臂的 Episode 历史在验证段之后就已
经不同（u10/T14 与 u10/T146 上 A 带 4 条、B 带 3 条），而历史经
`method.py:374` → `fast_agent.py:804` 参与 Fast 上下文，所以未暴露配对**不是严格的同知识
配对**；(2) 全人群指标回答的是一个有效问题——**加上这套更新机制之后整个服务人群是否受
益**——适用面窄本身就是系统表现的一部分。可以确定的只是：**差异来自非直接暴露的决策，
来源尚未充分区分**。同一次运行内未暴露配对的离散为 mean −0.0084、min −0.3135、
max +0.1575、9/57 达 MATERIAL；这说明本次运行存在这个量级的离散，**不足以**证明"噪声必
然比信号大一个量级"。

**最早卡在哪里？** **采纳→交付之间，不是呈现→采纳。** 呈现通了，采纳也通了（select 改
成 identity）；断在 **select 阶段对候选池没有否决权**：全部 120 条决策里，agent 选
identity 的有 20 条，运行时**照样部署了 12 条（60%）**；agent 点名候选的有 96 条，运行时
弃权 33 条、改部署另一个 18 条。**agent 的选择决定最终交付的只有 53/116 = 45.7%。**

## 一、三项修补，全部接入并有实测证据

### 1. 特征说明改成事实

21 个特征逐条给出**公式**与**计算窗口**，写明每次决策从头重算，**删除了 DEV-SEQ-2 断言
的全部漂移话术**（"DECAYS"、"MONOTONE NON-DECREASING"、"scale-free"）——那些里只有一条
被真正测过，一条序列上的测量不是特征的性质。新增三个不同对象的区分：

| 范围 | 是什么 |
| --- | --- |
| 特征窗 | `values[:origin]`，整段已观测历史（u9 时 = 1656 点） |
| **服务窗** | `values[origin-192:origin]`，**Consumer 唯一看得到的 192 点** |
| 修改区 | 程序在服务窗上实际改动的点，执行时才决定 |

并写明：**这套词汇里没有任何特征测量修改区**——要指它就写正文。

**它确实进了 Slow 的推理。** g1 的卡正文原样引用了这条区分：

> "These features describe the whole observed history rather than the serving window,
> so this separation is cautionary rather than proof."

也就是说，Slow 读到了、理解了、并据此把自己的结论降级为"提示性而非证明"。**但它仍然
把这些全历史量写进了检索条件**——理解了尺度问题，没有改变写条件的习惯。

### 2. 动作事实

用**评价器自己的 `_prepare`**、自己的 `_linear_integrity` 基线与 `isclose(equal_nan=True)`
容差重放已合法打开的窗口——不重训、不花 Consumer 时间、不建新 schema。

**烟测校验：训练侧计数与评价器自报的 `behavior_point_count` 逐位相等**，是同一个数而非
近似。实测样例（T14 @1656，`outlier_mad`）：服务窗 **5/192** 点被改动；共享训练材料
**778/48000** 点、200 个窗口。

语义按要求标注：训练改动是**共享训练材料**的属性、不是被评价序列的属性；Support/delayed
各绑各自的 UID/窗口/程序/参数；delayed 合法到达前不记；UNKNOWN 保持；**计数是动作不是
效果**。g2 复用历史的 20 条记录全部补齐，0 条留 UNKNOWN。

### 3. 批内并行

批次之间串行、批内 4 路并发；每序列独立 backend/core/method/view/guard；拟合与共享缓存
写入串行在一把锁后；汇总按**固定 roster 顺序**。

**实测（不是预估）**：

| 指标 | 值 |
| --- | --- |
| 有效耗时 | **71 秒/决策** |
| 逐序列墙钟之和 / 实际墙钟 | 5286s / 1415s = **×3.74** |
| 有效调用速率 | 16 秒/次 |
| 故障 | **0**（6 格 120 决策全程） |

烟测另行验证：并行与串行读数**逐位相同**、**不多花一次 fit**、400 次并发计费**精确计
400**、每序列格预算互不侵占。损失的 6% 是拟合与缓存写入串行的那一段，正是设计要串行的
部分。

## 二、两组的边界：两张不同的卡，两种不同的结局

| | g1 | g2 |
| --- | --- | --- |
| 复用历史 | 23 条 Episode | 24 条 Episode |
| 分组 | 7 条实质失败 → 1 组（7 名/6 序列），13 条成功对照 | 7 条实质失败 → 1 组，11 条成功对照 |
| 卡 | `high_missingness_outlier_caution` | `missingness_deviation_identity_guard` |
| 条件 | `forecast ∧ mf>0.5 ∧ lmrf>0.05 ∧ z≥3.0`（4 子句） | `forecast ∧ mf≥0.4 ∧ z≥5`（3 子句，**无 lmrf**） |
| **暴露** | **0/60** | **3/60** |
| 结局 | 两臂不跑，效用未测 | 两臂跑满 |

**g1 为什么零暴露**——逐子句机械读出，与 DEV-SEQ-2 的失败方式**不同**：

| 子句 | 满足者 |
| --- | --- |
| `missing_fraction > 0.5` | **只有 T14**（三窗口全满足） |
| `longest_missing_run_fraction > 0.05` | **只有 T146、T16**，T14 从不满足 |
| `local_robust_z_peak ≥ 3.0` | 56/60 |
| **同时满足前两条** | **无** |

不是"某条子句永远为假"，而是**两条子句各自成立却从不落在同一条序列上**——合取建立在
互斥的证据上。它们是从形成段一起读出来的（u7 上 T14 同时有 mf=0.5655、lmrf=0.0689），
到臂窗口就分开了。

**g2 为什么送到了**：少写了 `longest_missing_run_fraction` 那一条。它的正文也正是本包
要试的设计——**硬前置只表达执行合法性，未验证的效果判断写进正文由 Fast 当场核查**：
"把缺失区与偏差区分开检查"、"宽或不确定的偏差跨度视为公开证据不足"、"只有当被检查的
假设有合法可验证绑定时才用最小局部程序，否则保留 identity"，并写明要保留什么。
**Slow 自己走到了这个形态，没有人指定。**

## 三、行为链：必须按暴露拆开读

把五个环节在全部 60 对上数，会得出"行为改变且部分决策改善"——**那是错的**：57 对里两臂
的**有效知识相同**（历史已略有分叉，见开头），其差异主要是采样。按暴露拆开后：

| 环节 | 暴露的 3 对（知识不同） | 未暴露的 57 对（其中 51 对实测严格同知识） |
| --- | --- | --- |
| 修改已加载 | **3/3**（A 臂 0） | 0 |
| 观察不同 | 3/3 | **40/57（70%）** |
| 候选池不同 | 2/3 | **39/57（68%）** |
| **交付不同** | **0/3** | **11/57（19%）** |
| 实质效果差 | **0/3** | 9/57 |

**采样本身**就让 70% 的配对观察不同、19% 交付不同。所以暴露那 3 对的"观察 3/3、候选池
2/3"**落在采样范围内，单看它们不能归因于卡片**。

但有一个环节**不落在采样范围内**，初版漏掉了它：**select 阶段选 identity 的比率。**

| | 暴露 3 对 | 未暴露 57 对 |
| --- | --- | --- |
| A 臂 select=identity | 1/3 | **8/57（14.0%）** |
| B 臂 select=identity | **3/3** | **8/57（14.0%）** |

两臂在未暴露面上的 identity 选择率**一个数不差**，而在卡片匹配的 3 条上 B 是 3/3、A 是
1/3。暴露集合是**在两臂开跑之前**由卡片自身的 applicability 判定的（`exposure_check`
先行，零成本），不是事后按结果挑的子集；按 B 臂 14% 的基率，3/3 的偶然概率约
0.14³ ≈ **0.003**。**n=3，这是提示性证据，不是结论**——第二步的重复设计就是为了确认它。

三条暴露决策的完整对照（**3 条记录只涉及 2 个 UID**：T14 出现两次、T146 一次）：

| 单元 | 序列 | A（无卡）select → 交付 | B（卡已检索）select → 交付 | 交付差 |
| --- | --- | --- | --- | --- |
| u9（验证） | T14 | `outlier_mad` 候选 → identity | **identity** → identity | **0** |
| u10 | T14 | identity → identity | **identity** → identity | **0** |
| u10 | T146 | `impute_linear` → **`outlier_mad`** +0.0699 / **−0.0778** | **identity** → **`outlier_mad`** +0.0699 / **−0.0778** | **0** |

最后一行是本包最有信息量的一条：**B 选了 identity，运行时仍然部署了 `outlier_mad`。**

## 五、select 阶段没有交付否决权（本包最实的发现）

这一节是复核逐决策工件时才出现的，初版没有。

`online_loop` 里，Fast 的 `chosen_candidate_id` **只决定探测顺序**
（`chosen_first_then_pool`），不决定交付。选 `identity` 的效果仅仅是"不把自己排到队首"，
候选池**照样逐个探测**，**第一个通过 Support 准入的候选就取得部署权**。这是明写的设计
（"Support 实测仍为最终确认"），不是缺陷；但它的后果是：

**任何通过 select 阶段起作用的指导，都不可能阻止一次部署。**

全部 120 条决策的实测：

| agent 的 select 输出 | 条数 | 运行时实际做了什么 |
| --- | --- | --- |
| `identity` | 20 | **照样部署 12（60%）**；保持 identity 8 |
| 点名某候选 | 96 | 部署该候选 45；**改部署另一个 18**；弃权 33 |
| — | **116** | **agent 的选择决定最终交付：53（45.7%）** |

那 12 条"agent 说 identity、运行时照样部署"的决策里，delayed 合计 **+3.5842**
（7 条正合计 +4.2745，5 条负合计 −0.6903）。所以**这个覆盖不是单向有害的**：Support 门
确实抓住了多数正收益，一律听 agent 的 identity 反而会净损失。**不能**据此说运行时该改。

能确定的是范围问题：u10/T146 上 B 的 identity 选择**恰好是对的**（delayed −0.0778），却
无处生效。卡片写的 `identity_retained` 这一项，**在当前架构下不可能被满足**，除非指导能
改变**候选池的构成**——而那条 `outlier_mad` 是**技能库供给**的
（`cand_skill_…`，`fast_agent._skill_frozen_candidates` 铸造），Fast 提不提它都在池子里。

**这条约束应当先于下一次卡片实验被处理**：继续让 Slow 写"证据不足时保留 identity"式的
指导，无论写得多好，都只能改变 select 的措辞，改不动交付。

## 六、本包修掉的六处我自己的缺陷

都是同一类毛病——**把可恢复的情况当成不可恢复，或让分母静默走样**。任何一处不修，本包
都会得出错误结论。

| # | 缺陷 | 后果 | 修法 |
| --- | --- | --- | --- |
| 1 | `error code: 403` 被列进账户标记 | 中转转述上游抖动被判为账户错误、拒绝重试、终止边界 | 拆出 `TRANSPORT_TRANSIENT_FAULT` 走有界单次重试；账户标记仍不重试 |
| 2 | `population_for` 先按形成人口取名再切 | 臂人口静默截断成 10 条，门跑在 30 而非 60 个决策上 | 先取两者较大值再按阶段切片 |
| 3 | 所有 runtime 拒绝一律终局 | Slow 在**已授权面**上条目类型写错即失去整组候选 | 拆出 `REFUSED_BY_RUNTIME_FORM`（可修正）与实质越权（终局） |
| 4 | `run_or_resume()` 缺 `concurrency` 参数 | 进程在边界之后直接崩溃 | 补参数并转发 |
| 5 | 中转暂态 400 不在共享重试范围 | 传输预检一撞就整组退出 | 在**本包层**加有界重试（3 次），每次尝试照实计费，账户错误立即上抛 |
| 6 | 行为链在全人群上计数 | 会把采样差异报成"行为改变且部分决策改善" | 按暴露拆成两块，Q6 只读暴露子集 |

每处都有保留的失败收据（`*.transport_403_attempt.json`、`*.form_refusal_attempt.json`、
被取代的 0/30 暴露收据），未覆盖、未删除。

## 七、最大未解问题

**最大未解问题**：**这张指导有没有增加判断依据？** 它改变了 select 的输出（3/3 identity，
对照基率 14%），但那 3 条里只有 1 条（T146）后续确实受损。**不能**因为 T146 后来受损，
就说 Fast 当时"本该知道"要弃权——当时它看到的是 Support +0.0699 为正。要回答的是：卡片
是否提供了比"Support 为正就用"更多的判断依据？本包 n=3，答不了。

**其次**：过程差异（少提一个候选、多做一次工具调用）**是否由卡片造成**，尚不能确定——
未暴露面的采样本身就有 70% 的观察差异。**不能**把它算成效率收益，也**不能**判成完全无
作用。

**方法论约束**：在这种暴露宽度下，全人群配对差**对"卡片效用"这个问题**没有分辨力（暴露
决策算术贡献为 0）。但全人群终点**仍然回答另一个有效问题**——整套机制对整个服务人群的
净影响——**因此保留为主终点照报，暴露子集与过程差异另列**，不因结果不好事后换口径。
（离散度为单次运行、n 小，作描述性报告，不称"可靠噪声底"。）

**已排除的一个解释**：初版写的"Fast 读到了不照做"**不成立**。模型照做了。

### 第 2 处的后续实测：历史通路存在，但基本没起作用

更正之后又量了一次——"历史可能污染"是可以直接测的命题，不该停在"尚未区分"。把两臂各自的
Episode 历史走一遍 `resolve_experience_contrast_pack` → `render_experience_pack`，即
`fast_agent.py:804` 之后注入 Fast instruction 的那条路：

| | 60 个配对 |
| --- | --- |
| Episode **条数**不同 | **25** |
| 注入 Fast 的**渲染文本**不同 | **6** |
| 其中落在 3 条暴露决策上 | **0** |

历史确实进了提示（实测渲染 596 字符，非空），但**条数不同不等于 Fast 看到的不同**：60 对里只有
6 对的注入文本真的不同，而 **3 条暴露决策上两臂的历史文本逐位相同**。

- **暴露决策上没有历史混淆**——那 3 条上两臂唯一的差别就是卡片。第五节"B 臂 select 3/3 选
  identity"这个读数不受影响。
- 未暴露面上，**51 对**快照视图与历史文本都逐位相同（严格同知识）：配对差 mean −0.0093、
  min −0.3135、max +0.1575，**41 对完全相同**、6 对达 MATERIAL。被污染的 6 对合计 mean −0.000665
  （5 对恰为 0），**对主终点贡献可忽略**。

按证据收窄：初版说"全部是纯采样"**当时没有根据**（没测），**测完之后基本成立**——51/57 严格同知识，
污染的 6 对贡献近乎零。但要注意 **41/51 完全相同**：模型在这条链上大体是确定性的，离散**集中在
少数几条序列**而非普遍抖动。这也修正了初版"噪声比信号大一个量级"的说法。
