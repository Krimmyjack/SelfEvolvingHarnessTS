## 1. 目标与本包的变化

核心问题：在多种时间情境中形成的每域 Skill，能否在同域其他实体、后续时期，帮助 Fast 构造和交付更好的增强训练材料？

一次跑完三个比较：
1. F_domain 对 F0：学习经验是否改善完整 Fast 的交付？
2. F_domain 对 F_shared：分别学域卡，是否比两个域共用一张学习卡更好？
3. F_domain / 最终采用系统对随机搜索、开发固定程序及公共参照：效果和成本处在什么位置？

主要改变是案例的时间覆盖与先后组织：前六个分散时期形成经验、接着两个时期选优、最后四个时期测试。动作空间、Consumer、每案例反馈几何和 Fast 搜索预算保持现役定义。加入共享学习卡是必要的分域消融，不新增 Router。

本包不只是提交选择器实验：Fast 必须保留观察、完整原语构造、条件化、材料检查、真实评估及自主提交的全部接口。NoMix 只是可用预设和强参照；不要求无卡先胜它才允许学 Skill，也不手工规定任何域的答案。

不启动新的 TSFM、缺口线、算子库、强度搜索、历史拟合反馈字段、Consumer 调参、公开模型排行榜或多轮修订。这是一次生成竞争—选优—冻结复用，不宣称已经完成论文全流程或持续进化。不得另插一包“先证明有空间”的普查。

- 全包HTTP最多4在途。9个独立 Slow提案也进同一池，不串行等待无依赖任务。
- 数值重任务全包默认2路，接线实测内存允许时3路；每个训练进程保持现役8线程。不是每案例各开3个。
- Fast等拟合时其他案例可发请求；同一轨迹内请求→动作→反馈依赖不能并行乱序。
- 阶段内标签处理可跨案例并行；Source/形成/Select/冻结/Test依赖及标签屏障保留。

沿用 decision_priority 已验证的OS锁、请求级usage、write-once响应、预算预留和缓存归属；不要重建调度或哈希平台。数值进程RNG隔离；协调器不加载torch；现役OpenMP初始化与不继承 KMP_DUPLICATE_LIB_OK 的约束保留。

未知usage时暂停新增付费派发，先收齐在途响应并记账。执行者不得代用户接受未知费用；本次起草/用户转发不等于自动接受未来未知usage。无未知费用的普通技术故障按原状态恢复；已收到有效响应不得再请求。

最多8次额外传输尝试，全包每逻辑请求最多一次；仅在已确认未计费或未知项已由用户明确处理后使用。有效响应的格式纠正算新的逻辑请求，不能叫网络重试。监控实际退出码、stderr和最后成功事件，不启动第二个恢复器。
