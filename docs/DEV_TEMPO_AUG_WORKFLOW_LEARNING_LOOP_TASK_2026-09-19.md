## 0. 目标与这次必须补齐的部分

核心问题：同一域内，通过“多候选 Workflow → 真实使用 → 后续反馈修订并提炼 Principles → 独立阶段选优”，能否改善 Fast 在后续批次上的交付质量或完整成本？

本包修改的是 **Skill 学习流程**。沿用现有 TempoPFN 增强空间、共享 Consumer、七工具和时间反馈定义。不给研究者手写增强答案，不要求无卡 Fast 先胜过简单方法。

本次不能省略：
1. 六个早期批次的合法历史：包括成功、失败、C_A/C_B 冲突及旧卡实际使用，而非只读四条无卡示范。
2. 两次预定的初始提案调用，总共最多四个 Workflow 候选，实际试用后保留两条父分支。
3. 每条保留父分支一次真实反馈修订机会；明确开放 Principles，不再永久固定 null。
4. 初版父卡、修订子卡、无卡在两个选优批次上共同竞争。
5. 后续批次保留“仅初版学习”和“允许反馈修订”的对照；即使系统选择不用卡，也实际测量最佳非空候选的表现。

这是一轮有界的同域学习闭环，不是原论文百例课程的完整复现，也不替代 AGENTS 的最终 A5/跨域/无反馈部署验收。新增 Principles 与 Workflow 修订作为同一个学习流程考察，不宣称单独识别某一字段或提示句的因果作用。

参考：Eval-Skill，https://arxiv.org/html/2606.07040v2 。借鉴候选探索、实际使用反馈、工作流与原则、无卡竞争；本包明确采用下表时序数据 setting。

## 4. 学习契约：反馈必须如何进入经验

### 4.1 三种反馈角色

以下语义必须明确写入 Slow 的系统任务，不仅出现在字段名：
- C_A：Fast 当时合法使用的即时反馈，解释它为何做出决定。
- C_B：本次开发经历的后续泛化反馈，用于评价原决定是否值得复用、需要收窄或修正；不是可忽略的旁注。
- E：本轮后续检验结果，所有知识和交付冻结后才开放，不进入本轮学习。

C_B 也只是有限时间块的观察，不等于普遍正确答案；C_A/C_B 冲突要保留，不能改成“以后无条件相信 C_B”。

### 4.2 统一 evidence 输入

从全部白名单轨迹确定性提取：
观察和实际调用 → 假设/完整方案 → 逐 seed/origin C_A → 当时 commit 与理由 → 所有实际已评估材料的逐 seed/origin C_B → 成本/失败。
保留候选材料语义和当时加载卡；失败/未评估值保持缺失，不能填 0。
材料身份去重但不删除行为轨迹；相同测量被多条轨迹引用只计一次数值证据。
跨分支 evidence_ref 必须包含 branch，避免旧的 job:event 编号碰撞；用字符串路径，不新增哈希。

Slow 的候选/修订输出除可部署正文外，附一个简短 `evidence_review`：
- 哪项观察支持哪条建议；
- 哪个后续结果反驳或限制原判断；
- 因此保留/删除/改写哪条规则；
- 尚不确定什么，以及下一次使用中预期哪种行为会改变。

这属于本次输出字段，不建设新证据平台，也不把这些历史逐项记录直接送给 Fast。对明确有数值反例的规则，要求模型回应反例；不由研究者指定正确原语。

压缩只去掉重复模板/数组展示，不丢动作、方案、数值、失败及冲突。每次首次科学调用前核对实际序列化请求、模型上下文长度与计费预留，保证纠错余量；不能用超预算/序列化失败冒充 KEEP。

### 4.3 权限、归因和卡片容量

共同基础提示明确：
“允许按合法 T 观察构造统一或条件化方案；单实体预测变化不能视作该实体材料的独立因果贡献，条件化完整方案仍可由共享训练比较。”

原有因果提醒保留。学习卡可以建议简单策略，但不能宣称工具不支持分组，或仅凭因果提醒推导普遍禁令。不建立研究者按偏好退卡的语义门；证据薄弱的合法候选由真实使用与选优评价。

全部候选共享 rendered body **6000 字符**上限（含 Workflow/Principles 标题），不再沿用 1200 字符挤掉关键条件。通过 study opt-in 参数贯穿 make_skill/apply_update/加载，不修改旧默认限制、不截断正文。初版允许用满同一上限。

初始候选先产生 Workflow；修订阶段明确要求尝试提炼 Principles：
Workflow 写观察、实验、比较与停止的流程；Principles 写证据支持的偏好、适用条件、反例与不确定边界。不能用泛泛的“谨慎”“看数据”替代。
证据不足时可以 KEEP 或不增加原则，但必须记录判断，不能省掉真实修订调用。

scope 继续 const:true、已知域加载；适用条件写进流程内部。Fast 每次最多加载一张完整冻结卡，不读原始跨 Job Episode。ID、来源名、行号答案表和历史 assignment 不写入可部署正文。

## 5. 完整执行流程

### A. 初始形成：两次探索调用，最多四张 W0

调用 A1 读取前六批 census，提出最多两种有理由不同的研究 Workflow。
调用 A2 读取同一 census 与 A1 原文，再提出最多两种不同的研究组织假设；它发生在任何新 Practice 分数出现之前。不得用改名/换措辞凑满四张。
差异可涉及诊断、构造、实验安排或提交判断，由 Slow 决定；不预先指派“某一张必须分组/用某算子”。

每次可 KEEP；每次至多一次纯格式/合同纠正，不因不喜欢内容追加调用。原文完全相同则别名合并；语义相近的合法版本照常试，不人为挑赢家。
正常 KEEP 与技术/预算形成失败分开。两次均 KEEP 则记 NO_INITIAL_PROPOSAL，停止本包，不能假装完成学习后启动 Test。

### B. Practice：两批真实试用，选择两个父版本

在 L1/L2 上运行全部合法初版候选，最多 4×2=8 条 Fast。L1 按候选 ID 升序，L2 反序；各自独立对话、相同基础提示与预算。
全部 Practice 分支结束后统一开 C_B；不生成/读 E。

每个候选按两个 Job 实际 commit 的 C_B 计算：
`J_P(v)=mean_j(mean_seed C_B(v,j) / mean_seed C_B(None,j))`。
两批完整可评分的候选按 J_P 由小到大保留两个父版本；数值平局按候选 ID。只有一个就保留一个，不补造。
此处是分配修订预算，不是宣布有效：即使两个都不如历史无卡，也应继续按计划给修订机会。
历史无卡仅作背景；本阶段不以旧提示下的历史行为冒充新的配对无卡臂。
没有任何完整可评分父版本则停止为 PRACTICE_INCOMPLETE。

### C. 修订与 Principles：每父版本一次

每条父分支调用一次 Slow。输入：父卡原文及原假设、初始合法 census、全部 Practice 卡的实际使用轨迹/C_A/C_B/成本及失败。
要求识别“建议没执行”和“执行了但没收益”，用后续反例修正可复用内容；不得只美化原叙述。

输出 KEEP 或一个子版本：
- 可有限改 Workflow 的一个主要行为机制；
- 可同步提炼服务该机制的 Principles；
- 保存原文、变化、证据和预期行为；最多两个子版本。
不规定必须更保守、更多观察、改变算子或分组。不允许修改 Consumer、权限、预算、评分和随机性。
每分支至多一次合同纠正；不进行第二次科学重写。KEEP 是同父卡别名，不编造“修订已发生”。
本包联合检验反馈修订流程；不能把结果独归于 Principles 或某一句 prompt。

### D. Select：新旧版本与无卡共同选优

在 L3/L4 上运行：两个保留父版本、两个实际产生的子版本、无卡，最多 5×2=10 条 Fast。
L3 顺序 [无卡,父1,子1,父2,子2]，L4 反序；不存在项跳过，完全同请求条件的别名只跑一次。
全部 commit/未完成状态冻结后统一开 C_B，不开 E。之后不再调用 Slow。

使用同样的 J 公式、只换为 L3/L4，分别冻结：
1. **W_initial**：两个父版本中的最低 J，代表只做初始探索和选优。
2. **W_learned**：父版本+子版本中的最低 J，代表允许反馈修订后的最佳非空卡。
3. **H_system**：在 W_learned 与新无卡之间取最低 J；无卡数值平局优先。
4. **Fixed_dev**：四公共参照中同一 J 最低的一份完整固定材料，供零额外成本强对照。

非空卡并列时父版本优先，其后按候选 ID；容差 1e-12。以质量为选优目标，成本单列，不临时加罚项或显著性门。技术不完整不能当零收益；所需选优比较缺失则标 SELECT_INCOMPLETE，不凭文字冻结赢家。
冻结文件须早于任何 Test 特征进入 Agent 和首次 Test 拟合。

### E. Test：三批固定知识，真实比较

每 Job 跑三条 Fast：
- F0：无卡；
- F_initial：W_initial；
- F_learned：W_learned。

另跑同预算 RandomSearch_B4，报告 Menu_CA、Fixed_dev 和四公共固定参照。
H_system 的交付是冻结规则选定的 F0 或 F_learned 的别名，无需第五条研究臂。

即使 H_system=无卡，仍运行最佳非空 W_learned，明确标为隔离的候选检验，而不是已采用 Skill 的部署结果；不能再以“空卡别名=无卡”替代其效用测量。
若 W_initial 与 W_learned 正文/知识条件完全相同，复用一次 Fast 并报告无修订差异，不冒充独立重复。

执行顺序：
- L5：[F0,F_initial,F_learned,Random]；
- L6：[F_learned,Random,F0,F_initial]；
- L7：[F_initial,F0,Random,F_learned]。
四公共参照同样提供给所有研究臂。当前 Job 不共享其他臂对话/候选。

Random 完整继承父包两统一+两条件化分布、去重/退化规则及独立 RNG，只追加 job_index；第一次该 Job 拟合前冻结四方案。Menu_CA 在四公共参照中按 C_A 均值选，0 额外拟合。
固定方案的开发选优成本和所有方法逻辑成本均要报告。

## 6. 标签屏障、恢复与缓存

Practice、Select 各自完整阶段先 commit/记录失败，再开 C_B。开发区已有旧标签也不能通过缓存元数据混进 Fast 请求。

Test 全局屏障：
三 Job 所有臂尝试结束且全部交付冻结 → 统一 C_B → 全部所需 E 预测冻结 → 统一 E 评分。
不得看到 L5 的 C_B/E 后再决定 L6/L7 的卡、候选分布、停止或预算。

沿用父包的未知 usage、labels_withheld、resume 边界与已构造未评估方案恢复处理。未知费用如实记 UNKNOWN，暂停后续收费调用；接受未知费用不解除标签边界。
失败请求不改记为免费；形成技术失败不等于 KEEP，不得跳入 Test。

只针对技术失败同配置重试一次；Practice/Select/Test 各最多两次额外拟合，共六次。全包额外原样 HTTP 最多四次；每请求最多一次。
在不改变方法/数据/反馈/预算且未开受影响标签时可修普通 bug，保留记录，不为常规修复等待多方批准。重大边界/投入变化才交用户决定。

## 9. 读数与解释

主问题按顺序回答：
1. Slow 是否针对原卡的实际失败/冲突作出可定位修订？后续 Fast 是否执行了这项变化？
2. W_learned 比 W_initial 是否改善交付？父子 Select 配对和 Test 阶段选择后的比较分别列。
3. H_system 相对 F0 的完整系统收益如何？若选择空卡，其收益=0 与候选 W_learned 的效果分开。
4. 是否胜过 Random、Menu_CA、Fixed_dev 和公共固定增强？收益是否值得学习成本？

每 Job 逐 seed 保存提交 C_A/C_B/E。Test 主配对差：
- d_evolve=E(F_initial)-E(F_learned)；
- d_skill=E(F0)-E(F_learned)；
- d_system=E(F0)-E(H_system)。
正值表示后者更好。其余对照同方向定义。
主汇总 G=mean_j[100×mean_s d(j,s)/mean_s E(None,j,s)]，三个 Job 等权；单位是相对该 Job None 平均损失的百分点，不混写成相对 Fixed 百分比。

每 Job 报逐 seed、配对 SE、n=3 的双侧 95% t 区间（df=2），不要用 2SE 冒充该区间。
同时报告三 Job 各自结果/均值/范围，起点全部保留。多个种子和配对候选不是独立 Job；本包不估计 LLM 重复决策方差。
缺失配对不填 0、不悄换主分母；完整性与可用子集描述分开。

缓存行为诊断仅解释机制：相同/不同材料、同/不同 commit、从何种合法观察形成假设、是否用中间反馈、哪些修订执行/未执行。更多步骤、更多原则、选不同算子、少花调用都不是自动成功。
CA/CB/E 排名和事后最佳只作解释，不再据此追加实验。不能将“argmin 未命中”写成“所有反馈无信息”。

成本分三层：历史学习资产的原始成本；本包增量学习成本 A–D；每 Job 部署成本（含基线准备和 Consumer）。同时给真实物理账本与每臂独立运行的逻辑成本，旧缓存命中不能当作方法免费。
质量相近只报告相近，不用宽区间宣称等效；省成本需连学习成本和可定义的摊销批次数一起报。

结论边界：
- 子版未被选中/KEEP：修订机会已提供，但该次进化增量未建立。
- 候选正、系统因开发选优弃权：候选效用与采用决策失败分开，不追溯选卡。
- 胜无卡但不胜简单对照：只支持有限指导收益。
- 只胜 None：主要归于增强，不自动归于 Skill。
- 有行为变化无净收益：如实收口，不追加第三轮。
- 正结果也只支持这一域、当前课程与 Consumer；不直接宣称长期持续进化、跨域迁移或原论文复现成功。
