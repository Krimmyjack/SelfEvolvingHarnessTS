## 0. 早上要的两个答案

> **收益主要来自新增候选，还是 Skill 更新也提供了额外价值？**

**主要来自新增候选。Skill 更新没有表现出额外价值。**
B−A（供给的价值）两组都为正：**+0.039170 / +0.032167**（delayed 面，全服务人群）。
C−B（写回卡片的额外价值）两组都不为正：**−0.054696 / −0.002144**。

> **这个判断在两组运行中是否一致？**

**B−A 一致（两组同号、量级接近）。C−A 不一致（−0.015526 / +0.030023，异号）。**
C−B 两组同为负，但**必须加一句限定**：第二组 C 一次写回都没有发生，
所以那一组的 C−B 测的是"两个机制相同的臂之间的运行间差异"（−0.002144），
不是更新机制的效应。真正含有写回的只有第一组，那一组 C−B = −0.054696。

**一句话**：供给这条通道在两组里都买到了东西；写回这条通道在唯一一次真正
发生的组里让结果变差，而且变差的原因已经定位（见 §4），不是噪声。

## 1. 三臂与隔离的那一件事

| 臂 | Fast 本地适应 | 外环提议与候选供给 | 目标卡 PATCH |
|---|---|---|---|
| **A 控制** | 保留 | 无 | 无 |
| **B 供给-only** | 保留 | 开放 | 无 |
| **C 供给＋更新** | 保留 | 开放 | 开放 |

隔离的是 `fast_winner_forecast_ridge_smase_outlier_mad` 卡冻结程序体的 PATCH，
**只有这一件**，不外推为所有 Memory 机制的贡献。

**B 不是"没有持久化"，是"不覆写目标卡"**。B 保留了正常的 Fast 生命周期，
包括 `activate_approved` 铸出新 Skill 并在后续被 `recalled_skill` 取回——
g1 里 B 的 `outlier_iqr` 就是这样在 u12 被重新取用的。这正是任务书要求的
"不顺带冻结已有执行资格或正常本地适应"。

**B/C 对称的关键**：验证事件在两臂**完全相同**。候选被 Fast 部署且 delayed
权威门通过时，两臂都记录事件、都按同一时刻关闭 Draft（B 记
`VERIFIED_BUT_NOT_WRITTEN_BACK`，C 记 `PROMOTED_TO_THE_SKILL_CARD`），
所以候选**在同一时刻退出供给池**。DEV-AUTO-2 里"不晋升的臂会永远重复供应"
的额外机制差异被消掉了。C 只多做一件事：把程序写到卡上。

三臂各自维护历史、Draft ledger、预测缓存与提议轨迹；缓存键含臂名，
不跨臂共享；分歧之后不重置为共同历史。模型、编辑空间、准入规则
（released bounded）、每臂额度（1000/3 = 333 次 LLM）一致，成本分臂记账，
**没有为了凑齐成本而发无意义调用**。

## 4. 为什么 C 更差：更新覆盖了仍然有效的知识

g1 逐单元 delayed 收益（三臂配对）：

| 单元 | A | B | C |
|---|---|---|---|
| u14 | 0.000000 | 0.013508 | **+0.141939** |
| u15 | 0.000000 | 0.271883 | **+0.360868** |
| u16 | 0.092525 | 0.132108 | 0.000000 |
| u17 | 0.000000 | 0.036670 | **−0.063268** |
| **u23** | **+0.595428** | **+0.595428** | **0.000000** |
| 合计 | 1.026822 | 1.653543 | 0.778408 |

C 在 u14/u15 靠新候选拿到 +0.50，然后在 u16/u17/u23 丢掉更多。
**u23 单格就是 −0.595428**，比整个更新通道挣到的还多。

机制已定位，收据俱在：

1. u14、u15 两次写回把卡体从 `[outlier_mad]` 改成 `[winsorize, outlier_mad]`
   再改成 `[hampel_filter, winsorize]`。
2. u17 Fast 经 `recalled_skill` 取回这张卡并部署，delayed **−0.063268**，
   权威门四条线里挂了三条（aggregate / harmed_fraction / single_series_harm）。
3. 生命周期随即**撤销了这张 Skill**：`snapshot_after: []`、
   `skill_bodies_at_end: {}`、store active 退回 K0 之前的 bundle。
4. u23/u24/u25，C 的 `snapshot_skill_ids_at_start` 是**空**，只能服务 identity。
   同一时刻 A 还有它的 `outlier_mad` 卡、B 有两张卡，两臂在 u23 都部署
   `outlier_mad` 拿到 **+0.595428**。

**PATCH 是就地覆写、且只有一个槽位。** 失败的修订不会退回旧卡体——
撤销把整张卡一起拿走，连祖先程序 `outlier_mad` 一起丢了。
B 没有覆写目标卡，所以它把祖先卡留住了，同时通过正常铸卡路径把新知识加在旁边。
这就是"更新覆盖了仍有效的知识"的字面版本。

按任务书 §6：不靠放松风险线救结果。**风险线一条没动**，
u17 的门失败是真实读数，撤销是既有生命周期的正常动作。

## 5. 仪器修复：Draft 重号（随包完成）

`DraftLedger` 的两个铸号点都用 `self._minted += 1`，而 M-R0d 入场态重建
**直接 append** Draft 却不推进计数器（实测：1 个 Draft，`_minted == 0`），
于是课程里第一次 `open_restricted` 又铸出同名 `resupplied_draft_1`。

修法：新增 `_mint_draft_id()`，跳过 ledger 里已存在的任何 ID。
**不重编号、不覆盖历史收据**，已有 Draft 的身份、验证次数、修订次数与关闭状态
逐字段保留（预检逐字段比对）。针对性检查 `a_restored_ledger_does_not_mint_a_used_id`：
载入已有 `_1` 后，新建 Draft 必须拿到 `_2`、再建拿 `_3`，且 `by_id` 无歧义。
另有 `the_live_entry_state_is_the_shape_this_fixes`，直接对真实入场态断言
"计数器落后于已有 ID"。

本轮三臂的 Draft ID 全部唯一。**不能仅凭 DEV-AUTO-2 的两次晋升用了 `_2`/`_3`
就说重号当时没有影响**：`by_id` 只返回第一个匹配，DEV-AUTO-2 里两个共号 Draft
中有一个是入场态带入的 `outlier_mad`（3 次验证、REVISABLE），
另一个是课程新开的 `outlier_mad>repair_level_shift`（0 次验证），
供给池与关闭逻辑都读过它们——旧结果单列保留，不追溯重算。

## 6. 按 §6 收口

命中的是第三种情形：**C 劣于 B**。按要求做了两项检查：

- **更新是否覆盖了仍有效的知识**：是，见 §4，且损失可逐格定位。
- **旧提议是否被迟到采纳**：g1 的 C 两次写回都源自 u13 同一次调用；
  B 在 g1/g2 各有 1–2 个候选在提出后 5–8 个单元才被验证
  （`outlier_iqr` u5→u11、`outlier_mad>winsorize` u9→u14），
  说明迟到采纳确实存在，且**供给通道本来就支持它**——不需要写回卡片。

同时命中第四种情形的一部分：**C−A 两组异号**，属于"结果高度不一致"。
按要求报告运行依赖而不挑好的一组：g1 的 C 触发了 2 次写回并随后被撤销，
g2 的 C 一次写回都没触发；两组 C 的命运由"Fast 是否恰好部署了那个候选、
delayed 面是否恰好过门"决定，而那是本设置下方差最大的环节。

**不追加实验直到跑赢。** 本包到此为止。

## 8. 行为路由只作解释，不作因果

**候选供给具备开发级价值；持久更新目标卡的增量价值尚未建立，且现配置下有明确的下行风险。**
