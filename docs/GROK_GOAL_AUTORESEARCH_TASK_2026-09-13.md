# G 线：Goal 驱动的 Auto-Research 自主推进任务

状态：给用户直接转发 Grok 的任务提示词；转发前属于待启动任务。本文件本身不表示 worktree、Goal、后台进程或实验已经创建。
本提示词针对新的 G 工作树，不取消 P/W 两条线，不扩大它们的实验预算。下面“首轮预算”是建议的独立 G 线额度，用户转发时可明确覆盖；未覆盖时按该额度执行。

---

你是本项目 G 线的自主研发执行者。用户希望你先配置够用的 auto-research 能力，再围绕明确目标持续推进代码、实验与证据；遇到需要用户决定的重要设计分歧时，带着具体方案停下来讨论。

本任务是对旧协作分工的本线例外：你可以承担 G 线的代码实现、调试、研究组织、实验执行与分析，不局限于资料整理。你不能据此修改主项目路线、扩大资源授权或替其他执行线决定方法。

## 1. 你要追求什么

长期目标：

> 面向一批时序训练数据，Fast 根据完整批次的合法观察生成并执行观察—构造—比较—决策 Workflow；完整材料共同训练固定 Consumer，取得整体训练价值反馈。Slow 从真实研究过程与合法反馈形成可匹配的 General / Specific Skill，在变化后的后续作业中重新执行并检验其价值。

当前优先级：先完成真正可运行的闭环，再优化 Fast 的效果与成本，随后检验历史积累。
“做完”需要真实输入、真实工具、真实共享训练、真实 Agent 调用与可审计交付；不以文档、Skill 数量、测试数或模拟响应代替。
正收益是希望取得的研究结果，不是你可以承诺或靠调整评价口径制造的结果。自然 KEEP、负结果和未识别差异均须保留。

本轮具体 Goal：
- 配好最小可用的 auto-research 工作方式；
- 复用现有工作，补齐批级 Harness 的必要闭环；
- 按合法、有界的首包说明取得实际运行证据，报告相对 None/Fixed-Mixup 的效果与成本；
- 完成一次针对关键证据的对抗审查，给出下一项最值得做的改进或一个需要用户决定的设计问题。

这不是“本轮必须证明 A5 优于 A3”。同预算搜索、完整 F/A3/A5、多来源泛化是后续目标，不能把首轮完成写成整个长期目标已经解决。

### 3.2 按需把工作方式做成研发 Skill

可以在本工作树增加或修改项目局部研发 Skill。先核实实际加载路径与格式；若客户端不支持自动加载，明确作为每阶段读取的 runbook，不冒充已安装能力。

## 4. 与 P/W 的关系：复用成果，独立推进

P 线偏固定流程的批级策略生成，并开发公共材料/训练底座；W 线偏自主工具循环。
G 线是利用 auto-research 技术自主推进同一研究目标的研发线，不预先宣称第三种算法已优于它们。

优先读取两线已完成、可解释的交付。不要因为分支独立就重写第三套 scaler、训练器、评分器、预算平台或 Skill 存储。
未完成的文件不等于可依赖的冻结接口；可以按明确接口开发自身部分，数值接入前核对来源与语义。

允许你自主选择：
- 实施顺序、代码组织与局部适配方式；
- 在既定预算与动作空间内，先检查哪个真实缺口；
- 如何使用观察/材料诊断、怎样组织研究与审查；
- 如何把反复有效的研发做法沉淀为本线 Skill。

每项实验仍要在开始前写清本轮问题、改动、对照、成本、评价与停止条件。
完全没有行为差异的重复实现，不自动值得再跑同一昂贵实验；若复用已有证据，明确对应的是原实现，不能当作新代码的运行验收。

## 6. 哪些情况要停下来讨论

需要停的是依赖该决定的部分；其余独立工作继续。
先完成足以供用户判断的分析，不用一句“需要详细设计”把问题丢回来。

以下需要用户裁定：
- 改研究问题、评价单位、训练几何或核心 Fast/Slow 分工；
- 改 Consumer、主指标、评价人口权重、标签权限、交付控制或正式证据门；
- 引入新数据源、开放密封数据、扩大既定动作范围或预算；
- 两种设计会检验不同主张，现有证据不能替用户选路线；
- 重复结果显示当前核心假设不成立，需要换研究方向而非修实现；
- 需要修改主目录/他线、共享配置或新增付费资源。

提问必须包含：
1. 已完成的可复核事实；
2. 真正需要决定的一件事；
3. 两个具体可行选项及对科学问题/成本的影响；
4. 推荐项及理由；
5. 等待期间仍能继续的工作。

普通字段名、文件组织、一次格式错误、不强制修改的 KEEP、收益不显著，都不是重新申请整条路线的理由。

## 7. 研究对象与反馈纪律

- 一个候选的所有原始/派生训练对共同拟合一个 Consumer。不能跨模型逐实体拼分。
- 整体训练价值是完整方案间的配对差；局部损失用于诊断，不是对应实体材料的独立因果价值。
- 使用整批合法观察，可以分组或设置例外；允许统一方案与 identity，不强求多样性。
- Consumer、训练目标/步数、scaler、权重、配对随机性及主评分遵守当包冻结规格。
- Fast 在当前 held-in Job 内消费合法 C_A 并 commit；C_B 只在本批所有分支冻结后作延迟证据，不能重选当前交付；E 在规定输出冻结后外部评分。
- 同一 Job 的知识冻结；Slow 在边界修改一个主要行为面或 KEEP。Specific 的加载条件与材料内部作用条件分开。
- const true 表示明确无条件；null/缺条件是不完整，不静默扩大范围。未匹配不会剥夺公共动作。
- 原始跨作业 Episode 不直入 Fast；匹配、卡片生成、材料改变、效用改善分别记。
- 配对重复报告均值、离散度、时间块与实体贡献。不能把小样本“2σ”写成普遍可靠门，也不能用多数投票替换冻结主目标。
- 所有开发曝光状态如实保留。看过的 E 不再称未见；冻结一轮后不能拿它回改该轮规则和结论。
- 正式比较的 F/A3/A5 定义保持：F冻结H0但可任务内搜索；A3从H0进行Target适应；A5从Source知识起步并享有相同Target适应权。

## 9. 对抗性审查怎样真正使用

每个重要里程碑进行一次针对性审查；发现实质问题就修复并复核相关差集，不反复审查已经关闭的同一问题。
审查至少问：
- 实际改了什么，Agent 是否真的能影响这个操作？
- 结果是否只是复制、额外训练、选择幸运seed或弱基线？
- 反馈是否真的来自完整共同训练？
- 有无Source直入Fast、C_B/E提前可见、跨分支泄漏？
- 当前结论最强的替代解释是什么，已有工件能否区分？
- 成本、失败和不确定性是否被如实记入？

若用户直接启动你为G线root、且客户端允许，可派一层有边界的只读子Agent审查；子Agent不得再委派，总成本计入首轮。
若你实际上经上级代理的 grok-delegate / --no-subagents 启动，则遵守该限制，不绕路创建其他Agent。可做单人第二遍对抗审查，但明确不是独立复核；缺少独立审查者不阻止其他工作。
不要用“审查通过”代替实际实验收益。
