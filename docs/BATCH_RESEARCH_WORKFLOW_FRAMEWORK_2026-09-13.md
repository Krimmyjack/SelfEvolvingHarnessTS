# 批级自主研究 Workflow 框架

更新：2026-09-14（阶段状态与后续方法优先级；原架构不变）
状态：M1批级闭环已完成；当前优先设计并验证固定Harness下Fast的实际训练收益，再研究Slow改进它。Fast相对简单搜索的持续净收益、历史积累优势仍未成立；最新用户确认及Fast设计见§17。
权威关系：项目 AGENTS.md §5.9 → 本规格 → 当包任务书。历史实验按各自原协议解释。

## 1. 目标与推进原则

用户确认的变化：
1. Fast 面向完整训练批次形成处理策略，不再从第一条序列广播，也不再独立生成完每条配方才汇总。
2. 策略覆盖观察、假设、材料构造、实验和交付，是可执行的 Workflow。
3. 先完成贯通的研究闭环，再改善 Fast 效果，随后检验跨任务 Skill 积累。

“做完”指真实输入、真实工具、真实共同训练、可消费反馈、明确交付、Slow 提案和下一批重执行均有实现；不以文档数或测试数替代。框架完成、Fast 有用、历史积累有用分别验收。某个局部对照尚不可辨，不再阻止最小框架建设；也不因此将未知效用写成正结果。

拟检验的主张：在固定 Task、Consumer 训练程序和有限反馈预算下，Agent 根据整批训练上下文生成并执行数据构造 Workflow，将作业经验整合为可匹配的 General / Specific Skill，改善后续作业的效果或研究成本。该表述是研究目标，不是新颖性或效果已成立的声明。

## 2. 单位与学习对象

| 对象 | 定义 |
|---|---|
| Job | 同一合法训练截止下，一组序列共同提供训练材料、训练一个共享 Consumer 的作业；不是 SGD minibatch |
| Research Workflow | Fast 在当前 Job 中执行的观察、构造、比较、停止及交付过程，可含分支和循环 |
| Material Plan | 一次具体候选的全批构造规则与实例化赋值；必须完整覆盖训练人口 |
| Material | 原始父训练对与派生对、权重、donor 等实际数组；一份材料在每个 seed 下共同拟合一个模型 |
| Episode | 一个 Job 的执行事实、工具观察、完整候选、反馈、交付与成本，不是独立实体的成败标签 |
| Skill | 从合法历史提炼的调查/构造/决策经验及适用条件；在新 Job 中重新实例化 |
| Target 适应段 | 若干先后发生的 held-in Job；A3/A5 可在 Job 边界更新知识 |
| 部署段 | 知识冻结后，Fast 在合法 Context 上重新执行；没有当前评价真值反馈 |

批级责任不要求统一处理。Workflow 可以按当前观察分组、使用默认构造及例外，也可以合法地给全部实体同一配方。差异化数量不是成功指标。当前 Plan 可含实体/父窗口 ID，可复用 Skill 不得用特定 ID 或数据集名称代替适用条件。

## 3. 输入输出与整体链

输入 J = (D_T, TaskSpec, ConsumerSpec, FeedbackAccess, Budget)，外加当前冻结知识 H。
ConsumerSpec 包括模型架构、训练目标、优化器、归一化、更新次数及样本权重语义，不能只用模型名称。
FeedbackAccess 明确可用的标签区间和反馈阶段，不能由 Fast 自开数据源补充。
输出包括实例化 Workflow、最终 Material Plan、已执行的模型引用、过程记录和成本。

~~~mermaid
flowchart TD
    J["整批数据 / Task / Consumer / 预算"] --> F["Fast 当前作业研究"]
    H["冻结 General / Specific"] --> F
    F --> W["执行观察与材料构造"]
    W --> D["候选完整训练材料"]
    D --> C["固定 Consumer 共同训练"]
    C --> A["C_A 整体反馈"]
    A --> F
    F --> O["commit 并冻结当前交付"]
    O --> B["C_B 延迟检查"]
    B --> S["批次边界 Slow 提案"]
    S --> K["候选 Skill / 后续重执行验证"]
    K --> N["下一 Job"]
    O --> E["外部 E 评价"]
~~~

Fast 是当前任务执行角色，不等于一次短调用。Fast 内允许有限循环和临时反思；同一 Job 中 H 不变。Slow 改变的是以后 Job 的求解指导，不能改写当前已交付结果。

## 4. Fast 的操作接口

以下是逻辑接口，优先包裹既有实现，不要求为每项新建子系统。

| 操作 | 输入与返回 | 权限 |
|---|---|---|
| overview | 全人口简明特征表、时间覆盖、训练材料数量、Consumer 说明 | T-only |
| inspect_data | 指定实体组、历史窗口、统计/片段视图；返回数值及来源 | T-only |
| inspect_material | 已构造候选的父/子对变化、donor 距离、权重和覆盖 | T-only；代理量不冒充效用 |
| build_material | 完整构造说明；返回 Material Plan、数组引用和机械检查 | 不读取 C/E |
| evaluate | 冻结完整材料与固定配对 seed；返回真实共享拟合及 C_A 分数 | held-in 才可用 |
| compare | 已完成的完整候选间的配对差、块/实体分解及成本 | 仅已获准反馈 |
| commit | 已完整拟合的 plan_id、简短选择理由和停止原因 | 冻结交付；Runtime 不重选 |

第一版以结构化 tool-call loop 实现。研究骨架提供工具和预算，不预写“发现周期就用某动作”的答案，不强制每次走完五种操作。观察顺序、补查对象、候选参数和下一项比较由 Fast 决定。

### 4.1 整批观察

启动时提供所有实体的紧凑观察表与分布概览，不能只看第一条或只提供均值。更多原始片段通过按需读取获得。读数记录真实窗口、实体集合和工具参数，不能以模型自报 observation_fields_used 替代工具调用证据。

首版复用既有周期、趋势、头尾水平/波动和父窗口描述。材料检查从已有 donor/父子对诊断中选少量廉价量；不为建框架先建设全量近邻库、聚类平台或新的估值器。

### 4.2 材料构造

原语来自现有增强实现，具体范围在任务书冻结。支持全批默认、按可见条件的组内覆盖、算子参数、同实体 donor 规则和有限组合。构造输出必须先机械展开为全人口赋值，再真实生成数组。

全部父对/派生对汇入一次共同拟合；不能拼接多个统一模型的逐实体预测。派生材料不得重新拟合 scaler。训练材料相同的候选允许精确复用，记录真实别名；不强制制造材料 diff 或非 identity。

### 4.3 决策及 C_B 的新位置

C_A 支持当前 Job 的实验与 commit。commit 后才开放 C_B，作为当前决定的延迟检查及下一次 Slow 的证据，不再用 C_B argmin 替换 Fast 交付。此变化是新协议版本，历史 H3/a94 的分数及选择逻辑不改写。

完整候选的三个 seed 是反馈重复，不是模型集成。交付模型采用事先锁定的 seed；Agent 只选材料方案，不选幸运 seed。无法取得有效 commit 时区分故障、耗尽与主动保留；服务兜底若发生，另报，不伪装成 Agent 决策。

## 5. 反馈对象与效果目标

主目标保持完整工作负载的 normalized MSE 宏均值。所有实体和全部固定 origin 保留；不要求每个实体都改善，不按多数投票替换目标。逐实体向量只用于解释贡献与已声明风险，不是对应训练材料的独立因果价值。

每个比较保留：
- 两份完整方案、共同训练背景、材料与 seed 是否真正配对；
- 每 seed 每合法块的损失及差值，均值、SD、SE，n<2 时 SE=null；
- 逐 origin/实体贡献，正贡献和负贡献分别汇总；
- 材料变化、实际工具使用及成本；
- 当前证据范围：训练随机性、时间冲突、单批观察或后续重遇。

相同 seed 要对齐初始化与父 batch；增强随机流单独固定。三次重复只提供有限分辨率，不承诺“噪声已经消失”。第一版不新增通用 2σ 晋升门，也不将历史 ε、MATERIAL 或相对容差跨指标照抄。

Fast 可以在预算内保留 incumbent、提出下一候选或停止。观察和负结果可以记录，含糊差异不能自动扩成长期禁令。拟合后的 C_A 反馈只能影响后续提案，不能回改已经评估过的材料及记录。

## 6. Skill、匹配与 Slow

### 6.1 General 与 Specific

General 描述公共研究习惯、工具和证据使用方式；Specific 描述某类数据/任务条件下可复用的调查或构造方法。两者均可以包含直接处理原则，不强制所有知识都写成“先调查”。

Skill 的最小内容：
- context：Task / Consumer / 几何及可观察条件；
- intent：要解决的问题；
- procedure：观察、构造、实验或决策指导；
- evidence：由运行事实提供的引用、效用与成本；
- limitations：未检验事项、反例及适用范围；
- validation_state：观察、候选试用、经后续检验等实际状态。

证据数值由执行器汇总，Slow 不能修改原始反馈。MATCH 表示条件满足，不表示效用已证明。

### 6.2 匹配的两步形式

先依据任务约束和批次概览取得候选 Skill，再按其 requirements 补查当前 T 的观察。批级 applicability 决定是否参考；Skill 内部的作用条件决定材料如何处理，两者分开。
条件判定沿用 MATCH / NO_MATCH / UNKNOWN。主动无条件使用显式 const true，null/缺字段不冒充主动无条件。UNKNOWN 时可取得所缺的合法观察；无法补全则不加载该 Specific 的行动指导；Fast 仍按公共工具与权限继续，不能因未匹配而缩小原有合法动作集。

### 6.3 四个可编辑面

| 面 | Slow 可修改 | 底层仍固定 |
|---|---|---|
| observation_guidance | 查什么、窗口/分组、补查顺序 | 工具计算语义、标签权限 |
| construction_guidance | 材料组织、donor/参数选择原则、条件分支 | 当包算子实现与参数范围 |
| experiment_guidance | 对照假设、候选与确认的组织 | 总预算、Consumer 训练定义 |
| decision_guidance | 冲突、不确定性、停止及 commit 指导 | 指标、E 墙、已冻结交付 |

每个自然更新聚焦一个主要行为机制。Slow 可以 KEEP，不能为了完成流程强造修改。原始跨作业 Episode 仅 Slow/Runtime 可见；Fast 只读取冻结 Skill、当前作业工具结果和已合法取得的当前反馈。

### 6.4 候选与晋升

一次合法反馈即可写观察，不能自动授予通用执行权。新 Skill 可在隔离开发分支中试用，其负结果同样保留；生产晋升/Shared Capability 仍需要不同于形成材料的后续验证。
M1 允许候选分支跑通，不要求先证明所有条件化效应；不得把该试用标为正式能力通过。
Source 和 Target 是时间上的证据角色：今天作业结束后的合法经验，可以在下一次形成知识；本轮 E 只能在本轮完全收口后，按下一代的显式权限使用。

## 7. 归因与后续复用

记录链条：Skill 暴露 → 实际工具变化 → Material Plan 变化 → 数组变化 → 完整模型效用/成本变化。
这允许定位“卡没送到”“有观察无决策变化”“材料没变”“完整方案有变化但效用不确定”等不同情况。不要用命中数、字段自报、卡片长度或算子多样性代替收益。

新旧 H 比较必须在同一新 Job 上重新运行 Fast，使用相同资源向量，允许两条实际探索路径不同。若要单独研究更新器，则固定输入证据另做比较，不将两种设计混用。单次模型采样仍与更新影响交织，M1 只作开发描述。

## 8. 冻结部署与 A3/A5

目标适应段至少包含两个先后 Job，才能观察边界更新的后续效果：
- F：H0 冻结，但允许当前 Job 内的同预算搜索。
- A3：H0 起步，在 Target held-in Job 边界更新。
- A5：Source-derived H 起步，享有与 A3 相同 Target 工具、标签和预算。
- Static / Fixed-Mixup：固定构造基线。

适应结束冻结 H。后续部署 Job 的 Fast 可以读取合法训练历史、观察、构造和训练；evaluate/compare 不得取得当前评价真值。它依据冻结知识和当前可见材料交付。最后统一开放 E，只作外部评分。

当前作业 C_A 上搜到好材料、下一次无反馈执行仍有效、A5 同预算优于 A3，是三种不同主张。不能以一个 Job 或同一模型增加几个预测窗口替代后两者。

## 9. 首版工程落点

使用一个逻辑入口 run_job(job, knowledge, budget, mode)，同一 Fast/工具执行器供 F、A3、A5 使用。
建议落点：
- methods/ttha/：批级 Fast loop、Workflow/Skill 解释与匹配；
- evaluation/main_protocol_p4/：批级数据/Consumer adapter、阶段权限和开发 runner；
- 当包 _scratch/：模型、材料索引、原始回复、过程记录和一份报告。

复用已验证的父对构造、scaler、增强、MLP、评分与预算机制。必要数值原语从旧 scratch 提取到正常模块；不长期依赖含可变 config 全局量的另一个已收口 runner，不修改旧包。路径是实施建议，不以文件数验收，不建第二套通用 Agent 平台。

## 11. 与相关方法的关系

- [CastFlow §IV-C](https://arxiv.org/html/2604.27840v1)：经验进入工具规划与执行。借鉴其明确作用位置，不照搬其预测器训练和评价权限。
- [Self-Harness §3](https://arxiv.org/html/2606.09498v1)：从重复失败定位有限编辑并重执行。借鉴局部行为修改，不将终端任务结果外推成增强效果。
- [AutoTTS §3](https://arxiv.org/html/2605.08083v1)：过程轨迹用于改进计算决策。其领域是 LLM 推理，缓存环境不能替代本项目真实共享重训。
- [MemCast §3](https://arxiv.org/html/2602.03164v2)：经验分层和情境检索值得参考；在线真值到达后的置信更新不能直接接入当前 E。

拟贡献在批级数据构造研究与经验复用的完整机制；上述拼接本身不证明创新。第一版目的是建立可开展此项研究的真实系统。

## 12. 当前证据边界

依据已有 donor probe 与 material evidence 报告，材料确有变化，所测 Pattern/donor 配置没有稳定的额外训练价值；冻结模型的残差平均描述尚不是重训机制证明。它们保留为输入和诊断，不作为“Skill 必然无用”或“改权重一定有效”的裁定。
批级重构改变决策组织，不能把其前后差全部算成知识学习。当前未宣称 Fast 净收益、A5 积累优势或新颖性完成。


## 13. 使用反馈修订后的阶段判断（2026-09-14）

本节为根 Agent 的结果整合和下一步建议，不修改已完成实验的协议、数字或判词，也不授权新运行。
证据：[修订包报告](../_scratch/dev_batch_research_skill_revision/REPORT.md)、同目录 result.json / slow_result.json、两组各臂 commit.json / e_scores.json / trace.jsonl。

### 13.1 已经回答了什么

- 72 次计划拟合完成；一次真实 Slow 修订后，新卡在两个预定批次加载。其正文纠正历史描述、取消强制两槽菜单、要求针对正确比较对象解释不确定性；Fast 随之改变构造顺序和比较组织。
- 新旧卡在两组均构造相同的 U-TimeMixup 0.25 与 FreqMask 0.1，最后分别交付 Fixed 和 None。逐 seed 的 C_A/C_B/E 交付差均为零；与固定 Menu 和 F0 也相同。根 Agent 从 commit 与逐 origin/实体 E 损失重算了交付宏值，未新增拟合。
- 新卡 Fast token 为 233,511，旧卡为 148,835；修订另花 100,354 token。实际交付质量相同、成本增加；本包没有净效用增量。两卡维持 CANDIDATE_TEST_ONLY。
- g0 的增强相对 None 的收益由固定材料同样取得，不归修订；g1 的微小候选差也不支持新的条件化规律。两个批次同一日历，不是两次独立时间验证。

“修订完全没有被检验”不准确：自然批次上的端到端效用与候选槽使用已经被检验，未观察到增量或节省。尚未充分检验的是更窄的条件性主张——在新增强方案以小幅、seed 符号混合的 C_A 优势胜过公共参照时，新卡是否改善选择。纠正历史叙述是事实一致性进展，不能预先判定该决策策略方向正确。

“在位方案”还须固定含义：代码的历史 incumbent 是 FixedMixup；g1 的 None 是看过 C_A 后两个公共基线中的 winner。若参照固定 Fixed，g1 的 None 已是小幅、seed 符号混合的替换，新旧卡仍作相同选择。因此不能笼统说没有任何小差冲突；上述尚未充分检验的主张只限定于新增强候选相对最佳预拟合基线的情形。

### 17.2 拟议H0：由真实反馈支持的配对材料修订

待检验的机制：Fast在一份已经真实评估的完整方案上作一个有明确比较对象的局部程序修订，从整体配对反馈判断该修订是否有价值，再选择继续、换方向或交付。它仍负责观察、构造、选择和停止；执行器负责把比较对象及未改部分保留准确。

|环节|Fast做什么|执行器提供什么|

|追加选择|在剩余预算内进一步修订，或另造一个不同方向的完整方案|同一工具和训练接口；允许离开初始候选邻域|
|交付|从自己已完整评估的候选与公共基线中commit|冻结计划及指定seed模型；之后C_B/E按原阶段统一打开|

这里的“配对修订”是新机制中心。首轮只考虑改变父policy某一既有数值强度叶子（TimeMixup的w或频域算子的mu），使用现役合法取值；其余policy、人口、训练段、scaler、权重和训练配置固定。一个规则参数可影响多实体，仍是整套材料的干预，不是实体级因果标签。父方案可以是当前已评估的新方案或公共Fixed；identity没有可改强度时可选择别的合法父方案或停止，不强制制造非identity。

拟议资源形状：最多3份新材料，每份仍用同一组3个配对训练seed。第一份自由构造；若继续，第二份用于上述受控修订；第三份可再修订或自由换方向，均可提前停止。它是待比较的新Harness协议，不冒充当前已实现行为，也不把新臂3槽与旧臂2槽直接比较。最终槽数、Job、调用/拟合/墙钟上限在执行任务书统一冻结。

实现优先在现役build_material/薄Adapter中增加父policy派生能力，输出最终仍为现役完整policy与assignment；不新增第二套DSL或搜索平台。原工具对其他study保持兼容。材料诊断与parent-child compare复用已有数值，不生成质量预测、阈值或隐藏评分。

Fast简短说明“依据哪项当前观察、改哪个参数、与谁比较、什么结果将削弱这项假设”即可；无需长篇研究报告或公开内部推理。它不得在看到反馈后回改当次假设，事后解释也不代替真实效用。

### 17.3 与已经试过的机制有什么不同

ROUNDTRIP只保证先回传工具结果再继续，已有两次原样继续第二评估的记录。本设计要求可辨的父方案与数值修订关系，使后续反馈回答一个具体的材料改动问题；不把串行调用本身记作新增贡献。需要反馈往返时复用旧机制，比较臂采用相同证据可见时序，避免将等待反馈和修订结构混为一项优势。

EXPLORATION-QUOTA要求评估一个随机Q；这里不指定必须尝试的候选、强度方向或统一/条件化形式。探索方向由Fast决定，父方案可以保留；局部修订不成功时有离开原方向的机会。研究者不从旧E指定新作业应交付D1，也不把旧赢家伪装成Source Skill。

改动会限制第二个新评估的结构，因此要公开记录这一权限差异。若收益只由普通局部搜索解释，不宣称LLM推理或数据理解已经产生增量。

### 17.4 首轮开发的比较与分层验收

第一轮固定H0、0Slow，不加载未晋升Source卡。保留：新配对修订Fast、同预算自由构造Fast、简单随机搜索、None/Fixed及固定菜单；对局部修订的Agent增量作归因时，还需要按同样参数邻域产生修订的简单局部搜索参照。各搜索臂使用相同T/C_A权限、Consumer、配对seed和物理评估预算；固定方法实际成本另列，不人为花满。优先复用现有训练器/反馈/恢复路径，当前不新建实现。

结果分三层报告：
1. **处理有用**：Fast实际构造并commit的材料在冻结后的外部评价优于不增强；报告后续批次的延续、失败与成本。若只是交付公共Fixed，收益归固定处理。
2. **Fast研究有增量**：相对强固定处理、同预算自由构造及简单搜索有质量改善，或同等质量下节省完整成本。局部修订产生不同材料而无收益不算通过。
3. **进化有增量**：后续Slow修订的Harness相对同一固定H0改善新的作业；该层本轮不测。处理有用可以作为继续开发的台阶，不能自动改写M2/M3判词。

首轮只需形成能继续研究的Fast结果及具体失效点，不要求同时证明跨来源泛化和全部历史积累贡献。Job/人口按预定顺序选，不按已知收益筛；新结果打开前冻结协议。官方主指标及难例保留，材料检查不是采用门，失败不伪装成基线交付。

### 17.5 Fast成立以后，Slow具体改什么
