## 1. 我们要解决什么

目标不是“多存几张好程序卡”，而是：每条序列在当前合法窗口由 Fast 自己观察、生成和
选择处理；批次结束后，Slow 从合法成败反馈修订共享知识，使下一批的处理更好。
共享 Agent、工具和冻结知识，不广播同一个程序。原始跨轨迹 Episode 不进入 Fast。

DEV-SEQ-1 验证的是逐序列执行程序与评价读数一致，不是 LLM 原选择总能决定交付。
窗口特征绑定和验证去重已在 DEV-SEQ-2 修复；旧 L2 覆盖过半、L3 重测旧程序已降为
诊断，改以真实新旧 Fast 比较。DEV-SEQ-4 同起点对照确认一处局部选择改变，但交付
没有改变；随后 Slow 修订已形成，后续效用对照尚不完整。最新状态与界限见 §13。
历史 cohort 广播实验与逐序列实验不并表；它们暴露的问题可作设计线索，不能直接外推。

## 2. 原实现与本次取舍

| 环节 | 近期 DEV-SEQ 实现 | 讨论后的方向 |
| --- | --- | --- |
| 分组 | 同程序步骤与失败方向归组，倾向用一条条件解释大组 | 轻量组织材料，保留成功对照；允许不同原因和子群 |
| 归因 | 规则限定错误类别，入口固定为 Skill 缺口 | 代码给事实，LLM 给可错的机制假说；类别不是修改否决权 |
| 修改 | 只允许 ADD 指导 Skill | 情境化 Skill，或 Fast 观察/提议/选择指导；每个候选只改一处 |
| 验证 | 条件覆盖多少失败、旧程序是否继续失败 | 新旧 Fast 的真实行为、后续效用、风险、覆盖与成本 |

保留的五类标签是：任务理解、数据现象判断、候选能力、候选选择、适用/记忆/风险。
它们是故障组织方式，不是已证明的物理原因。Support 正、delayed 负只证明效果没有
延续，不能直接证明“缺失导致伤害”或“Scope 太宽”。

Slow 一次说明四件事即可：观察到什么事实；怀疑什么行为问题；改哪里；预期行为与
效果怎么变、什么结果会反驳建议。不要求每次先做完整因果实验，也不要求解释唯一正确。

## 3. 修改对象与条件化

- 情境化 Skill：新增指导，或修改已有指导的正文/适用条件；例如某种缺口与局部异常
  共存时，先观察什么、比较什么。具体算子建议仍由当前序列的 Fast 检验和选择。
- 通用决策指导：修改已有观察流程、候选提议或选择指导。例如新候选失败后，不应
  无理由遗忘仍合法的旧候选。此例是机制示意，不是给运行模型的手工答案。
- 不开放模型修改裁判、风险阈值、Consumer、算子实现、任意运行时代码或执行权限。
  使用现有分支/编译机制保留父版本；保留知识不等于永久保留部署权。

硬前置条件（任务、合法数据、作用区间）必须准确。效果假说可以是需要当前观察/探测
确认的软指导，不必先用一个数值条件完美分开所有成败。因此条件化既可以是
“Pattern → 候选处理”，也可以是“Pattern → 观察/比较程序 → 当前处理决定”。
“覆盖全部对象”不自动无效；“只覆盖一个子群”也不自动可泛化。

## 4. 为什么值得试，不能保证什么

它解除的是修改空间与问题错配、以及用条件覆盖代替效果验证的阻断。真正待检验的是：
可见反馈是否含可复用信息，Slow 是否把它写成有用的指导，Fast 是否使用并受益。
程序能运行、解释合理、候选更多、卡被读到，都不等于后续效用提高。

逐序列执行后仍存在 Support 到 delayed 翻负。继续寻找 Support 高分候选可能放大
选择偏差，不能把困难都归结为弃权或弱模型。没有单特征完美分隔，也不证明所有条件
都不可学；修正窗口绑定同样不保证发现规律。当前 Consumer 仍是既有按 Program 拟合的
prepared/raw 管线，不是“逐条异质准备后只训练一个共享模型”。本轮不改这个几何。

本地 Self-Harness 的可借鉴部分是失败挖掘、模型选择有限修改位置、实际回归测试：
`../Self-Harness/diagnosis/src/self_harness_diagnosis/trace.py`、
`../Self-Harness/proposer/src/self_harness_proposer/multi_proposer.py`、
`../Self-Harness/acceptance/scripts/run_acceptance_gate.py`（相对仓库根）。
[论文](https://arxiv.org/abs/2606.09498)支持这条基本循环；它不保证本项目的时序泛化，
也不能把其测试集用法照搬到本项目最终密封面。“失败后反思”本身不是独有贡献。

## 5. 留给后续讨论的问题

| 问题 | 当前边界/判断方式 |
| --- | --- |
| 当前 Pattern 是否有可利用的信息？ | Fable 条件化线并行检验；不以完美分隔、同 UID 跨窗反号作总否定 |
| 逐序列反馈密集，是否就足够学习？ | 行数不等于独立证据；同序列多窗口、共享模型和重复预测均可能相关，反馈还须及时且绑定正确 |
| 应学固定程序，还是观察与适应方法？ | 优先检验后者能否改变逐序列决策；不是预先宣布后者更好 |
| 分组过粗或过细怎么办？ | 保留窗口、参数和成功对照；允许子群，不靠强迫覆盖多数制造一般性 |
| 归因如何可信？ | 事实与假说分开；修改的实际结果可证伪假说，但有效修改也未必证明全部因果解释 |
| 现有编辑/工具足够吗？ | 有差异却无对应可执行动作时再扩能力；不先上全套新特征/新算子 |
| 读到指导为何没用，或反而变差？ | 区分加载、观察、提议、选择、交付；检查旧候选被挤掉和过度弃权 |
| 收益下降、伤害下降如何取舍？ | 同人群报告两者及覆盖；比较当时实际可执行策略，不把少处理自动算智能 |
| 如何区分学习与更多搜索？ | 先冻结/更新两臂；有增量后再加同信息同权限的普通反思与同预算搜索 |
| 能否迁移、证据会否过期？ | 新窗口、实体、Task/Consumer 分别检验；当前两组重复不算独立跨域复现 |
| 条件化是否依赖训练/服务几何？ | 固定并披露现有 K+1 管线；不能混入另一种 Consumer 训练方式解释收益 |

## 6. 推进与停留标准

先完成证据修复，再跑最小新旧 Fast 对照；普通反思、分组消融和更大迁移留到确有
值得拆解的增量后。两臂比较只归因于整套更新流程，不给单个组件抢功。
Fable 的研究者分析不能回填为 Slow 当时自己知道的答案。

若只能写出更漂亮的解释而无行为/效果增量，继续增加卡片不是解法；若行为改变但
后续无益，应调整学习假设；若更新有益，再检验普通反思是否已经足够，以及后续复用。
不因一张卡失败放弃完整项目，也不靠反复改 Gate 把失败包装成进展。

## 7. 把最小学习循环具体化

### 7.1 事实层：记录一次决定，而不是给序列贴永久标签

一次学习材料应能回答：对哪条序列、哪个当前窗口、哪个 Task/Consumer，Fast 看到了
什么，试了哪些完整程序，选了什么，当时和后续分别怎样。身份用于追溯，状态用于
条件化；“T15 曾经失败”不能直接编译成“T15 永远不适合某算子”。

需要区分三类信息：

- 决策前可见：当前历史、公开特征、可用工具、Task/Consumer 语义；可以参与当次选策。
- 决策中获得：合法观察、程序试执行和当前 held-in Support 探测；成本和获得顺序保留。
- 决策后到达：delayed 结果及其对应窗口；可以解释旧决定，并成为以后 Slow 的历史，
  不能冒充旧决定当时就知道的信息。

密集逐序列反馈是一项资产，但标签多不等于独立证据多。同一缓存重复、同一实体多窗、
同一拟合模型服务多条序列，都需要保留依赖关系。未部署程序的 delayed 若未实测就是
UNKNOWN；不能拿部署者的 delayed 代替，也不能把缺测当成功或失败。

信息充分不等于把所有原始数据点塞进提示。优先保留成败对照、关键动作与可追溯摘要；
若压缩，不能再系统性丢掉成功侧或后续失败侧。汇总属于 Slow 输入，不给 Fast 开生案例旁路。

### 7.2 分组层：先找值得一起比较的案例，再谈是否共同原因

初始分组仍可按 Task/Consumer、程序结构和失败表现完成，不先引入聚类模型。完整参数、
作用几何与窗口状态不能丢；相同算子名字不保证实际动作相同，不同名字也可能是行为别名。

给 Slow 一个“反例 + 相近成功例 + 尚不清楚的差异”的对照包。成功例的作用是指出应
保留的价值，而不是装饰报告。相近案例可以帮助提出假说，但匹配不自动消除所有混杂。
允许模型解释一个子群或拆分原因；不要求一张指导包揽大组，也不把每个孤例都升格为 Skill。

例：一组离群处理失败中，部分可能涉及持续水平变化，部分可能是插补改变了后续检测，
另一些暂时看不出区别。正确输出可以是只对第一部分提出可检验指导，其他保留不确定。
一般性最终看后续复用，而不是看训练组覆盖人数。

### 7.3 归因层：诊断是选择试验的工具，不是正确性证书

五类旧标签用于索引、统计和提示检查方向；它们不应把“后续翻负”机械等同于“必须
收窄”，也不应把候选选择问题强行写成新的数据条件卡。LLM 可以提出复合或暂未分类
的解释，但可执行修改仍受明确白名单约束。

建议沿用现有字段表达四件事，不另造归因平台：

1. 事实：引用哪些合法正反例/动作读数，不补造缺失的事实。
2. 假说：哪个可修改的判断或行为可能导致问题，哪些原因尚不能排除。
3. 修改：一个具体 surface 和局部差分，尽量保留已有成功行为。
4. 预测：下一次应改变什么可观察行为、希望改善什么结果、什么读数会反驳建议。

模型说“我很确定”不增加证据权重。一个修改有效，也只直接支持该修改的价值，不一定
证明解释中的每条因果链。相反，解释不够完美不应阻止一个合法、可检验的候选被测试。
没有必要让每次 Slow 额外调用一次独立分类模型；解释与提案可以在同一调用中完成。

### 7.4 修改层：保持明确的对象和最小差分

| 面临的可检验问题 | 倾向尝试的修改对象 | 应检查的实际变化 |
| --- | --- | --- |
| 旧指导没有区分两种局部结构 | 情境 Skill 的 OBSERVE/TRY 或适用条件 | 是否先取得相关观察，再为当前序列形成不同候选 |
| 程序候选缺少某类合法组合 | 候选提议指导 | 该组合是否由 Fast 自己生成、执行，是否有后续价值 |
| 新知识挤掉仍合法的旧候选 | 选择指导 | 新候选失败后是否仍考虑可用旧方案，是否减少无效回退 |
| 同一指导在不同 Consumer 下含义不同 | 条件化指导中的 Consumer 语义 | 相同数据模式下，是否形成符合当前任务目标的处理 |

这不是运行时的“故障标签 → 唯一算子”路由表，只是研发时选机制的例子，不能把已知
案例赢家直接作为 Slow 的答案。今晚实际开放面以任务书白名单为准。

指导应影响“如何生成答案”，不能利用隐藏 marker 绕过 Fast 直接广播答案。允许建议
公开处理顺序，但要由当前序列的 Fast 决定是否尝试。父版本留在已有分支系统内；知识
保存、检索资格和部署资格是不同事情。一次失败不应抹掉仍有价值的父版本，也不能
因为父版本还存着就无条件重新获得执行权。

### 7.5 验证层：不仅检查写入，还要检查清空对话后的重新使用

候选编译成功后，在新 Fast 会话中只通过正式指导入口传递修改。检查它是否实际加载，
是否改变观察、候选、探测、选择，最后是否改善交付。不能把 Slow 的完整分析对话带进
下一会话，然后把收益归给一张实际上没有被使用的 Skill。

验证阶段可以决定是否采用；后续阶段用于检查效果是否延续。未采用候选仍可在已授权
隔离 development 分支测试，但要单列，不能把它算作自然晋升后收益。被测分支失败不
修改实际父版本，验证结果也不能让 LLM 自行更改裁判。

## 8. 值得保留并逐步检验的三个想法

这些是后续可选研究方向，不是今晚必须同时实现的模块。

### H1：可迁移的可能是“如何修改”，不只是“哪个程序好”

在相同情境 e、相同计分人群和干预几何下，记程序收益为
`g_e(P) = L_e(raw) - L_e(P)`，局部修改的增量为
`d_e(P → P') = g_e(P') - g_e(P) = L_e(P) - L_e(P')`。

即使 P 的绝对收益跨窗变化，某类局部修改的相对优势仍可能更稳定；也可能完全不稳定。
这是一项假说，不是配对差分自动保证的性质。早先“同程序跨窗反号”的结果并未单独
回答它，但已测过的特定差分失败也不能忽略，需先复用对应证据而非重新包装。

可积累的知识形态可以是：“出现某种可观察冲突时，优先比较哪一种局部差分、保留哪一
部分、什么结果应放弃这项解释”。应先在少量合法差分上检查相对价值，而不是开发一个
通用修改分类器。比较仍须满足当前效用、风险与覆盖语义；d 大不代表可以不受约束部署。

### H2：面向动作的观察，可能比更多通用统计量更有用

数据摘要 `z = φ(x)` 描述“序列长什么样”；动作相关观察
`z_P = ψ(x, P, Consumer)` 描述“这个程序实际会改变什么、依赖什么”。后者可能包含：

- 修改点是否连续、是否集中在近期 context、是否与缺口及插补位置重叠；
- 周期填补实际有没有合法历史供体，而不只是周期强度高不高；
- 两个候选对当前合法数据是否根本产生相同动作；
- 若现有合法接口提供，训练准备与服务准备分别发生了什么。

这些观察只能从当前合法数据、工具和试执行获得，不能包含未来损失。试执行不等于
免费；需要新 Program 拟合或额外模型调用时计成本。不一次加几十个特征，而是针对
一个已有正反例冲突，检验一项观察能否改变选择。已有 R4C 等测试过的具体作用条件，
应先查结果，不把“动作相关”三个字当作尚无人试过的新方向。

关键的三个问题必须分开：**程序会不会实际起作用 → 起作用是否带来相对价值 → Agent
能否利用这个条件**。识别了修改位置、供体存在或动作强度，只回答第一项。

### H3：条件化知识可以迁移“适应程序”，而不必预测固定答案

当静态 Pattern 不足以直接选择处理时，知识仍可能告诉 Agent：“进入这种情境后，
先做哪个合法小比较最有信息”。它迁移的是观察与试验顺序，不要求一个跨所有域不变的
Pattern → 最优程序映射。最终仍要证明这种顺序比从头搜索更有效或更省反馈。

适用边界很重要：held-in 可以做有反馈的探测；最终 held-out 是冻结后的 Fast-only，
不能把“到了新地方再读目标答案验证一次”包装成零反馈部署。需要 Outcome 的适应
必须提前在 held-in 完成；held-out 只使用合法可见观察及冻结知识。

H1/H2/H3 可以分次检验。没有任何一项必须靠完整因果模型、世界模型、向量 Router 或
开放式代码自修改实现。若普通反思已有同等效果，选择更简单的版本。

## 9. 两个最容易继续误判的问题

### 9.1 反馈属于单条序列，不等于效应只来自处理这条序列

当前 prepared/raw 管线中，选择 Program 同时涉及准备训练数据所得的模型与服务
context。因此 per-series loss 是“这套管线对该序列的效果”，不是单独清洗其局部点的
因果效果。仅看到某序列受损，就断言它的尖峰被错误删除，会遗漏训练侧通道。

并行线的 [R4D-A 报告](R4D_A_ACTION_DECOMPOSITION_RESULT_2026-09-08.md)在其所测 pooled
设置中报告共享模型通道占较大的代数幅度份额；本次只读报告，未重算工件。这不是方差
解释率，也不证明当前服务状态无法调节模型效果。它提醒后续归因需要知道真实干预几何，
而不是证明“应该取消逐序列决策”。报告后续路线/预算的更正以状态页和该线新任务为准。

未来若研究训练侧、服务侧或 per-channel 的差异，应在独立任务里固定变化点并重新比较。
不要把另一种 Consumer 几何插进 DEV-SEQ-2，或者把异质准备后统一训练冒充现有 K+1 管线。

### 9.2 选择和验证都不能只追逐表面更好看的数字

同人群的配对效用才可比较。候选不可执行时真实走了 raw，可计其实际回退；未测量则
UNKNOWN。不能按候选自己的可读格求均值，再和父版本的完整人群均值相减。

固定 Program、固定预测、嵌套 Scope 且退出者回 raw 的旧几何下，收窄增量等于被排除
集合净收益的相反数。伤害次数下降在这种设置下可以是构造结果，不足以证明选得聪明。
这个恒等式不能直接搬到同时改变 Workflow 或重新训练几何的修订中。

当前 Support 是选择依据，选择最优后 Support 更高不是独立效应证据；需要区分后续
delayed 表现。平均收益下降、风险下降是一种取舍，不能现场改主目标给某个候选追认。
参照应由当时合法信息决定的实际可执行策略提供，不是永远 raw，也不是永久免检的父程序。

## 10. 结果出来后，如何决定下一包

### 10.1 先把 DEV-SEQ-2 跑完整

本包问题是整套更新是否有价值，先用冻结 A / 修改 B。两组同数据重复不能给出可靠
方差估计或跨域复现；若某组没有真实修改，该组不承担修改效应结论。关注反例是否
改变提案、修改是否影响 Fast、影响是否变成后续价值，而不是提案数、卡数或版本数。

| 观察到的结果 | 最有价值的下一步 | 不应该怎么做 |
| --- | --- | --- |
| 没有合法候选 | 区分合法弃权、输入缺失、编译/编辑出口问题；处理具体故障或重新界定可检验假说 | 催模型直到吐出指定卡；直接宣布自然数据不可学 |
| 修改未进入 Fast | 修复该 surface 的加载/检索接线，在同范围验证 | 添加更多卡或重跑全课程掩盖接线问题 |
| 已加载但无实质行为差异 | 检查指导是否可操作、目标条件是否实际出现、原流程是否已做同样事情 | 强制选新程序来制造 treatment |
| 行为改变，只有 Support 更好 | 结合 Fable 条件化/作用通道证据，选一个具体可见信息或试验策略检验 | 把更大 Support 搜索空间当成泛化修复 |
| 后续效用下降、伤害也下降 | 检查退出对象、覆盖和既定风险目标；判断是有意义的风险修复还是过度回退 | 临时换分母或改目标把负号变正 |
| 未采用候选在后续看起来有益 | 保留为诊断线索；如要改采用规则，另做前瞻的规则比较 | 用后续答案追认之前通过，或悄悄放宽风险线 |
| 出现后续增量 | 保留该版本并做机制对照，再检验独立情境复用 | 马上开最终密封数据或宣称完整 A5 成立 |
| 两组方向不同 | 先拆候选/形成历史/行为及有无 treatment，不估计不存在的“噪声底” | 只保留较好的一组，或无限加种子直到显著 |

一个小包未见改善通常只关闭该候选/设置的强结论，不足以永久判死某类学习机制。
但反复出现“无行为”或“只有 Support 改善”也应促使改变具体假说，而不是只扩大运行量。

### 10.2 有值得拆解的信号，再区分普通反思与成败对照

下一层可以比较：冻结知识、直接反思更新、成败对照驱动更新。后两者具有相同合法
信息、模型、编辑权限和资源，区别主要在如何使用材料，而不是一方得到详细成败、
另一方只有 REJECTED。直接反思若已同样有效，就保留它；这是方法简化，不是失败。

有必要时再选一个消融：只保留总体分数、移除成功对照，或移除动作差分。每次问清它
检验哪项机制，不展开所有组合。随意打乱 Task、程序、时间会制造错误资料，下降不能
单独证明正确经验的价值；删经验也不要求所有优势归零。

同预算确定性搜索适合可枚举部分。若它追平局部数值选择，缩小 LLM 的该项职责；
不能由此直接否定其他情境的知识复用。若质量、迁移和效率的合理对照均持续追平，
则承认当前学习机制缺少足够增量。

### 10.3 再回到跨情境积累与完整目标

检验次序可以是：一个未参与该次修订构造的开发情境，确认指导不是只记住当前窗口；
然后在独立实体/训练条件或数据集上冻结协议，做完整 Static/A3/A5。
同一批序列换窗口、换顺序与跨域泛化分开；数据集角色不预写成“必定学成/必定修对”。

为区分积累和修订，可使用“同样持有累积 Skill，但结构冻结、只允许目标本地校准”
的参照。评价同时看固定 Target 反馈预算下的效用、风险、覆盖，和达到预定质量需要的
反馈量；Source 知识形成与维护成本单列，不能当免费赠品。

Wind Farms、NOAA 等资产按原有授权与数据边界准备，不因本备忘录自动启动新下载、
适配器或密封运行。最终 held-out 的一次性评价仍独立于所有开发选择。

## 11. 什么值得成为项目的核心贡献

想争取的不是“有 Memory、有验证器、能写 Skill”，而是：旧准备知识遇到局部反例后，
系统能保留有效部分、修订失效部分，并使后续情境的程序生成或适应更有效。

证据需逐层建立：

- 响应性：反馈之后提案变了，不代表改变方向有用。
- 机制生效：修改进入新会话并改变实际行为，不代表效用提高。
- 局部价值：同人群配对后续结果改善，不代表来自某个单独组件。
- 积累价值：后续新情境受益，且不能轻易由同预算重新搜索解释。

学习对象可以是处理程序，也可以是观察/比较程序，但通用选择小修补的成功不能单独
证明 Data Pattern 条件化成立。后续仍要展示 Task/Consumer/可见数据状态如何真实改变
处理行为及价值。程序多样性不是目标，相同答案有时就是正确答案。

Self-Harness 已包含诊断、提议与回归验证，因此该循环本身不构成新颖性。当前有希望的
差异是程序性准备知识的条件化修订及其复用；是否足够独特还需与最近工作逐项对照，
本备忘录不替代完整文献评审，也不以“评价昂贵”作唯一研究空白。

## 12. 后续讨论和执行的约定

每次结果后优先回答四问：真正的 treatment 是什么；最早失效在哪一环；哪项假说被
支持或削弱；下一项最小改动是什么。只选择一个会改变决策的后续分支，形成一包任务。
这些问题不要求每一步都重新经多方审批。

继续坚持：每序列 Fast、批次边界 Slow、Skill-only 跨轨迹知识、合法反馈的时间顺序。
证据修复是基础工作，不能代替方法进展；归因分类可以轻量，允许修改的位置和真实
效果比较不能被简化掉。不自动增加 schema、哈希、存储层、聚类模型或审查角色。

此前扩写只更新此备忘录。没有修改当时已发夜间任务书、实验代码、AGENTS、Fable 文件，

## 13. 2026-09-08 合并取舍：先对齐部署对象，再检验知识修订

影子不改实际历史；冻结运行不注入 raw Episode、不回传其结果。Fast 当前预测的外部

写清，不能重命名旧包的选择面来冒充当年独立验证。

### 13.2 条件化与归因：保留问题，不提前给方向判死

- R4E 的 0.07–0.13 空间只属于固定 P/identity 二选一。扩菜单 oracle 有用，但仍只
  约束被测合法菜单；缓存缺项时不能把已测最好值写成完整上界。
- AUC 0.826536 是 pooled 设置中服务侧影响通道的结果，不是 per-channel Consumer
  的结果，也不直接证明 origin 前信息可预测 +48 的总效用。特征计算范围必须一致。
- per-channel 对照同时改变训练材料/样本构成；不能将全部差异归因于模型结构，更
  不能把研究者换 Consumer 写成 Agent 的学习收益。
- Support 已拒与 Support 正而 delayed 负需要分开给 Slow，但前者未被证明事前
  可预测，后者也未被证明不可学习。训练侧与服务侧动作事实不能互相代替效果解释。
- 既有自写获胜的 32 次按算子为 MAD 24、IQR 6、Hampel 2，只证明该执行通路存在；

### 13.3 确定性基线前移，但不把它偷换成方法

公共 DSL 菜单、合法 held-in 校准、冻结后确定性部署，是不依赖 LLM 的强参照。
使用 LLM 生成的池再排序只能叫零新增调用回放。两种对照可帮助区别程序供给、选择
和累积知识，不替代最终 A5/A3/Static，也不将项目缩为数值 Router。

效果与效率不是必然两篇论文：在既定安全/效用要求下，以更少反馈达到相同水平可以
是学习价值；但不能因效果负了才临时把效率换成唯一主终点，Source 成本必须单列。
知识保存、检索、候选供给和实际执行继续分开，不在现阶段新建完整退休/竞争系统。

### 13.4 少量数据提供尺度，不提供虚假的精确性

MATERIAL 是效应量阈值。6/51 超线不是 12% 假阳性率；同 UID、多窗、共享拟合不能
当独立样本。先报依赖和尾部，再给敏感性范围。若仅暴露子群发生变化且无外溢，
整体增量为 `p × 子群增量`：p=1/40 时，全人群 +0.005 对应子群平均 +0.20。
这解释小暴露为何难测，不证明任何窄指导都无用。效用主表不因看见差异小而换分母。

## 15. 2026-09-09：回到 Skill 核心，先修真实偏差，再检验生成与学习

### 15.1 用户确认的设计，以及没有获准改变的部分

用户本轮确认：以 General / Specific Skill 为核心；Fast 在其指导下为每条序列的当前
合法窗口生成 Workflow；Slow 根据反馈，在有限范围内修改 Skill 的正文、适用条件等。
这与 `AGENTS.md` §1、§2 及 8 月 19 日全局设计中的 `Skill != 当前任务的最终 Workflow`
一致。**恢复的是目标和职责，不是 git 回退到 8 月 28 日，也不证明当日实现没有偏差。**

```text
冻结的 General / Specific Skill + 当前序列的合法 Context
  → Fast 观察、生成 Workflow、确定性检查、提交实际处理
  → Runtime / Evaluator 取得合法到达的效果，形成对应窗口的 Episode
  → 批次边界：Slow 分析成败与仍有效的行为，提出有限 Skill 修改
  → 候选知识分支冻结；下一段 Fast 使用它重新生成 Workflow
  → 比较实际交付的效果，决定是否保留该知识版本
```

- General 是通用观察、构造、选择原则；Specific 是有证据范围的条件化指导，可含
  Workflow 模板。模板可以被复用，但不是 Runner 必须供给并保住的标准答案。
- 两类知识是语义角色，不急于新增 SkillKind、存储系统或 Schema。现有 bootstrap
  Skill、proposal/selection guidance 可以先作为 General 的实现；情境卡承载 Specific。
- Skill 的适用条件、Workflow 内部作用区间、评价人口是三个不同对象，不能都混称
  Scope。适用性提示不授予执行权，收窄检索不改变评价分母。
- Program 是编译后的处理 Workflow；当前支持线性 1–4 步，不等于任意 DAG。
  Agent 的多轮观察/构造过程与数据处理步骤也要区分。**不强制多步；单步可以是正确答案。**
- 新比较中的 Fast 不读取当格下游分数或跨轨迹原始 Episode；合法试执行/修改回执
  不等于下游效用反馈。评分与知识更新留在 Runtime / Slow，批内知识固定，可并行处理。
- 不默改 Consumer、训练材料、风险线、评分时点或密封边界。当前仍是每个 Program
  对应准备—训练—服务管线，不是所有序列异质处理后训练一个模型，也不是固定模型只修本序列。

### 15.4 当前最核心的三个研究问题

**问题一：合法观察足以决定怎样处理吗？**
General / Specific 的分层本身不会产生信息。Fast 必须看见与候选作用相关的区别，
而不是只拿“缺失多、波动大”推断完整训练—服务管线的好坏。先检查已有局部观察、
程序试执行和合法 Consumer 语义是否被真正使用；不要为了有规律而无限加统计特征。
若扩观察，明确要区分哪两个假说，且不读取当格下游效果。

**问题二：Slow 能否把反馈变成可执行的生成指导？**
过去“P 在甲成功、乙失败”只够提出问题，不自动推出“乙该用 Q”。对已有配对证据，
应展示同情境下两种完整程序的相对效果；再带上 Fast 当时读到的 Skill、关键观察与
构造记录，允许 Slow 判断是观察原则、步骤组合、局部参数/定位，还是适用性出了问题。
分组只是整理材料，五类原因只是标签；LLM 提出的因是可错假说，不是代码授予的因果结论。

更新保持简单：事实 → 怀疑的行为问题 → 修改哪段 General/Specific → 预期改变与反证。
允许具体、受证据约束的操作建议或模板，不能把“不要复制单个赢家”误用为“只能写泛泛
原则”。每次有限局部修改，必要时做一个历史上的小对照；不要求一套完整因果归因系统。
保留有效旧知识；新卡不自动胜过旧卡，也不因为一次子版本失效抹掉祖先。

**问题三：知识是否带来固定方案与额外搜索之外的增量？**
胜过旧的弱 Fast 不足以说明条件化成立。新知识可能只是找到一个更好默认，也可能只是
改变保守程度、池位或成本。必须在同一正确执行器、同模型/信息边界下比较新旧知识，
并保留同反馈校准的固定方案。结构修复收益、基础模型能力、观察工具收益与学习收益分列。

我的判断是：原目标仍值得做一次真正对应它的验证；但纠正偏差只消除无效测量，
不会保证自然数据存在足够稳定的条件化规律，也不保证比固定程序更好。

### 16.2 系统还保留着用户想要的骨架，但有三层必须区分

```text
General / Specific 知识
  → 当前序列可见信息 + 被检索到的指导
  → Fast: inspect → propose 一个或少量 Workflow → 合法试执行 → select
  → 冻结所选 Workflow 后交付（DEPLOY 路径无当格下游分数）
  → 外部评价完整准备—训练—服务管线；记录对应 UID/窗口/程序的结果
  → 批次边界 Slow: 读合法历史 → 提出一处知识修改 → 隔离分支
  → 下一段冻结 Fast 在相同入口使用新旧知识，外部比较实际效果
```

第一层是**表达能力**：Program/schema 支持 1–4 步线性 Workflow，不是单算子 enum，
也不是任意 DAG。第二层是**实际供给**：旧冻结程序卡、Agent 候选、identity 会合池，
受默认 actionability 筛选和槽位限制。第三层是**实际行为**：最近 DEPLOY 记录里的
保留/交付程序都是单步。这三件事可以同时成立，不能由第三件反推语法只支持单步。
来源：`methods/ttha/schemas/fast_propose_v1.json`；`fast_agent.py` 的
`_actionable_operators`、`_compile_candidates`、候选合池和 `select`。

也不能从“没有 public_parameter_bindings”推出“所有参数只能默认”：该字段指机械
绑定；`operators/registry.py` 为 impute_linear、denoise_median、hampel_filter 等
另有公开参数 schema，`_compile_candidates` 会接收参数。动态绑定指导、公开参数形状、
默认单步预筛选和本轮实际参数取值应分别检查。是否过度剪枝由夹具检验，不凭注释决定。

Fast 当前的公开工具主要返回全历史特征及估计区间，不能自由请求任意局部诊断。
另一 gateway 中的 `compare_history_windows` 属于 `observe` 阶段，不能仅凭工具存在
就称当前 inspect/propose/select 已能调用。增加一句“先观察局部结构”的指导，
不会自动增加这项观察能力。来源：`methods/ttha/public_tools.py:193–248,390–434`。

### 16.3 Skill 仍有结构和 Scope，但不是统一的六段式可执行规则

正式 SkillEntry 包含 id、kind、revision、body、observable_applicability、allowed_tools、
risk_guards，并保留 optional serving_scope。General / Specific 是语义角色，当前
正式 kind 为 bootstrap_procedure/capability/safety，不是 general/specific 两种 enum。
来源：`contracts/harness.py:101–123`。

- General：bootstrap 流程卡，以及 candidate_policy 中的提议/选择指导。
- Specific：按情境检索的 capability 指导；历史上还存在携带冻结程序的能力卡。
- 正文主要是自然语言；部分历史 Source 经验卡的 `risk_guards.sections` 确有六段
  内容并被读取，但最新 ADD 指导卡不要求都经过六段字段化验证。不能统称“完全无结构”，
  也不能统称“每张卡的 WHEN/OBSERVE/TRY 都是独立可编辑、独立执行字段”。
  来源：`methods/ttha/retrieval.py:158–170`、`agent_core.py:135–142,178–191`。

| 容易都叫 Scope 的对象 | 实际回答 | 当前作用 |
| --- | --- | --- |
| observable_applicability | 这条指导是否呈现给当前 Fast？ | 谓词匹配加 top-k，可能阻断加载 |
| legacy serving_scope | 旧卡的程序服务哪些序列？ | 历史供给/服务语义；最新指导修改不授予此权 |
| Workflow 区域/算子 targeting | 数据的哪里被处理？ | 由程序参数或算子内部规则决定 |
| 评价人口 | 哪些交付进入总效用分母？ | 实验协议固定，不随 Skill 条件收窄 |

因此结构化 Scope 能保证条件被执行，**不能保证条件预测效用**。可执行前置如任务类型
可以硬约束；“这种形状可能更适合 P”是待验证的效果假说，不必全部提前做成加载硬门。
是否扩大呈现、改软判断仍是方法选择，不能在修 bug 时顺带放宽。

### 16.4 当前 Slow 做到了什么；与“每次错误聚类后修订”差在哪里

最新 DEPLOY-2 将 120 条形成期记录与菜单材料池化后交给 Slow。R/C 读同样效果信息，
区别主要是提议说明是否强调比较；C-minus 去掉新增效果。一次 `edit` 阶段输出一个
有限修改、预期行为及反证条件，运行时编译隔离分支。它不是每条轨迹分别诊断、再按
诊断聚类、逐簇产生修改的循环。`derived_cause` 由所选 surface 映射，不能当作先验
根因判断，更不是根因已获验证。来源：`run_dev_deploy2.py:539–671`；
`slow_agent.py:344–463`；`dev_seq2_knowledge.py:846–884`。

早期 DEV-SEQ 确有轻量规则分组：在可比 Task/Consumer/读数语义下，按完整**算子序列**
及响应方向分组、配成功对照；这个分组键不包含参数数值，也不表示共同原因已成立。
来源：`methods/ttha/group_fault.py:36–84`、`dev_seq1_knowledge.py:323–411`。
所以用户问“是否每次修改都经过整体错误聚类”，当前准确答案是：**不是；不同实验
入口做法不同，最新入口没有独立的机制聚类阶段。**

成对证据也分两种：

- 同一合法情境对 P/Q 都做过评价，才有可直接比较的动作差分；其 UID、窗口、
  Task/Consumer 和评分人口必须一致。P、Q 的完整步骤与参数要分别保留，不能只按
  算子名拼接；两程序及参数本来可以不同，差异正是比较对象。
- P 在甲成功、在乙失败，是帮助形成条件假说的跨情境对照，不等价于在乙测过 Q。

目前菜单其实已有逐序列读数，却在 `_render_menu` 被删除。A 的修复只把已有事实
送回 Slow，不创造反事实。即使补齐，也不保证模型能从中提炼稳定规律。

### 16.5 哪些 surface 真能影响 Fast

当前目录包括六种模板，实例数取决于已有卡：新增指导、改指导正文、改适用条件、
改 bootstrap 正文、改提议指导、改选择指导。General/Specific 的语义不要求另建平台。

| 可改对象 | 能改变的决策环节 | 不能因此自动做到的事 |
| --- | --- | --- |
| bootstrap/观察指导 | inspect 的假说与区间；后续构造原则 | 创建一个并不存在的局部观察工具 |
| proposal_guidance/构造正文 | 提什么算子、顺序、合法参数/定位 | 越过算子 schema、预筛选或候选槽位 |
| selection_guidance | 合法候选中最终选哪个，包括 identity | 读取当格下游分数；保证未来收益 |
| specific body | 命中情境时的观察、构造、选择建议 | 自动取得供给或部署权 |
| applicability | 哪些情境收到指导 | 直接修程序或改善数据 |

它们确实进入提示，不是空注册。SEQ-4 同起点对照已经观察到选择翻转；DEPLOY 路径
又去掉了旧 Support 对交付的覆盖，所以选择指导现在可以直接影响交付。**但没有哪个
surface 仅凭名字就“影响大且有益”**；修改需要指出它如何改变当前可执行的行为。
来源：`agent_core.py:178–191`；`fast_agent.py:946,1018,1302`；目录见
  `dev_seq2_knowledge.py:479–584`。细化映射见 Grok B 报告，关键项已经主助手复核。

### 16.6 Self-Harness 最值得借鉴的不是多一个聚类器

本地源码显示：先由 LLM 结合轨迹和终局 verifier 分析未恢复的关键行为，再由代码按
`terminal_cause / criticality / agent_mechanism` 的一致签名分组；提议者选可修的机制和
hook，同时说明应保护的成功行为；最后用实际回归结果接受或拒绝。
这是“先解释行为，再汇总机制”，不是先把所有负分塞在一起宣布同因。
来源：`../Self-Harness/diagnosis/src/self_harness_diagnosis/trace.py:322–354`、
`integrated.py:41–114`；`proposer/src/self_harness_proposer/multi_proposer.py:104–163`。
论文方法见 [Self-Harness §3](https://arxiv.org/html/2606.09498v3)。

其签名也是模型假说，不是形式化因果证明；论文整体改善不能证明聚类单独贡献。
其称 held-out 的集合参与反复晋升，不等同于我们的最终冻结密封区。
[AutoGuide §3](https://arxiv.org/html/2403.08978v2) 则从同任务成败轨迹的动作分歧提炼
情境指导；[GEPA](https://arxiv.org/abs/2507.19457) 以执行反馈驱动文本修订和外部选择。
因此“经验→指导→新行为”已有先例，但不能把其效果直接移植为本项目保证。

本项目更难的一处是证据含义：预测 loss 变差通常不直接指出哪项观察/步骤判断错误，
且含共享训练管线的作用。需要分别记录可见的 Agent 行为事实和对效用的解释假说，
不能用“受损”直接替代“误删了该序列真实信号”。这是一项机制分析，不是不可学习证明。

### 16.7 我们下一轮应讨论并决定的核心，而非立即追加跑数

1. **观察与生成是否配套。** Slow 建议核查的区别，Fast 是否真的有合法信息和工具可查？
   默认单步预筛选是否挡掉本来合法的参数化/组合？先据源码和夹具裁定，再决定改哪一处。
2. **归因怎样指向具体知识。** 可考虑把“成败池直接写卡”与“轻量行为诊断/机制分组
   后修相应指导”比较。分组可以跨算子，但必须有共同可修改行为；同一算子也可以拆组。
   先区分无有效决定、确定性违法、合法交付但效用不佳，避免让 Slow 学习混合故障。
3. **结构化应服务修改，不只是格式。** 继续复用现有 SkillEntry；正文可按
   WHEN/OBSERVE/TRY/RISK/VERIFY/FALLBACK 组织，要求修改明确指向旧指导的哪一条。
   暂不新建 Schema；合法条件、软效果假说、程序区域分开，保留未被反例否定的知识。
4. **效果验收仍不能省。** 旧知识与新知识在同一生成入口、无当格反馈下比较实际
   Workflow 和效用，同时保留同反馈固定短 Workflow。模型写出好解释、发生选择变化、
   产生多步程序都不是最终成功条件；工程修复的收益不能算作知识学习。

目前没有依据承诺以上组合必然奏效。最值得保留的主线仍是“Skill 改善 Workflow
生成”；最需要补的不是更多卡或更多 Gate，而是**正确证据 → 可修改行为 → 有用知识**
这条对应关系。A 修复和 B 调研已经完成，下一步与用户集中回看，再确定下一项机制变化。

## 17. 用户确认：逐训练序列准备后，共同训练一个模型（2026-09-09）

### 17.1 已确认的目标，不等于已完成的实现

用户原话：“每条训练序列各自生成 Workflow → 汇总处理后的训练数据 → 训练一个
共享模型；预测时也逐条准备输入。这个才是我的预期的想法。”已同步 AGENTS §5.7。

一轮运行应是：冻结 General / Specific Skill → Fast 逐条观察合法训练材料、生成

预测输入逐条生成准备 Workflow → 同一共享 Consumer 预测 → 外部评价 → 到达合法

训练可见数据不等于允许读取评价真值，预测期也不能重演 Support 根据当格效果选策。

当前实现的区别由 `evaluation/main_protocol_p4/per_sequence.py:24–48` 明文确认：
每个程序 P 准备整套 train-role 材料、对应模型 M_P，评价序列选择 P 后读取 M_P
自己的预测行。它不是上述异质训练材料汇总后的单个模型；逐序列绑定正确并不代表
训练组织方式已经正确。用户不是要求 Consumer 永远不重训，也不是改成每序列模型。

### 17.3 反馈与归因要保留的区别

- 服务期仍有每条评价序列的误差，不能把它直接分配为某条训练序列的处理好坏。
  改动训练序列 A 可能影响评价 B、C；不处理某条服务输入也不再保证它与 raw
  模型的 Static 预测逐位相同，因为共享模型可能已经变化。
- 新旧 Skill 的主要效果比较需运行两套完整准备策略，各自汇总、拟合共享模型、
  对同一评价人口评分。旧缓存按程序取行的“精确拼接”性质在此不能沿用。
- 轻量行为诊断与错误聚类仍有价值：聚的是共同可修改行为，不是宣称共享损失
  已精确定位到某个训练样本。保留成功对照，按事实提出假说；有必要时才做局部
  对照，并计入重新拟合成本，不预设拥有所有动作的成对反事实反馈。
- 结构化 Skill、作用条件与有限修改面不必重造。更新仍主要作用于如何观察和
  生成 Workflow；有效性来自后续完整策略的收益/风险/成本，而非结构完整或多步率。

### 17.4 下一项实施应集中解决什么

先对齐训练请求、逐条执行后的汇总与共享模型拟合，再做一个小型端到端验收：
训练序列确实各有自己的 Workflow、汇总数据确实来自各自结果、同一臂预测确实
共用一个模型、每条预测输入仍逐条准备、Fast 未读 Outcome。现有错误状态/UNKNOWN、
窗口绑定与去重修补保留。训练目标是否可修改、窗口内可见范围和训练/预测变换
兼容性需明确写进实施规格，不借“逐条处理”默认扩大权限。

先验收执行修正，再在同一新入口比较旧 Skill 与自主修订 Skill，区分架构修正收益
与知识学习收益；不得拿新结果直接减旧路由式结果来证明自进化。旧特征线索用于
构造假说，不自动保证新组织方式出现正效应。

本节只落实设计确认及已有证据复用范围；没有新代码、拟合、LLM 实验、Git 提交或
密封读取。供 Fable 登记：设计已由用户明确确认，执行迁移未开始；不替其编辑
DECISIONS 或状态页，不把该确认写成已发车。

## 18. 取消 35% 后，其他设计如何取舍（2026-09-10）

状态：取消通用修改比例硬门已获用户批准，见 AGENTS §5.7.2；本节其他部分为后续
设计方向，不冒充全部已实施，也不授权修改核心运行时或启动新一轮实验。

### 18.1 保留用户的主架构，不转成固定算子路由

General / Specific 的结构化 Skill（描述、适用条件、观察和处理指导等）仍是知识
核心。Fast 逐训练序列生成 W，Runtime 汇总后每臂拟合一个共享模型；预测时 Fast
逐序列生成 V。同批知识冻结，Slow 在合法反馈到达后的批次边界更新有限知识面。
Fast 不读当格下游反馈；原始跨轨迹 Episode 留在 Slow / Runtime。

Workflow 可以单步也可以组合；不强制多步、多样性、非 identity 比例，不能把这些
计数当成效果。取消修改比例上限不等于允许改输出维度、碰评价真值或越过声明区间。
平滑使数据更适合指定 Consumer 可以是有效准备，不要求先证明某点属于“污染”。

### 18.2 Scope 保留，但区分操作边界与效果假说

明确的任务/输入兼容性、允许读取与处理的区间仍由代码执行。关于“什么形状适合
哪种处理”的效果判断，可以写进 Skill 正文供 Fast 在当前窗口观察和决策；不要求
一条阈值先覆盖多数失败，也不以少改点或多弃权为默认正确。

这不表示所有卡都应无条件检索。硬条件确实表达必要条件时仍可保留；扩大提示暴露
也可能分散注意力。暴露检查只定位是否送达，不把覆盖率变成新的成功门或优化目标。
当前 h0 instruction 仍有 “Keep modifications local ...” 等偏好；数值 cap 取消不会
自动改变这类知识。是否调整其通用措辞，应在新包明确对各臂共同的操作权限，区分
协议允许全窗处理与 Skill 是否会选择全窗处理，不偷偷替新臂写入赢家。

### 18.3 训练与预测需要兼容，不强制相同，也不强制预测侧 identity

近期诊断表明不同准备方式的训练侧、预测侧及交互效果不同。不能由一个 IQR 案例
推出所有算子只应改训练；也不能把 FFT 的组合结果解释成只有两侧都处理才可能有效。
因此继续让 W/V 由各自角色与合法窗口证据指导；可用固定 W 换 V / 固定 V 换 W 的
小型重放解释差异，但每个新的训练赋值必须真实重拟合，不能拼不同模型的预测行。

### 18.4 Slow 修订的是判断依据，不是失败标签的另一种写法

输入按窗口绑定程序、公开观察、动作事实与效果，保留成功对照和 UNKNOWN。训练
赋值影响共享模型，评价 UID 的损失不能直接当成某个训练 UID 被洗坏的证据。
轻量分组用于呈现类似行为冲突，不先宣布共同根因；允许只解释子群。

Slow 可在既有白名单内修改 General 指导、Specific 正文或适用条件、观察/提议/
选择指导；由证据选择具体位置，不固定 ADD 或一律改成弃权。竞争解释必要时用
小对照区分，但不要求每次运行完整因果实验。只有已测 P/Q 才称成对效果，未测 Q
不补零。当前实现收集成败不等于已完成机制聚类，更不能将表述变长当成能力增强。

验收看新指导是否改变真实的观察、Workflow 和最终交付，以及全人群质量、风险、
成本；不再用“覆盖半数失败”“文字完整”“少处理多少点”替代效果。

### 18.5 参数与动作权限分开处理

名义周期24与局部自动估计是两个可用信息来源，不等于每个窗口真实周期必为24。
SSM 显式 period24 的增益线索值得纳入后续同权限菜单/参数核查，但这次取消比例
门没有批准修改算子 schema、强制所有算子 period 必填，或向一臂暗送参数答案。
如下一包扩入显式参数配置，固定基线与新旧 Skill 得到同样参数说明与合法权限。

### 18.6 下一步的最小效果问题

在同一取消比例门的动作权限下，小规模比较 Static、形成段校准固定 Workflow、
旧 Skill、Slow 自主修订 Skill，保持 Consumer、人口、时间边界和观察接口一致。
这轮不同时增加新记忆系统、退休系统、训练权重动作或任意代码自改。

- 固定基线变好：说明动作空间有价值，不证明学习。
- 新 Skill 优于旧 Skill，但仍输固定：说明修订有局部作用，条件化优势尚未建立。
- 新 Skill 在质量或相近质量下的风险上有可复现优势：再扩大情境，检验积累与迁移。
- 好动作存在却生成不出：看参数/观察/提议；交付已改变仍无净价值：看条件与训练—
  预测交互，不能继续把问题统称为“没有使用知识”。

既有全人口指标和风险读数保留；诊断分组可加报但不事后换主终点。所有后续开发
窗口仍标曝光 development；扩大权限后的结果不与旧0.35历史直接相减归因为学习。
