# 任务书：DEV-AUG-TSFM-OFFLINE-SKILL（2026-09-24）

状态：用户 09-24 确认——由执行者编写 TSFM 版本入口，设计与 `DEV-AUG-PATCHTST-OFFLINE-SKILL` 同构（条件化重新学卡），在服务器 1–2 × RTX 5880 上运行。入口 `evaluation/main_protocol_p4/batch_research_aug_tsfm_offline_skill.py`，输出 `_scratch/dev_aug_tsfm_offline_skill/`。身份：开发复验（40 例 Test 已曝光）。

## 1. 设计

- **Consumer**：Time-MoE-50M 官方权重（`Maple728/TimeMoE-50M`，旧 LTSV 包 `tsfm_env/model`、源码 `tsfm_env/src`），transformers 4.40.1，fp32，eager attention。每个（案例、方案、seed）都从同一预训练权重微调：AdamW（除 bias 外 wd 0.1）、梯度裁剪 1.0，损失为 48 步自回归预测 MSE（KV cache 展开，与官方 `generate` 逐位相同，沿用 `ltsv_tsfm_helper`），父 / 子视图各 0.5，同一批父窗。批流取 `train.batch_indices(seed, …)` 的前 `batch` 列，与 MLP / PatchTST 同一随机流。输入用 T scaler，不加逐窗标准化。
- **校准（只 Source、只 None）**：每域 A1/A2 的 G1 共 6 例，首 seed；lr {1e-5, 3e-6} × 每步父窗 {4, 16} × 检查点 {25, 50, 100}；目标 = C_A+C_B nMSE 域内平均再三域等权；平局依次取更少步数、更小批、更低 lr。零样本只作锚点，不参与选择（不训练就没有增强起作用的通路）。
- **其余流程与 PatchTST 包相同**：Source 12 个固定方案 + 24 条无卡零反馈轨迹（Fast 看到 Time-MoE 描述）→ Slow 每域 2 张卡（只读 Time-MoE 证据）→ 原 Select 选卡 → Test 四臂 f_tsfm / f_mlp / f0 / f_naive（朴素卡按 Time-MoE 描述重生成），参照 None、NoMix、Source 选出的固定方案、零样本 Time-MoE。
- **不保存模型文件**（每个约 450 MB）：训练进程训练完立即只用 E 输入窗（服务输入，不读目标）冻结预测；控制器在阶段屏障后才读目标评分。Source / Select / Test 的屏障与 PatchTST 包相同。
- **接线（付费前自动执行，失败即停）**：展开与官方 generate 逐位相同；NoMix 在同一进程先后两次（中间隔另一次拟合）预测逐位相同；NoMix 与 None 不同（子视图确实参与训练）；有第二张卡时同一拟合在两卡上逐位相同。

## 4. 修订 1：改用 Time-MoE 原生微调方式（2026-09-24，用户选 B）

**起因**：第一版（rollout）在服务器上校准后，12 个微调配置全部不如零样本（最好的 lr 3e-6、25 步、每步 4 窗，验证误差 0.1985；零样本 0.1959）。与 LTSV 所用的 Time-MoE 原生微调相比，第一版有 4 处不同：损失（只监督 48 步自回归展开的 MSE，没有逐位置多头 Huber 损失和路由辅助损失）、输入归一化（实体 T scaler，而不是逐窗口）、AdamW β2（0.999，而不是 0.95）、每个窗口的监督量。用户选择停下第一版，改用原生方式重跑。第一版的部分结果保留在 `_scratch/dev_aug_tsfm_offline_skill/`，不与新版并表。

**原生方式（`SEH_TSFM_RECIPE=native`，默认）**：
- 训练损失直接调用 `TimeMoeForPrediction` 的官方损失：每个 240 点窗口（192 输入 + 48 目标）取 `input_ids = window[:-1]`、`labels = window[1:]`，四个预测头（1/8/32/64 步）在每个位置上算 Huber（δ=2），再加 0.02 × 路由负载均衡损失。父视图和子视图各 0.5。
- 归一化：每个窗口都用它自己 192 个输入点的均值和标准差（无偏，下限 1e-5）标准化，训练和服务一致（官方推理约定），预测再映射回 T scaler 单位后评分，评分器不变。
- 优化器：AdamW（β = 0.9 / 0.95，除 bias 外 wd 0.1，梯度裁剪 1.0），恒定学习率。
- 校准网格（只看 Source、只用不增强）：lr {1e-5, 5e-5, 1e-4} × 每步父窗 {8, 32} × 检查点 {25, 50, 100, 200}，共 36 次拟合，零样本锚点同样按逐窗口标准化。选择规则不变。
- 输出目录 `_scratch/dev_aug_tsfm_native_offline_skill/`，包名 `DEV-AUG-TSFM-NATIVE-OFFLINE-SKILL`。

**新增自检（`--selftest`，不调用 LLM）**：在单独目录里跑接线、两案例快速校准、Source 拟合与屏障、脚本化的零反馈 Fast 流程、单案例 Slow 证据整理、Test 零样本与屏障。`server/run_tsfm.sh` 在启动付费阶段之前会自动跑一次，不通过就不启动。

- 2026-09-24 17:00 本机（RTX 4060，torch 2.12，transformers 4.40.1）原生版 `--selftest` PASS 8/8，用时 570 s：接线（generate 最大差 0.0、重复逐位、子视图生效）、两案例快速校准、Source 屏障拒绝与评分、脚本化零反馈 Fast、单案例 Slow 证据整理（22 KB）、Test 零样本与屏障。显存实测（原生，3 步）：每步 8 窗不增强 3.9 GB、增强 5.9 GB；每步 32 窗不增强 9.9 GB、增强在 8 GB 卡上 OOM（已分配 14.3 GB）。据此改为按任务估显存派卡。服务器更新包 `server_export/update_v5.tar`。

## 9. 修订 5：推理上下文准备（v9 / v10，2026-09-24 晚，不训练，不调 LLM）

**起因**：用户指出应考虑 in-context 路线，要求“能尝试的方法都可以试下”。核对原文后发现：LTSV 所说的“in-context finetuning”其实是一步梯度更新；TimesFM-ICF 需要专门继续预训练的模型，并要在例子之间加分隔符，HuggingFace 上公开的 TimesFM 1.0–3.0 权重都没有标明为 ICF 模型。Time-MoE-50M 支持最长 4096 点的上下文，而本项目一直只用 192 点。因此在不训练的前提下，测试“给零样本模型准备什么样的推理上下文”。

**`--context-screen`**：
- 每个 E 起点用它之前的 Lc 小时作上下文，Lc ∈ {192, 336, 672, 1344, 2688}，可以读到 T 段之前的历史，但不读起点及之后的数据。
- 标准化方式两种：逐窗口按自身均值与标准差标准化（官方做法），或用 T scaler 标准化。
- 与现有零样本基线（逐窗口标准化、192 点）比较，基线与之前存下的零样本结果最大相对差 5×10⁻⁵（浮点级）。
