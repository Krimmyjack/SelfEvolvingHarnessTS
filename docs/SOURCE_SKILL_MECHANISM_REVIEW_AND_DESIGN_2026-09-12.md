# 当前项目与 Source/Specific Skill 的机制审查及后续设计

> 最新进度：H3及诊断、a94 Source对照均已收口；§14补充a94结果及Slow观察/修改面的边界；早期章节保留历史状态。

日期：2026-09-12。性质：方法审查与下一轮设计建议，**不是新实验结果或对在跑任务的变更**。

用户确认 Grok 正在推进 H3。本次未访问 H3 运行目录或其 E，未修改执行代码、Source、模型、数据、预算及评分规则。核查对象是项目正典、repair 执行实现和已公开给团队的历史结果；公开文献按本次可取得的原文核验。主张以 [AGENTS.md](../AGENTS.md) 为准，本文件作为 [现行方向与计划](HARNESS_RESEARCH_DIRECTION_AND_PLAN.md) 的专题审查附件。两位 medium 子 Agent 分别协助机制核查与文献核查，根 Agent 整合；这不是外部独立审稿。

## 1. 我的明确判断

**保留“面向数据增强的 Harness 自进化”，继续完成正在运行的 H3；下一项方法投入优先补齐 Source 经验与可学习决策之间的对应关系。** 当前既不该再解释为“增强环境完全没空间”，也不该认为“匹配接好，A5 就应该更好”。

已有 Time Mixup 的真实后续收益，说明这个增强环境值得有限投入。尚未成立的是：历史知识能否教会 Agent 比强固定、同预算搜索和从头适应更有效地解决新作业。此前几轮失败混合了三种不同情况：旧清洗环境的局限、真实方法无增量，以及工程失败造成的不可评价。不能把它们合成一个“Source 一直无效”的结论。

**当前最重要的设计矛盾有三个：**

1. Source 主要提供固定动作的成绩与粗粒度统计，系统却期望 Slow 产出细粒度适用条件和调查技能；材料不足以直接支持后两者。
2. Specific 的“加载条件”与“有益条件”容易被混为一谈；加载算法正确，只能证明发给了该发的文本，不能证明文本适合这个作业。
3. 当前 pilot 的多数反馈与选择都服务于本作业交付模型；更新后的知识尚未在下一份训练材料上重新解决任务，其长期价值没有完整的验证机会。

我最推荐的方向是：**让 Source 成为有实际依据、可被 Target 修订的实验先验；让 Specific 表达在何种任务和数据结构下，优先观察、构造、比较什么。** 这包括有根据的正向处理经验，也包括调查经验。避免把它缩成“遇到不确定就不处理”，也不要求每条经验必须输出处理动作。

这里的 4.6535% 是报告预定的“两个作业损失求和后的相对改善”，不是两个百分数的算术平均，也不是显著性结论。原 2% 是资源分配门槛。H2 的 A3/A5 主结果应是 UNKNOWN，Fixed-Mixup 兜底只作诊断；不能把兜底成绩当作完成适应后的 A5 成绩。H3 本次尚未审阅。

必须停止沿用的旧判断：

- “八个学习器都失败，所以条件化没有用”：相关跨模型逐实体拼分实验已撤回。
- “跨 origin 标准差就是知识效应的噪声，几倍 SD 可一票否决”：不是相应配对比较的统计检验。
- “一个 F 同 H 分支差值就是采样方差”：单个差值不能估计方差。
- “缺失多就是坏数据，所以任务不该入场”：执行器病态计算与真实缺失环境是两件事。
- “Ridge 行数少于维数，因此所有收益都是假象”：不足以推出该结论；GBM 对照只说明部分大效应依赖消费者。
- “比 seasonal-naive 好，所以 MLP 已充分调优”：只能说明超过这两个简单基线，不能排除所有训练配置问题。

## 3. 当前 Source 究竟是什么

**Source 是历史研究经验的来源角色，不是额外塞给预测 MLP 的一批原始训练数据。** 当前 A5 比 A3 多的是从 Source 提炼的 Specific 及其后续影响；双方在 Target 上训练自己的共享 MLP，不能将 Source 与 donor 混称。

当前流向：

~~~mermaid
flowchart LR
  S["历史作业：实际方案、C/E、风险与T描述"] --> C["确定性摘要"]
  C --> L["Slow形成Specific：正文、Scope、引用"]
  L --> F["Fast：按实体匹配后读取正文"]
  L --> R["Slow：研究与修订时读取初始知识"]
  F --> W["各实体Workflow汇总成训练材料"]
  R --> F
  W --> M["一个共享Consumer"]
  M --> O["合法Target反馈"]
  O --> R
~~~

对应实现：

- [source_material.py](../_scratch/ts_aug_harness_h1_repair/source_material.py)：a30/a40 六臂、a50/a60 三臂，C/E、seed、origin 和风险摘要；历史特征主要为跨实体均值/标准差。
- [knowledge.py](../_scratch/ts_aug_harness_h1_repair/knowledge.py)：单份正文、Scope、引用与版本；General 规定公共动作和权限，Specific 是可检验建议。
- [applicability.py](../_scratch/ts_aug_harness_h1_repair/applicability.py)：闭合观察词表与三值判定，复用项目原匹配求值逻辑。
- [driver.py](../_scratch/ts_aug_harness_h1_repair/driver.py)：A3/A5 同一路径，区别为初始知识；q2研究、Target更新、q3/q4重新生成。
- [finalize.py](../_scratch/ts_aug_harness_h1_repair/finalize.py)：按共同 C_B 规则选模型，冻结预测后评分；不完整方法单独标记。

现在已经明确区分显式宽 Scope、条件 Scope、缺失条件与技术失败。**这些修复提供可解释的执行链，并没有验证条件本身的效用。**

另一个关键点：Fast 零匹配不等于全系统没有使用 Source。q2 Slow 仍可读到 Source 并把它变成研究指令。对“某 Specific 没生效”的诊断，必须区分直接进入 Fast 与经 Slow 间接影响实验这两条通路。

## 4. 最值得解决的八个方法问题

### 4.1 用总体成绩学习局部条件，存在信息缺口

现有摘要能表达“该作业有某种总体形态，Time Mixup 整体较好，部分实体受损”，却没有保留“某种观察对应哪种受控处理及什么响应”的关系。

例如，两批材料都可以有相同的周期强度均值、相同的改善实体数、相同的总体收益，但一批主要是强周期实体获益，另一批主要是弱周期实体获益。仅凭这几项摘要无法区分它们。因此 Slow 写出“周期强度大于某值才增强”，很可能是在提出假说，不能称为从现有摘要学到了条件规则。

即使补回逐实体对应，也只能增加关联信息。共同训练会产生跨实体影响，不能将实体损失差直接当作该实体增强的因果效应。

**最小修正：**围绕一个未决问题保留 Context—完整赋值—受控变化—结果的必要对应片段。只补会改变下一决策的材料，不恢复几十万字符整包输入。只有实际联合对照支持的条件，才有资格成为较强处理依据；其余标明假说。

### 4.2 当前 Source 最可靠的信息，已被公共强基线覆盖了一部分

四个历史作业中，Time Mixup 都是各自已测试动作的 E 均值最优；但 a50/a60 只比较了 None、Copy 和 Time Mixup。Source 没有两步组合的历史证据，也没有直接比较过所有后续异质赋值。

所有方法已知道 Time Mixup 的构造方式，而且 q1 后共同获得当前固定方案的 C_A 反馈；最终交付池还包含 Fixed-Mixup。因此“历史告诉你 Mixup 值得试”是一条有用经验，却可能只在第一步产生小幅优势，很快被公共反馈追平。

**这不是强基线设置错了。** 它准确暴露了研究要求：完整 Source 必须提供超出一个好程序名字的信息，或在包含全部成本的情况下更快达到同等质量。不能删掉 Fixed-Mixup 来创造空间。

优先追问：Source 会不会帮助识别哪一个替代方案值得用下一次拟合验证？或者解释为什么当前短校准结果与旧经验冲突？这些才是现有先验之外可能有价值的内容。

### 4.3 匹配的对象不够清楚：数据相似，不等于作用相似

有效适用域应围绕：

> 可见数据结构 × 作用几何 × Task/Consumer × 当前证据阶段。

“都是 Electricity”不够；“频谱相近”也不够。同样频谱，在不同历史覆盖、donor 配对、归一化或消费者下可能出现不同效果。当前固定环境无需新增字段大平台，但它限制了能学到什么：固定 433 个父窗口、固定 MLP、无缺失的四作业，无法提供“历史数量变化如何改变增强收益”的经验。

特别是一些原尺度统计，经当前训练段 scaler 转换后不直接保留其数值意义。它们可以作为假说线索，不能未经验证就成为增益阈值。应优先看与实际增强产生的变化相关的量，例如父对/donor 的结构差异、联合变换后哪些关系改变；这需要明确的新假说才能新增观察。

### 4.4 Scope 和建议强度被放在了一起

需要区分三个问题：

| 问题 | 例子 | 应有后果 |
| --- | --- | --- |
| 能否合法使用 | 相同输入/目标角色，donor 已成为合法历史 | 硬检查，不满足则不可执行该动作 |
| 是否与当前问题相关 | 当前存在旧经验讨论的结构差异 | 决定是否检索/呈现此条知识 |
| 是否已证明应当这么做 | 在相似结构、共同消费者下有重复对照支持 | 决定建议强度与所需 Target 校准 |

当前 AST 主要处理第二个问题。一个 MATCH 不能同时回答第三个问题。

**宽 Scope 可以合理。** “遇到强度与 donor 两种解释冲突，先做保持另一因素不变的对照”可以适用于很多数据；“周期高于某值就用 FreqMix”则需要更窄、更直接的证据。Specific 的“特定”是任务结构和用途明确，不是一定有一个狭窄阈值。

不匹配时继续公共 Harness 正常求解。信息不足时可在 held-in 阶段申请合法观察/对照，或暂不采用该经验；不能把经验不确定直接等同于整个作业必须 identity。也不能为了激活率强行放宽 Scope。

### 4.5 把初步先验写成禁令，可能压低有效探索

历史 Source 曾输出“统一单步 Time Mixup，并排除其他操作”。它支持“先考虑 Mixup”的部分有数据依据；对所有未测试组合的排除则跨越了证据。

这种压制可能发生在三个位置：初始候选趋同、q2 沿旧解释试错、Target 更新把新反例再次总结为更保守的规则。不能只看最终 identity 比例来诊断；始终 Mixup 也可能是过强先验。

建议在既有正文中区分：

- **正向能力：**优先构造什么，依据是什么。
- **待解问题：**当前证据不能说明什么。
- **修订路径：**什么合法反馈会改变建议，下一次优先比较什么。
- **风险边界：**已观察到的失败、未验证范围。

这不是要求 Slow 必须输出“积极动作”。ABSTAIN、保留固定、停止某项尝试都可能正确。真正应减少的是“未测试→全面禁用”“不确定→没有建设性下一步”。

当前 General 已说明 Specific 无权删除公共动作；真实模型是否把建议当禁令，仍需实际执行证据。不能把修复后的形式约束直接当作认知偏差已经消失。

### 4.6 当前固定流程限制了“学习怎样研究”的空间

q2 允许复用或一次 action/steps/order 变化，随后更新、q3/q4、C_B 选择顺序固定。Fast主要拿到预先计算的观察，尚没有学习选择观察工具或校准切片的权限。

所以当前 pilot 可以检验“先验影响候选与一次对照”的价值，不能承载完整主动研究能力的结论。**不是动作少就不能做 Agent，而是需要说清 LLM 在哪个尚有信息的决策上发挥作用。**

下一轮只宜增加一个具体决策自由度：例如在相同拟合预算中，选择哪一个有解释价值的子群替换对照；不要同时加新算子、工具系统、验证选择器和长期 Memory。

所谓对照必须按实际变更解释。正常 Workflow 构造仍由 Fast 完成；研究阶段若 Agent 主动申请“只改变某组”，执行器可以按共同合同复用其它组已执行的材料，保证受控背景。这是明确实验的执行约束，不能变成 Runner 私自修正普通 Fast 答案。

### 4.7 当前 C_B 门主要选模型，不是知识的独立验证

q4 比 q3 好才有资格加入交付池，随后又从包含 q3 的池里按 C_B 最小值选模型。除极小容差外，这个门几乎不会改变赢家：比 q3 差的 q4 本来就不会被 argmin 选中。

这不是运行错误，记录这种分支关系也有用；但“采用了新 H”并不因此获得独立的长期知识证据。当前 E 评估冻结的模型，不是在另一作业调用新 H、生成新材料、重新训练。

此外，已有 C/E 排名冲突表明：好候选可能因有限校准而未交付。把这一问题全部归为 Skill 匹配错误，会修错地方。应分别报告生成候选的质量、C_B 选取的交付质量、旧/新 H 分支与 F 重复。事后 E 最好只用于开发定位，不能替换预选交付。

如未来研究校准代表性，应让所有臂获得同一套新权限与相同反馈成本，并使用新的确认材料；不能只给 A5 更好的选择器。

### 4.8 临时反思与长期 Skill 的区别，目前没有充分呈现

F 不写共享知识，但它可以使用当前任务的反思；A3/A5 将类似内容写入可编辑 Skill。在同一 Target 内，两者都能影响后续候选。持久化的优势只有在下一任务需要复用、修订或组合时才有机会体现。

各 Target 从 H0/同一 Source 重启，适合隔离 Source→Target 转移；**它不是错误设计，也不等于连续积累。** q4 对 q3 的后续预测收益可以提供本地更新线索，但持续演化需另有新训练作业重解。

Source→A5 与 H0→A3 是积累的主要比较。A5−F 同时变化历史起点和共享更新权限，不能叫纯 Source 效应。

## 5. Source 应怎样设计，才能有正向作用

### 5.1 首先承认三种内容的证据强度不同

| 内容 | 当前是否具有形成基础 | 应怎样使用 |
| --- | --- | --- |
| 程序先验：某类增强值得先考虑 | 有；来自真实固定方案的跨时间结果 | 可撤销的候选偏好，保留强固定对照 |
| 条件处理经验：某种结构适合怎样增强 | 仅有初步假说，缺对应与联合对照 | 先检验，不能自动成为硬门 |
| 调查技能：遇到冲突，哪种观察/对照更有效 | 当前固定实验表缺少过程经验 | 通过实际研究轨迹形成，不能把模型想出的建议直接命名为学得技能 |

经验不一定必须由 LLM 产生。确定性实验也可以成为优质 Source；关键是它是否留下了支持所声称知识的比较。反过来，一千条 LLM 思考文字没有相应对照，也不比一条可靠实验更强。

不要求 Source 全是正例，也不要求人为凑成功/失败比例。Source 的组织目标应是**覆盖相互竞争的解释**：在哪里成功、什么变化使它失败、哪一个对照排除了哪种解释、下一次能复用哪一步。真实失败、未决和弃权都保留，技术故障不伪装为动作失败。

### 5.2 建议采用“有依据的默认候选＋可检验例外”，不强制每条都窄匹配

这是下一轮内容设计原则，不是立即改 H3 格式。

现有正文、Scope、引用已经足够承载一个小原型。可按下面六句话组织：

~~~text
用途：这条经验帮助解决什么决策，交给 Fast 还是 Slow。
已知：在哪种 Task/Consumer/训练几何中，实际支持了什么。
优先做：当前条件下值得先构造或检查什么。
未决：证据尚不能区分哪两种解释。
下一对照：固定什么、改变什么；不同结果怎样影响下一决定。
边界：什么情况下仅作假说、暂停迁移或交回公共求解。
~~~

Scope负责合法且相关的加载；正文明确未经验证的效用假说。不要再创建一套知识治理状态机。范围与正文一同修订已有接口足够，只有实验证明需要多个互相矛盾的有效技能时，才扩展数量或检索器。

一条有效 Specific 也可能在许多任务适用。**重要的是它在当前任务提供了相应的帮助，而不是总让更少实体命中。**

### 5.3 怎样把“匹配好了”变成可检验的主张

至少分开检验三件事：

1. **送达：**同一个条件求值结果是否对应实际 prompt；这是仪器问题。
2. **使用：**知识是否改变了实际观察、候选、对照、保留或修订；这是机制中间证据。
3. **价值：**在新作业相同权限与预算下，改变是否改善联合模型的后续质量/成本；这是研究结果。

如果要声称条件匹配比宽适用更好，应比较**同一条有用正文**的宽范围与条件范围，并控制处理数量/强度造成的保守化解释。最终每个完整赋值单独训练一个共享模型。不能按“匹配实体的预测更好”拼出因果结论。

只有在存在可信匹配假说时才做此消融。现在不能先编一个阈值，再用高激活率证明匹配质量。也不能根据最终 E 的“好实体名单”反推 Scope 后再在同一 E 验证。

### 5.4 一个下一轮可以研究的具体问题

**候选问题：当统一 Mixup 在当前合法校准中收益不稳定时，是否存在一类可见的训练结构，使局部保留原始材料比继续对该组增强更有利？**

这不是说已经找到了这类结构，也不预设“趋势强”一定有害。先让实际证据决定检查哪个现象。

一种有界研究方式：

- 所有方法共享 None 与固定 Mixup 参照。
- Agent 从当前合法 T 观察和已获得的共同模型反馈提出一个解释，并指出哪种结果会推翻它。
- Agent申请一个联合对照：保持其余实体已执行方案不变，只改变基于可见条件选定的组；例如单步 Mixup 与保留原始材料之间的比较。
- Runtime执行实际指定的变化，一次联合拟合，返回整作业效用与诊断分布。结果归于这个背景中的组干预，不归于组内每个点。
- Slow只根据这次对照修订经验；未区分解释就保留未决。
- 冻结知识后在下一份训练材料上重新识别结构、构造完整方案并验证。

首个可取的正向结果可以是“较少反馈找到了同等质量方案”，也可以是“同样预算下找到了固定 Mixup 未覆盖的有用方案”。若固定方案足够、对照无额外信息，就不应继续扩复杂规则。

如果后续证据指向 donor 相容性而当前菜单无法改变 donor 规则，应单独设计一个所有方法共享的最小动作扩展；不能把新强动作只送给 A5 后算作 Source 增量。当前不同时开放这两条改动。

## 6. 应如何准确看待 Random-search

当前 random_search_recipes 有一半概率提出全实体相同 recipe，另一半提出异质 recipe；空间含 identity、三个单步及九个有序两步组合。这是有合理覆盖能力的强基线，并非“胡乱操作数据”。

Random 暂时领先有几种相容解释：

- 合法动作整体已有价值，抽几个完整候选足够。
- 其提议分布覆盖了 Source 未测、却可能有效的组合。
- 单条强先验使 Agent 的候选高度相关，四次调用并不带来四种有用比较。
- 只有一个完整单元，训练/生成与选择波动仍可能决定次序。
- Agent本来有好候选，但共同 C_B 规则选错。

现有局部数据不能唯一确定哪一个解释。H2不完整A3/A5尤其不能参与“随机全面击败积累”的结论。

同动作空间不代表同提议分布，这是方法差异，不自动构成不公平。应保留 Random，分别检查最初候选、预算内候选集合、预选交付与成本；不应要求它逐实体调用 LLM来人为变贵。“0 LLM”也不等于零成本，它仍消费真实消费者拟合。

如果最强可复现结果始终是固定增强或简单搜索，应保留这项工程能力，但不要用它替代用户要求的 Harness 自进化贡献。

### 7.1 MetaCaster：本次已经取得全文，应关闭“只读摘要”的旧边界

[MetaCaster v2](https://arxiv.org/html/2608.23473v2)，本次选读§3–4、算法与数据隔离附录。它在多数据集上优化生成Agent的Harness，使用下游预测表现、训练日志和生成轨迹修订；冻结后在分离的数据集上评价，也包含未见域。执行空间是生成程序、训练与选择轻量预测器，比当前小菜单更宽。**不能再把它描述为没有跨任务Harness学习的单作业生成器。**

其形成语料内部被称为test的分段参与外环优化，按本项目语义应视为已用Source反馈；不能直接指控最终Target测试泄漏。它也不等同于固定共享Consumer、同Target反馈预算的A3/A5比较。上述区别仍需正式基线与机制实验，不能当作已经证明的创新。

从比较得到的设计推论是：只提供少量数值观察和固定菜单时，应先证明该决策确实需要可复用研究经验；不能因为更开放、证据更丰富的Agent成功，就期待当前受限切片自动成功。也不建议照搬其整套生成器和预测器库。

### 7.2 文献并没有证明“精确匹配之后，自然会有效”

相关工作分别实现轨迹反思、程序复用、原则绑定、任务搜索、请求缓存或跨任务Harness优化，没有一篇可以替代本项目的核心检验：

> 在共同训练、合法可见条件和相同Target反馈预算下，经过历史形成的知识是否改善后续求解？

因此最接近的路线是借用“候选相关性→证据绑定→实际试验→后续复用”的结构，同时提供数据任务特有的作用单位、时间权限和共享训练证据，而非宣布发明了匹配或反思。

## 8. 推荐的推进顺序：先完成当前观察，再做一个机制改动

### 第一步：H3只按已冻结规格收口

本次不影响Grok。完整后按以下分支解释：

| H3所见 | 下一项方法动作 |
| --- | --- |
| 技术不完整 | 只处理具体阻断；该方法主结果UNKNOWN，不据兜底裁决 |
| 合法Source零匹配 | 检查相关性与形成依据；不能事后放宽Scope重评分 |
| 真加载，候选被强先验压成同一方案 | 以“先验强度/可修订性”为单一待测机制 |
| 候选有效，C_B交付差 | 优先检查合法反馈代表性；不盲改匹配 |
| q4本地较好 | 保留该知识，安排下一训练作业重解，不只增加同模型预测窗 |
| A5完整胜A3/F/Random | 追踪具体使用链后做预定重复；单单元不足以声称稳定积累 |
| 全部完成仍无可定位优势 | 停止扩大同形课程，进入下面的机制小比较或暂停该假说 |

这张表是错误类型与下一实验的对应，不是“看到不好就必然换机制”。只挑有真实记录支持的一项。

### 第二步：先让Source拥有一次真正的判别经验

不要求额外堆Source数据量。优先使用H3结束后合法开放且真实发生的受控对照；若实际只是候选搜索，就老实标明，不能改名为调查成功。

若没有足够对应经验，可预定一至两个形成作业，每个最多四次逻辑联合拟合，含参照。只研究一个从现有记录提出的冲突；所有背景、真实改动和解释未决都保留。Source形成后允许KEEP/ABSTAIN，不能反复抽卡直到说出研究者喜欢的结论。

此时应做到：**比较用的简短程序先验与过程型Skill来自同一份经验、同一可见权限。** 如果只给过程型Skill新增对照资料，而程序先验还用旧四作业表，胜负混合了信息量和学习对象，不能解释为“过程Skill更好”。

### 第三步：先比较“历史好方案”与“历史调查经验”的增量

建议的最小机制包，而非替代正式A3/A5：

- 共同None、Fixed-Mixup；同一MLP/数据/动作/Scope执行器/Target临时状态。
- 一种知识只保留证据支持的方案先验；另一种允许保留真实对照支持的调查/构造经验。
- 两者Source证据相同、形成预算相同、编辑与Target反馈权限相同；不以更长prompt或更多调用作为隐藏优势。
- 两个在看效果前选定、训练材料变化的后续作业；先一条配对执行轨迹用于开发判别，各四次候选预算。约20次Target联合拟合上界：每作业2个公共参照＋两种知识各4次。若另有两个形成作业，最多再8次。精确复用不增加逻辑反馈。
- 预先看第1/2次和完整预算的交付质量、候选差异与总费用；公共参照成本计入两侧。最终C_B选择规则对两侧完全相同，不能用E挑前缀赢家。
- API上限依据H3实际每阶段消耗另行冻结；上述是方法设计，不是本轮执行授权或承诺耗时。

这一小比较问的是“过程知识是否超出好程序先验”，**不直接宣称A5>A3**。出现有效机制后，再恢复完整Static/Fixed/Random/F/A3/A5，在多条独立形成与执行轨迹、后续作业上评价。没有效果且没有具体 first-fault，就不扩成数百格。

“简短程序先验”是诊断对照，不能成为主方法，也不能绕过Source→Slow→Skill通路直接把历史Episode编译为Fast候选菜单。

### 第四步：单独验证新H的后续复用

从同一已完成形成过程取得H_old和H_new。下一预定作业重新取T、重新生成每实体Workflow、共同训练，并给两者同样Target预算。不能用旧模型继续预测冒充新任务。

如果这个作业用于批准新H，它已是验证数据；下一轮长期确认需要未参与批准的材料。保留一例旧适用情境检查是否丢掉已有能力，不能只展示新情境的改善。

如果新H只复现了历史最佳程序，应报告答案复用。如果其对照选择/构造方法带来额外效用或成本改善，才有过程技能证据。多个后续作业保持该优势，才能逐步建立累积价值。

## 9. 怎样判断“更有希望”，避免继续盲目投入

**有依据的希望：**真实增强已改善后续预测；存在C/E冲突、候选差异和可解释的数据作用，提供了研究素材。当前没有证明环境只允许identity。

**最大的未知：**合法观察和有限反馈是否足以把这些差异转化为可重复决策；Source是否能提供超过强固定与临时搜索的信息。工程修复没有回答这两问。

我会用三个具体检查判断后续投入是否值得：

1. Source能否明确改变一项合理的候选/对照决定，且该变化源于真实经验而非模型常识或人工答案？
2. 这个决定是否在变化后的训练作业中改善质量或真实总成本，且不能由固定方案或同预算临时反思解释？
3. 该经验的适用与失败边界能否在后续修订中被保留，且没有靠看到E之后调整条件？

前两个失败，就先关闭所测机制。不要用复杂格式、更多Skill、强制非identity或提高匹配率续命；也不把一次失败扩成“整个Harness主题无效”。

固定4次逻辑反馈的当前pilot本身不够证明完整样本效率：真实效率需在共同的多个预算检查点定义交付并统计形成、LLM与拟合费用。精确缓存或reuse节省物理成本可以报告，但不自动意味着知识减少了必要反馈。形成成本能否在重复作业中摊薄也要单列。

## 10. VLDB定位：机会在什么地方

建议持续追问的数据管理问题是：

> 如何在重复发生的训练材料准备作业中，把具有时间权限、共同训练耦合和验证成本的实验经验，变成可执行、可修订的增强研究技能？

潜在贡献必须落在实质机制：如何选择有解释力的联合对照、如何限定经验的适用和使用权、如何在新作业减少无效验证。仅有Source、Scope、谱系、反思或缓存，都已有近邻设计。

[VLDB 2027官方Research Track](https://www.vldb.org/2027/call-for-research-track.html)包含相关数据准备、面向ML的数据管理、时序和工作流议题，同时要求实质性数据管理联系。范围匹配不保证创新。MetaCaster、TSAA、Kitana、DiffPrep与通用Harness优化器都应成为实际机制定位的参照；不能靠“共享消费者”一词自动划出新领域。

如果最终只能证明固定Mixup提高若干数据集分数，环境实验有价值，但不足以支撑当前Harness方法论文。若能证明条件化研究经验在后续作业减少了错误实验、保持质量并降低总体费用，再通过相应消融定位数据特有机制，才有继续扩展论文的理由。

## 11. 与师兄讨论时最有价值的七个问题

1. 我们希望积累的是最佳程序、适用性经验，还是调查方法？当前每项究竟有什么证据？
2. 当前Source中哪条信息是A3在第一次公共反馈后仍无法轻易得到的？
3. 一条Specific命中后，具体改善哪个可执行决策？如果只让候选趋同，为什么值得付费？
4. 哪个条件由受控响应支持，哪个只是数据相似性的描述？
5. 固定Consumer和小菜单中，哪一个问题确实需要Agent组织证据，而不是简单搜索即可解决？
6. 新Skill在下一份训练材料上有没有重新解决任务，还是仅在当前作业选中了一个模型？
7. 如果固定Mixup已经捕获大部分收益，我们可否用可信成本节约证明价值？若也做不到，愿意在哪一个已定义机制上停止投入？

**本次交付是把项目的未知项收敛到可检验机制。** 不改主题、不预告正结果，也不再把“接线通过”当成“快要学会了”。Grok的完整H3是下一份应等待的实际证据；其后优先验证经验内容与决策的关系，再决定是否扩展课程。
