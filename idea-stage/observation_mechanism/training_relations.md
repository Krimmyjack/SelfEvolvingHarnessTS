# 从条件验收转向关系发现：训练侧探索（2026-09-08）

用户当前目标是发现能改进方案的联系：哪些数据状态、Consumer 特点、程序作用和结果相互关联。探索阶段不要求每一条联系先成为可靠的部署规则。一个关系能帮助决定观察哪里、优先试什么、比较哪两个步骤、在哪里多收一点反馈，就值得保留并继续研究。

本轮已经做了零新增拟合、零 LLM 的关系探索。脚本是 [explore_training_relations.py](explore_training_relations.py)，完整的 96 对描述性读数和 80 条序列摘要是 [training_relations.json](training_relations.json)。没有修改主线、已有报告或其他执行线文件。

## 本轮实际看了什么

- 数据与结果沿用 R4D-A/B 已曝光的 KDD development，Consumer 是 pooled Ridge 和 per-channel Ridge，Task 都是 Forecasting。
- 数值原始数据只解析索引 `[0, 900)`；每条历史训练样本仍为 192 步输入 + 48 步历史目标，10 个固定 anchor。这里的“历史目标”全部早于最早部署起点 1176，不是未到达的预测真值。
- 160 条序列用于描述训练条件；关联读数以 80 条被服务序列为单位，每条先平均其已有窗口结果，同时保留四个块内的相关和 support/delayed 分面相关。
- 12 个描述量 × 8 个结果量。结果量包括平均收益、处理效果的绝对幅度、W2 相比 MAD 的额外收益，以及两种 Consumer 的 Static 差值。没有按 AUC 门槛筛选“通过”。
- 描述量使用标准库计算；不是算子真实修改点的逐点复现。平均、趋势与极端程度经过历史输入窗口的稳健尺度标准化。
- 80 个 UID 与三格库对应；840 个配对实例。按窗口数加权复算的 pc Static 优势为 0.3754710446631155，与 R4D-B 的 0.375471045 一致。

## 值得继续追查的关系

下表的 rho 是 Spearman 描述性相关，不是准确率、效果提升或独立验证。

| 条件与结果 | 80 序列 rho | 四块内 rho | 能给方案什么启发 |
|---|---:|---|---|
| 历史训练输入中的极端值比例 ↔ pc 下 MAD 的平均完整管线收益 | +0.465 | +0.489 / +0.686 / +0.113 / +0.467 | 描述训练输入的异常程度，作为优先尝试 MAD 的线索。当前服务窗没有尖峰，并不排除历史训练数据值得处理。 |
| 历史训练目标段相对输入常态的极端值比例 ↔ pc 下 MAD 训练侧效应的绝对幅度 | +0.748 | +0.671 / +0.655 / +0.868 / +0.741 | 找到可能对训练准备敏感的对象；优先对比处理前后模型行为、保留弱处理对照。它提示影响幅度，不保证收益方向。 |
| 历史训练窗口内的水平漂移强度 ↔ pc Static 相对 pooled Static 的优势 | −0.415 | −0.588 / −0.510 / −0.662 / −0.641 | pc 并非在每种数据状态下都同样占优；Consumer 的训练来源、结构应与趋势状态共同进入解释。不能据此直接给 Runner 硬编码模型或程序选择。 |

第一条按 support/delayed 分开，rho 为 +0.382 / +0.237；第二条为 +0.734 / +0.721；第三条为 −0.509 / −0.231。这些差异说明平均关系和单个时间窗口决策并不相同。

定义：极端输入值比例是在每个历史训练窗口中，线性补缺后的输入点离输入中位数超过 3.5 倍稳健尺度的比例；目标段极端值比例用同一输入常态作参照；水平漂移是输入首尾各 48 点均值之差的绝对值除以稳健尺度。

第二条同类的描述量也有关联：历史季节预测误差与效应幅度 rho +0.751，输入尖峰比例与效应幅度 +0.724，目标段与输入水平偏移与效应幅度 +0.707。它们可能共同描述训练数据的不规则程度，不能算四条独立发现。

## 哪些猜想暂时没有得到同样清楚的联系

- 最初猜的“与 pooled 训练语料越不同，越需要独立模型”没有被简单距离量清楚支持：结构距离与 pc 优势 rho +0.018；周期相位形状距离 rho +0.282，但四块内是 +0.857 / +0.780 / +0.120 / −0.260。
- W2 相对 MAD 的程序偏好关系较弱：历史输入尖峰比例与 pc 的 W2 额外完整收益 rho +0.206。不能用对 MAD 有收益的联系，替代“能分辨两个程序谁更好”。
- 当前没有跨 Task 的新读数，不能把 Forecasting 里的这些关联直接迁到 AD/Classification。

## 如何把发现用于方法开发

这些联系先进入 Observation 与候选生成的探索，不直接变成自动执行资格。例如：

> 历史训练输入存在较多极端偏差；历史目标段的偏差也明显。先比较仅训练侧处理、训练与服务都处理，观察预测变化的幅度与方向。服务侧是否处理，另参考当前窗口的状态。

让 Agent 根据这个上下文决定优先检查和比较什么，保留已有反馈机制裁决执行。要试的是这些信息是否减少无效搜索、帮助提出更有区分度的候选，之后再检验后续部署收益。

关系发现还应保留两种无需“精确预测收益”的知识：

1. **步骤依赖**：既有实现中 MAD 自带缺失填补，其后再接只补缺失的周期填补会失去动作对象。这可帮助安排顺序、删除无效步骤。
2. **作用面区别**：R4D-A/B 都显示训练侧模型变化占主要效应；R4E 的尖峰线索描述的是服务窗口。两者应分别给出上下文与对照候选。

本轮是 96 对关系的开发数据探索，没有外部验证，也没有因果识别。窗口重复、尺度因素、训练数据来源和 Consumer 结构混合变化都可能参与解释；四个块不是四个独立数据来源。下一步可把其中最有机制理由的关系固定为少量观察与 probe 优先级，先看它是否改变 Agent 的搜索行为，而不是继续给每一个特征做二元判词。
