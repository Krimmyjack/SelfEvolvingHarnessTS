# Observation 条件化探索：当前可支持什么（2026-09-07）

本轮结论：自然数据上“部署可见条件 → 更有价值的准备决策 → LLM 实际利用 → 后续获益”仍未成立；但现有负结果也没有证明条件不可观测。已经能确认的缺口是：只用当前序列的原始形态解释整个训练与服务管线的效用，观察对象不完整。下一步值得检查程序实际作用的条件，而非直接放弃 Pattern 或改风险门。

本目录是独立分析交付。未改主线代码、协议、状态页、历史报告或 sol 补跑配置。新 Consumer fits=0、新 LLM 调用=0、新 Hash=0；没有解析 horizon 真值。读数与脚本分别为 [readout.json](readout.json) 和 [analyze.py](analyze.py)。

## 1. 先更新事实范围

以当前仓库为准，R4A 和 R4A-b 已经落盘，不能继续说“从未正面测过”。R4A 试了九个机制量和十二个现有数值量，主表判为 WEAK；其中 W3 与祖先完全同效，八个主格只有六个不同效果格。四个序列块并非四个数据来源，也不能把同一 uid 的重复窗口作为独立样本。

“过去全是通用全局特征”也不准确：`../CURRENT_STAGE.md:939` 的 W61 已明确测试局部片段、动作变形、cohort prevalence/alignment 和 Task/Consumer 条件，结果为负。其动作/任务与当前 KDD 路径不同；不应把所有负结果归到一个已识别的共同原因。

R4A 测量的是条件可识别性的一个有限版本。把可见模式交给 LLM，控制其他信息和预算，再测它是否产生更好的准备决策，仍缺少针对性证据。DEV 系列中已经能改 Workflow，早期只允许 Slow 输出 feature/direction 的限制也不能概括当前全部实验。

## 2. 本轮实际补算

输入是 `_scratch/m_r0k_prediction_store.json` 中已存在的三种不同程序，21 个课程位置、两面、每面每程序 420 行。原始数据仅用于这些已曝光 uid 的 pre-origin context；共 840 张 context 卡、80 个 uid，最大数值索引 3863，小于禁区 4056。没有使用 R4A 的未来 ORACLE 特征。

当前 WSL Python 没有 NumPy，已确认的 Windows project 环境因 WSL interop socket 错误无法启动。本轮没有安装依赖；用标准库按现有源码翻译必要的中位数、插值和动作命中公式。Hampel 阈值规则四折 Support 效用复算全部与原工件的六位小数一致。动作命中计数是源码公式级诊断，尚未声称与生产执行器逐位交叉验证；正式接入前应做该复核。

### 2.1 当前窗口没有被裁剪，依然会获益或受损

“无裁剪”相对于原始管线已经做的线性缺失填补而言。MAD 按生产公式先插值，再用 3.5×1.4826×MAD 裁剪。

| 面 | 无 MAD 裁剪实例/全部实例 | 无裁剪实例中获益 | 无裁剪实例中严重受损 | 全部严重受损实例 |
|---|---:|---:|---:|---:|
| Support | 236/420 | 160 | 16 | 28 |
| delayed | 269/420 | 177 | 24 | 31 |

delayed 面约 64.0% 实例没有改变当前服务窗口；约 77.4% 的严重受损实例出现在这一组。它们不是独立序列数量，不能据此计算跨域显著性。

实现解释很明确：`scoped_serving_evaluator.py` 的原始管线和准备管线分别训练模型。即使服务 context 没变，切换到在准备后训练语料上拟合的模型仍会改变预测。因此这些实例的效用不能用“裁掉了当前窗口中的重要尖峰”解释。

这不证明路由是全部伤害的主因，也不推翻 D1 在另一组实例上的 `ROUTING_HARM_NOT_DOMINANT`。它说明当前 R4A 的数据中，训练侧作用必须进入条件解释。无裁剪组也有大量受益者，所以“当前无尖峰就不使用准备管线”同样没有得到支持。

### 2.2 全局尖峰描述和实际算子命中不是同一个对象

按当前 Hampel 源码的两次滚动中值、局部 MAD 和零尺度守卫重算：840 个 context 中，Hampel 命中了 6466 次原始已观测点；其中 5985 次（92.6%）的点，在 R4A 使用的全窗口 robust-z 下小于 3。

这不是 6466 个独立物理点：context 有重叠。它也不证明这些命中有害。它证明仅用全窗口“有无 ≥3 尖峰”描述这个局部算子的实际修改位置，会遗漏大量行为。需要观察局部判据命中的点、连续程度、周期位置及其修改幅度。

### 2.3 缺失率没有表达周期填补的实际可用性

当前 W2 的参数是 period=24、cycles=3、min_donors=2。840 个 context 中共计 31805 次缺失点出现，其中只有 10044 次（31.6%）有至少两个原始已观测同相位历史供体；其余按当前代码回退线性插值。

这是机制统计，不是效用规律。它指出更贴近动作的候选观察量：有多少缺口真的能使用周期供体、供体之间是否一致、周期填补与线性填补实际相差多少。应分别测训练窗口和服务窗口。已有缺失率/最长缺口并未直接表达这些条件。

源码还有一个确定性的顺序关系：`outlier_mad` 自带 `interp_nan`，执行后缺失已经消失；后接只补缺失的 `period_median_complete` 会成为恒等步骤。缓存中 W3 与 MAD 的 42/42 条完全同效与这一机制一致。这个事实可帮助排除重复候选，但本身不证明新 Skill 的学习或效用增量。

### 2.4 Hampel 的正向线索需要用正确参照理解

本轮固定 R4A 已经报告的 `spike_peak_over_tail_sd >= 6`，没有扫阈值；按四块等权，重放结果如下：

| 面 | 规则相对 Hampel 全处理 | 规则相对 MAD 全处理参照 |
|---|---:|---:|
| Support | +0.081614 | −0.221642 |
| delayed | +0.034832 | −0.124572 |

Support 四折相对 Hampel 全处理都改善，但其中一折仍低于 raw。固定阈值 6 到 delayed 后，四折中有一折也低于 Hampel 全处理。R4A 在 delayed 上重新选择的最优阈值/特征，并不是这条固定规则的独立后续确认。

两种全处理程序参照都是影子读数；MAD 全处理不等于当时合法 incumbent，也不自动满足风险门。这里仅说明“能让较差程序少做一些”与“能选出更好的整体方案”是两种不同贡献。规则的数字四线检查为 Support 1/21、delayed 4/21，均不是生命周期晋升。

## 3. 现有结论中的三个推断需要收窄

### 低重测相关不排除可见的动态条件

R4A-b 测的是相隔 48 步之后，序列的收益排序是否保持，以及 uid/单元主效应能解释多少方差。它支持“记住某 UID 过去受益，不能可靠预测下一窗”。它不支持“可见 Pattern 不存在”或“所有 Scope 都不可能有效”。

反例：令部署时能观察的状态 X_t 为独立等概率 ±1，处理收益 g_t=X_t。相邻收益相关为 0，uid 主效应也为 0，但根据当前 X_t 选择是否处理可做到完美决策。稳定的条件关系可以作用在快速变化的状态上。

因此 ANOVA 剩余方差应称为“当前分解未解释的方差”，不能直接认定为不可约噪声。单一 cohort 均值作为序列级分类分数，也不是所有条件模型的上界。

### 三个未来摘要不是信息论上界

未来有无尖峰、缺失率和均值变化解释力弱，只排除这三个具体描述的强区分力。它们没有包含预测偏差与真实值的方向关系，更不是“已掌握全部未来信息”的 oracle。

同样，一组特征失败加上种植阳性对照成功，只说明这套仪器能恢复所种植的规则；不能证明自然数据中不存在其他可用条件。

### 逐窗效应变化不等于仪器出错或风险虚警

当前 Ridge 使用固定 alpha 的确定性线性求解。相同数据重复拟合主要检验数值复现；移动 origin 同时改变了数据与真值，不能把收益变化全部计作重复测量误差。用观测增益做置换，也不能自动识别“真正中性程序”的风险虚警率。

风险门衡量的是一次部署实际可能遭受的损害。要改成多窗口均值风险，必须先明确保护目标已经改变，不能仅因原门难通过而改。此次探索不建议据 R4A-b 直接修改主线风险协议。

## 4. 更值得验证的 Observation 设计

把条件前提拆成三项，各自验证：

1. **作用条件可识别**：这个程序在当前哪些位置、哪些作用面真正改变了数据？供体是否可用？后续步骤是否仍有动作？
2. **相对价值可识别**：这些作用条件加合法历史反馈，能否提高相对当前合法策略的效用/风险/成本决策？预测的是条件期望和决策价值，不要求猜中每个未来窗口的正负号。
3. **LLM 能利用**：相同模型、候选能力和反馈预算下，增加这些观察是否改变对照选择与 Workflow，并改善后续结果？

优先检验三个紧凑对象：

| 对象 | 给 Agent 的可核验信息 | 可改变的决策 | 当前地位 |
|---|---|---|---|
| 周期填补 | 原始同相位供体覆盖/一致性、相对线性填补的差异、训练与服务分别统计 | 是否值得试周期填补、步骤顺序 | 有明确机制与可计算性，效用预测待验证 |
| 局部异常处理 | 实际命中位置、局部与全局判据分歧、命中是否成段/重复于相位 | 是否减弱、删除或替换某一步 | 当前全局描述与实际动作不匹配，尚无稳定有益规则 |
| 训练与服务的共同作用 | 数据准备改变训练模型的预测响应、当前 context 的额外作用 | 优先检验哪条作用路径，是否保留程序 | 无服务裁剪仍产生大量效应，需做作用分解 |

第三项可以用两个已有模型作诊断性预测对照：raw 模型/raw context，program 模型/raw context，program 模型/program context；必要时补第四格。中间预测是作用分解，不是新部署模式。当前落盘库只有每序列损失，没有模型与逐步预测，不能凭它宣称此对照是零 fit。下一次已有两模型拟合的有界开发运行中可同时采集；若要追补旧实例，必须如实计费。D1 已测过简单预测分歧并未可靠分离，不能换名重复认领它。

## 5. 与补跑线衔接

现有 sol 补跑保持原样，当前目录只产出分析材料。下一包可以把“更新规则比较”的输入先固定为一个机制明确的 Observation 版本，而不是继续扩大所有特征：

- 在新的 development 训练 cohort 上固定一种候选观察定义；候选与特征定义不能根据该 cohort 的结果再挑。
- 同时保留固定程序、现有特征和合法目标反馈基线。比较修订增量/选择效用与预算，不把 AUC≥0.70 当所有方法必需的通用门槛。
- 确认可用后，做同一 LLM 的输入消融：现有观察 vs 加入实际作用观察；目标反馈和模型相同，读候选/对照是否改变、后续增量是否形成。
- 历史跨域材料先由 Slow 形成审计后的 Skill，再给新 Target 的 Fast；不把原始跨域胜负 Episode 直接塞回 Fast。
- 若这种具体观察仍无增量，关闭该观察假设并报告证据不足/无效，不外推成自然 Pattern 不存在。

可支持的最终表述是：**当前还没有找到可直接交付的自然数据效用规则，但已经找到了观察对象与执行机制不匹配的具体证据；应先验证面向实际动作的条件信息是否改善决策，再扩大 Skill 修订。**
